# PRD: 음성 인식 엔진 (한·영 혼용 STT)

## 달성 가치
- **V2**: 한·영 혼용 음성 인식 정확도 (전 진입점 공통)
- **V7**: 시스템 전역 글쓰기 보조 (키보드 확장 전용 인식기 한정)

## 개요

본 앱의 모든 음성 입력에서 사용하는 STT(Speech-to-Text) 엔진. 한·영 혼용 발화에서 정확도가 가장 높은 모델을 채택하는 것이 핵심 요건이다.

진입점은 두 그룹으로 나뉜다:
- **메인 앱 진입점** (AI 채팅 음성 모드, 숏컷 음성 모드, 임시 공간 직접 음성 입력 등): 동일한 엔진 인스턴스를 공유한다.
- **키보드 확장 전용 진입점** (`prd-keyboard-extension.md` AC5): iOS App Extension의 격리 특성상 메인 앱 프로세스와 메모리·런타임을 공유할 수 없으므로 별도 인스턴스(또는 별도 인식기)로 동작한다. 단, 동일한 추상화 인터페이스와 모델 선정 기준을 따라 정확도와 동작이 일관되도록 한다.

## Acceptance Criteria

### AC1: 한·영 혼용 정확도 최우선 모델 채택
- **설명**: 모델 선정 시 한국어 단일·영어 단일 정확도가 아니라 **한·영 혼용** 발화 정확도를 최우선 기준으로 삼는다. 후보 모델들을 한·영 혼용 데이터셋으로 평가한 결과를 근거로 채택한다.
- **달성 가치**: V2
- **검증 방법**: 모델 선정 평가 보고서 존재 + 한·영 혼용 정확도 수치 명시.

### AC2: 메인 앱 진입점 무관 동일 엔진
- **설명**: 채팅 탭, 숏컷 음성 모드, 임시 공간 직접 음성 입력 등 **메인 앱 프로세스 안의** 모든 진입점은 동일한 STT 엔진 인스턴스를 사용한다. 동일 발화는 동일 결과를 낸다. 키보드 확장은 본 AC의 범위 밖이며 AC6에서 별도로 다룬다.
- **달성 가치**: V2
- **검증 방법**: 동일 음성 파일을 메인 앱의 세 진입점에서 입력 → 결과 일치 여부 확인.

### AC3: 외래어·고유명사·기술 용어 대응
- **설명**: 사용자가 자주 사용하는 외래어·고유명사·기술 용어는 사용자별 단어장 또는 모델 자체의 강건성으로 대응한다.
- **달성 가치**: V2
- **검증 방법**: 사용자 정의 어휘 샘플로 인식률 측정.

### AC4: 모델 교체 가능 구조
- **설명**: STT 엔진은 추상화된 인터페이스 뒤에 있어, 더 정확한 모델이 등장하면 코드 변경을 최소화하며 교체 가능하다. 메인 앱과 키보드 확장 두 인스턴스가 같은 추상화를 공유하므로, 모델 교체 시 양쪽이 동일한 변경 절차를 거친다.
- **달성 가치**: V2
- **검증 방법**: 인터페이스 설계 검토 + 대체 구현체 모킹으로 교체 가능성 확인. 메인 앱·키보드 확장 양쪽에서 교체 동작 확인.

### AC5: 응답 지연 허용 한계
- **설명**: 정확도가 최우선이지만, 응답 지연이 사용자가 즉시 캡처라고 느끼지 못할 수준(예: 종료 후 결과 노출까지 3초 이상)으로 떨어지지 않는다. 절충 기준은 실제 사용 시나리오에서 결정한다.
- **달성 가치**: V2 (V1과의 절충)
- **검증 방법**: 평균 발화 길이 기준 종료~결과 표시 지연 측정.

### AC6: 키보드 확장 전용 인식기
- **설명**: 키보드 확장(`prd-keyboard-extension.md` AC5)은 iOS App Extension 격리 특성상 메인 앱 엔진 인스턴스를 공유할 수 없으므로 **확장 내부에 자체 인식기**를 둔다. 단, 다음 조건을 만족한다:
  - AC1과 동일한 한·영 혼용 정확도 기준을 통과한 모델만 채택한다.
  - AC4의 추상화 인터페이스를 그대로 따른다 (모델 교체 가능 구조).
  - AC3의 사용자 단어장이 키보드 확장에서도 동일하게 활용된다 (App Group 공유).
  - 인식 결과는 호스트 입력창에 즉시 반영하지 않고 키보드 확장의 미리보기 흐름(`prd-keyboard-extension.md` AC9)에 전달한다.
- **달성 가치**: V2 (정확도 일관성), V7 (시스템 전역 글쓰기 보조의 음성 입력 부분)
- **검증 방법**: 키보드 확장 단독 환경에서 AC1·AC3·AC4의 조건이 모두 통과하는지 확인. 동일 음성 파일을 메인 앱과 키보드 확장에서 입력했을 때 결과 차이가 허용 범위 안인지 비교.

## 비고

- **모델 후보 예시(참고용, 실제 채택은 평가 후 결정)**:
  - OpenAI Whisper / Whisper-large-v3
  - Apple Speech Framework (on-device, iOS 기본)
  - Google Cloud Speech-to-Text
  - 기타 한국어 특화 + 코드스위칭 강건 모델
- 채택 시 비용·프라이버시(온디바이스 vs 클라우드)·지연·정확도를 종합 평가한다.

## 열린 질문

- **키보드 확장 인식기 구현 형태**: AC6의 키보드 전용 인식기를 on-device 모델로 둘지, 네트워크 STT를 부를지, 하이브리드로 갈지. App Extension의 메모리·번들 사이즈 제약과 Full Access 권한·네트워크 정책을 함께 고려해 결정 필요.
- **메인 엔진과의 코드 공유 범위**: 추상화 인터페이스만 공유할지, 모델 가중치까지 App Group으로 공유할지. iOS의 App Extension 메모리 한계(약 50~120 MB)를 고려하면 메인 앱과 동일한 큰 모델은 못 쓸 수 있다.
- **사용자 단어장 동기화**: AC3·AC6의 사용자 정의 어휘를 App Group에 두고 양쪽이 읽도록 할지, 키보드 확장이 별도 사본을 가질지.
