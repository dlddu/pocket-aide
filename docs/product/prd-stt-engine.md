# PRD: 음성 인식 엔진 (한·영 혼용 STT)

## 달성 가치
- **V2**: 한·영 혼용 음성 인식 정확도 (전 진입점 공통)
- **V7**: 시스템 전역 글쓰기 보조 (키보드 확장의 음성 입력 — 본 앱 엔진 경유)

## 개요

본 앱의 모든 음성 입력에서 사용하는 STT(Speech-to-Text) 엔진. 한·영 혼용 발화에서 정확도가 가장 높은 모델을 채택하는 것이 핵심 요건이다.

엔진은 메인 앱 프로세스 안에 **하나**만 둔다. 모든 진입점이 이 엔진을 쓴다:
- **메인 앱 진입점** (AI 채팅 음성 모드, 숏컷 음성 모드, 임시 공간 직접 음성 입력 등)
- **키보드 확장의 음성 입력** (`prd-keyboard-extension.md` AC5): 키보드 확장은 기기 마이크에 접근할 수 없으므로 본 앱이 녹음·인식하고 결과를 키보드에 넘긴다(AC6). 키보드 확장 안에는 인식기를 두지 않는다. 구현 구조는 엔지니어링 문서 `../engineering/keyboard-voice-input.md`.

## Acceptance Criteria

### AC1: 한·영 혼용 정확도 최우선 모델 채택
- **설명**: 모델 선정 시 한국어 단일·영어 단일 정확도가 아니라 **한·영 혼용** 발화 정확도를 최우선 기준으로 삼는다. 후보 모델들을 한·영 혼용 데이터셋으로 평가한 결과를 근거로 채택한다.
- **달성 가치**: V2
- **검증 방법**: 모델 선정 평가 보고서 존재 + 한·영 혼용 정확도 수치 명시.

### AC2: 진입점 무관 동일 엔진
- **설명**: 채팅 탭, 숏컷 음성 모드, 임시 공간 직접 음성 입력, 키보드 확장의 음성 입력(AC6) 등 모든 진입점은 메인 앱 프로세스 안의 동일한 STT 엔진 인스턴스를 사용한다. 동일 발화는 동일 결과를 낸다.
- **달성 가치**: V2
- **검증 방법**: 동일 음성 파일을 메인 앱의 세 진입점과 키보드 확장에서 입력 → 결과 일치 여부 확인.

### AC3: 외래어·고유명사·기술 용어 대응
- **설명**: 사용자가 자주 사용하는 외래어·고유명사·기술 용어는 사용자별 단어장 또는 모델 자체의 강건성으로 대응한다.
- **달성 가치**: V2
- **검증 방법**: 사용자 정의 어휘 샘플로 인식률 측정.

### AC4: 모델 교체 가능 구조
- **설명**: STT 엔진은 추상화된 인터페이스 뒤에 있어, 더 정확한 모델이 등장하면 코드 변경을 최소화하며 교체 가능하다. 엔진 인스턴스는 메인 앱에 하나뿐이라 모델 교체는 한 곳에서 일어나고, 키보드 확장의 음성 입력에도 그대로 적용된다.
- **달성 가치**: V2
- **검증 방법**: 인터페이스 설계 검토 + 대체 구현체 모킹으로 교체 가능성 확인. 교체 후 메인 앱 진입점과 키보드 확장의 음성 입력 모두 새 구현으로 동작하는지 확인.

### AC5: 응답 지연 허용 한계
- **설명**: 정확도가 최우선이지만, 응답 지연이 사용자가 즉시 캡처라고 느끼지 못할 수준(예: 종료 후 결과 노출까지 3초 이상)으로 떨어지지 않는다. 절충 기준은 실제 사용 시나리오에서 결정한다.
- **달성 가치**: V2 (V1과의 절충)
- **검증 방법**: 평균 발화 길이 기준 종료~결과 표시 지연 측정.

### AC6: 키보드 확장 음성 입력의 본 앱 경유 처리
- **설명**: 키보드 확장(`prd-keyboard-extension.md` AC5)은 기기 마이크에 접근할 수 없으므로 확장 안에 인식기를 두지 않는다. 키보드의 음성 입력은 **본 앱이 녹음하고 AC2의 엔진으로 인식**한 뒤 결과를 키보드에 넘긴다. 다음 조건을 만족한다:
  - 인식은 메인 앱 진입점과 같은 엔진·같은 모델로 한다(AC1·AC2). AC3의 사용자 단어장도 본 앱 한 곳의 것을 그대로 쓴다.
  - 본 앱에서 인식 결과에 후처리(예: LLM 교정)를 더할 수 있다. 후처리를 더해도 결과는 AC5의 지연 한계 안에 키보드에 도착해야 한다.
  - 인식 결과는 호스트 입력창에 즉시 반영하지 않고 키보드 확장의 미리보기 흐름(`prd-keyboard-extension.md` AC9)에 전달한다.
- **달성 가치**: V2 (정확도 일관성), V7 (시스템 전역 글쓰기 보조의 음성 입력 부분)
- **검증 방법**: 키보드 확장에서 음성 입력 → 본 앱이 녹음·인식하고 결과가 키보드 미리보기 흐름에 도착하는지 확인. 동일 음성 파일을 메인 앱 진입점과 키보드 확장에서 입력했을 때 결과가 같은지(AC2) 확인. 사용자 단어장 항목이 키보드 경유 인식에도 반영되는지 확인.

## 비고

- **모델 후보 예시(참고용, 실제 채택은 평가 후 결정)**:
  - OpenAI Whisper / Whisper-large-v3
  - Apple Speech Framework (on-device, iOS 기본)
  - Google Cloud Speech-to-Text

## 결정 사항

- **엔진 인스턴스 하나 (AC2·AC4·AC6)**: 키보드 확장은 기기 마이크에 접근할 수 없으므로, 확장 내부 인식기(이전 AC6) 대신 본 앱이 키보드의 음성 입력을 녹음·인식하고 결과를 넘긴다. 그래서 엔진은 메인 앱 프로세스 안에 하나이고 모든 진입점이 공유한다. 키보드 쪽 동작은 `prd-keyboard-extension.md` AC5·결정 사항 「음성 입력 경로」, 구현 구조는 `../engineering/keyboard-voice-input.md`. (2026-10-09 결정)
