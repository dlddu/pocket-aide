# PRD: 통합 위젯 (1개)

## 달성 가치
- **V6**: 일상 정보 통합 시야 — 일정·메일·날씨·자주 읽는 문장·아이폰 알림을 하나의 위젯에서 노출
- **V4**: 의도된 반복 노출 — 자주 읽어줘야 하는 문장을 위젯을 통해 외부에서도 노출
- **V3**: 영역 분리된 작업 관리 — 임시 공간에 쌓인 미분류 항목 수를 위젯에서 보여 정리 필요를 알린다

## 개요

홈 화면에 배치되는 위젯 1개. 사용자의 일상 정보를 한 화면에 통합 노출하는 것이 목적이다. 위젯 1개로 여섯 가지 정보 영역을 표시한다:

1. **캘린더** — 다가오는 일정
2. **메일** — 최근/미확인 메일 요약
3. **날씨** — 현재/오늘 날씨
4. **자주 읽어줘야 하는 문장** — 회전 노출
5. **아이폰 알림 모음** — 시스템 알림 요약
6. **임시 공간 미분류 수** — 정리가 필요한 항목 개수

## Acceptance Criteria

### AC1: 단일 위젯에 여섯 영역 표시
- **설명**: 위젯 1개 내에 여섯 정보 영역이 모두 표시된다. 위젯 크기에 따라 영역의 표현 방식(축약/확장)이 달라질 수 있다.
- **달성 가치**: V6
- **검증 방법**: 위젯 추가 후 여섯 영역 모두 가시 확인.

### AC2: 캘린더 연동
- **설명**: iOS 시스템 캘린더를 읽어 다가오는 일정 1~3개를 노출한다.
- **달성 가치**: V6
- **검증 방법**: 시스템 캘린더에 일정 추가 → 위젯 갱신 → 표시 확인.

### AC3: 메일 연동
- **설명**: 사용자가 앱에 연결한 메일 계정들(계정별 IMAP, 앱 비밀번호 인증 — 백엔드가 접속)의 받은편지함에서 미확인 메일을 합쳐 요약 노출한다. 표시 형태(개수, 최신 발신자/제목 등)는 디자인에서 결정.
- **달성 가치**: V6
- **검증 방법**: 메일 도착 → 위젯에 반영 확인.
- **비고**: iOS는 기본 메일 앱의 계정·받은편지함을 다른 앱에 열어주지 않으므로(메일 확장 MailKit은 macOS 전용), 메일 앱에 연결된 계정을 그대로 읽지 않고 앱에서 계정을 따로 연결한다(2026-10-05 결정).

### AC4: 날씨 연동
- **설명**: 사용자의 현재 위치 또는 설정된 위치의 현재 기온, 날씨 상태, 강수 가능성 등을 노출한다.
- **달성 가치**: V6
- **검증 방법**: 위치 권한 부여 → 날씨 정보 정확성 확인.

### AC5: 자주 읽어줘야 하는 문장 회전 노출
- **설명**: 자주 읽어줘야 하는 문장 탭에 등록된 문장 중 하나가 위젯에 노출된다. 위젯 갱신 주기마다 회전된다. 노출 우선순위는 해당 탭의 우선순위 설정을 따른다.
- **달성 가치**: V4
- **검증 방법**: 갱신 주기 동안 다른 문장이 노출되는지, 우선순위에 따른 빈도 차이 확인.

### AC6: 아이폰 알림 모음
- **설명**: 시스템 알림 중 표시 가능한 항목(권한 범위 내)을 모아 요약 노출한다.
- **달성 가치**: V6
- **검증 방법**: 시스템 알림 발생 → 위젯에 반영되는지 확인.
- **비고**: iOS는 다른 앱의 알림에 대한 직접 접근을 제한한다. 본 앱이 직접 발행한 알림(루틴, 투두 마감 등)을 모아 표시하는 형태가 현실적 구현이다. 시스템 알림 직접 접근이 불가하다면 이 점을 사용자에게 명시한다.

### AC7: 갱신 주기
- **설명**: 위젯은 각 영역의 데이터를 **30분마다** 출처에서 다시 가져온다(표시만 회전하는 것이 아니라 데이터 자체의 신선도 기준). 앱에서 위젯에 보이는 데이터가 바뀌면(다짐 편집, 알림 확인, 로그인·로그아웃, 위치 갱신 등) 위젯 타임라인을 즉시 다시 요청한다. 실제 반영 시점은 iOS 위젯 갱신 예산 안에서 시스템이 정한다.
- **달성 가치**: V6
- **검증 방법**: 출처 데이터를 바꾼 뒤 30분(갱신 주기 한 번) 안에 위젯에 반영되는지 확인.

### AC8: 위젯 영역 탭 시 앱 진입
- **설명**: 위젯 내 각 정보 영역을 탭하면 그 정보에 대응하는 화면으로 진입한다. 영역별 대상:
  - 다음 일정 → iOS 캘린더 앱 (위젯 링크는 이 앱만 열 수 있으므로 앱이 링크를 받아 캘린더 앱으로 넘긴다)
  - 날씨 → 앱 내 날씨 화면 (AC10)
  - 메일 → 앱 내 메일 화면 (AC11)
  - 자주 읽어줘야 하는 문장 → 자주 읽는 문장 탭
  - 알림 → PR 모니터 탭
  - 임시 공간 미분류 수 → 임시 공간 탭 (AC9)
- **달성 가치**: V6
- **검증 방법**: 각 영역 탭 → 위 대상 화면 진입 확인. 마지막으로 연 탭에 그대로 머물지 않는다.

### AC9: 임시 공간 미분류 수 표시
- **설명**: 위젯은 임시 공간(PRD-4)의 미분류 항목 개수를 표시한다. 개수는 앱의 임시 공간 배지(PRD-4 AC5)와 같은 값이다. 0개이면 "정리할 항목 없음"처럼 비어 있음을 명시한다. 이 영역을 탭하면 임시 공간 탭으로 진입한다(AC8). 임시 공간 탭이 "더 보기"에 있어 하단 탭 바의 배지로는 보이지 않으므로(PRD-12 결정 사항), 앱을 열지 않고 정리 필요를 알아차리는 주 경로다.
- **달성 가치**: V3, V6
- **검증 방법**: 임시 공간에 항목 3개 추가 → 위젯 갱신 후 3 표시, 앱의 임시 공간 배지와 일치. 하나를 분류 → 2로 감소. 모두 분류 → 비어 있음 표시. 영역 탭 → 임시 공간 탭 진입.

### AC10: 앱 내 날씨 화면
- **설명**: 위젯 날씨 영역을 탭하면(AC8) 앱 안의 날씨 화면이 열린다. 위젯과 같은 위치·같은 제공자의 값을 보여 위젯 수치와 어긋나지 않는다. 화면은 위에서부터 다음을 보인다:
  - **현재**: 동네 이름, 현재 기온, 날씨 상태, 체감 기온, 오늘 최고·최저 기온, 오늘 최대 강수 확률
  - **시간별 예보**: 지금부터 24시간, 1시간 간격의 기온·날씨 상태·강수 확률 (가로 스크롤)
  - **주간 예보**: 오늘 포함 7일, 일자별 최고·최저 기온·날씨 상태·강수 확률
  - **갱신 시각**: 마지막으로 가져온 시각. 당겨서 새로고침으로 다시 가져온다.
  
  위치 권한이 없으면 위젯과 같은 안내(「앱에서 위치 접근을 허용해 주세요.」)와 설정으로 가는 버튼을, 조회 오류에는 「잠시 후 다시 시도할게요.」와 다시 시도 버튼을 보인다.
- **달성 가치**: V6
- **검증 방법**: 위치 허용 상태에서 위젯 날씨 영역 탭 → 날씨 화면의 현재 기온·상태가 위젯과 일치, 시간별 24개·주간 7일 표시 확인. 당겨서 새로고침 후 갱신 시각이 바뀌는지, 위치 거부·네트워크 차단 시 안내·다시 시도가 보이는지 확인.

### AC11: 앱 내 메일 화면
- **설명**: 위젯 메일 영역을 탭하면(AC8) 앱 안의 메일 화면이 열린다. 연결한 IMAP 계정(AC3)의 미확인 메일을 보고, 계정을 연결·해제하는 곳이다.
  - **목록**: 연결한 계정들의 받은편지함 미확인 메일을 합쳐 최신순으로 최근 50통까지 보인다. 각 줄은 발신자·제목·받은 시각·계정 라벨과 본문 앞부분 미리보기 한 줄. 줄을 눌러도 본문 화면은 열리지 않는다.
  - **계정 필터**: 목록 위에 「전체」와 연결한 계정별 알약을 두어 걸러 본다. 고른 필터는 기기에 저장되어 다시 들어와도 유지된다.
  - **읽기 전용**: 앱은 메일 상태(읽음 등)를 바꾸지 않는다. 메일이 목록에서 빠지는 것은 다른 곳(메일 앱 등)에서 읽었을 때뿐이다.
  - **계정 관리**: 화면 안에서 계정을 연결(이메일 주소·앱 비밀번호·IMAP 서버 — 주요 서비스는 서버 자동 채움, 저장 시 백엔드가 접속을 시험)하고 해제한다. IMAP 인증에 실패한 계정은 「재연결 필요」로 표시되고 앱 비밀번호를 다시 넣어 복구한다.
  - **상태**: 연결한 계정이 없으면 연결 안내, 미확인 메일이 없으면 빈 상태 문구, 조회 오류에는 다시 시도. 당겨서 새로고침으로 다시 가져온다.
- **달성 가치**: V6
- **검증 방법**: 계정 두 개 연결 → 위젯 메일 영역 탭 → 두 계정의 미확인 메일이 합쳐 최신순으로 보이고 필터로 한 계정만 걸러지는지, 메일 앱에서 한 통 읽은 뒤 새로고침하면 목록에서 빠지는지, 앱 사용 후에도 메일 앱의 미확인 상태가 그대로인지, 계정 해제 후 그 계정 메일이 사라지는지 확인.

## 결정 사항

AC2 구현(위젯 다음 일정 영역) 중 확정된 사항. (2026-10-04 결정)

- **캘린더 권한 요청 시점 (AC2)**: 로그인된 상태로 앱이 시작되거나 로그인을 마친 직후, 알림 권한 요청 다음에 iOS 캘린더 전체 접근을 한 번 요청한다. 위젯은 권한을 요청할 수 없으므로, 권한이 없거나 거부된 상태에서는 다음 일정 영역에 「앱에서 캘린더 접근을 허용해 주세요.」를 보인다. 허용하면 위젯 타임라인을 즉시 다시 요청한다.
- **다가오는 일정의 범위 (AC2)**: 기기의 모든 캘린더에서 지금부터 7일 안에 시작하는 일정과 지금 진행 중인 일정을 시작 시각이 가까운 순서로 최대 3개 보인다. 첫 일정은 제목과 시각 범위(예: 「14:00 — 15:30」), 나머지는 시작 시각과 제목 한 줄이다. 오늘이 아닌 일정은 「내일」 또는 「월/일」을 시각 앞에 붙이고, 종일 일정은 시각 대신 「종일」로 적는다. 3개를 넘는 일정은 「+ N 더」로 개수만 보이고, 일정이 없으면 「다가오는 일정이 없어요.」를 보인다.
- **캘린더 갱신 (AC2·AC7)**: 캘린더 권한이 있으면 위젯이 30분마다 캘린더를 다시 읽는다(일정 추가·삭제가 갱신 주기 한 번 안에 반영된다). 타임라인의 엔트리마다 그 시각 기준으로 끝난 일정을 뺀다.
- **진입 대상 (AC8)**: 다음 일정 영역의 탭 대상은 이번 결정에 포함하지 않는다 — 위젯 기본 링크를 따른다(PRD 공백 「PRD-8.AC8 네 영역의 진입 대상」 그대로). → 2026-10-05 결정 「진입 대상 — 다음 일정」으로 대체.

AC6 구현(위젯 알림 영역) 중 확정된 사항. (2026-10-04 결정)

- **알림 모음의 대상 (AC6)**: iOS는 다른 앱의 알림을 읽을 수단을 주지 않으므로, AC6 비고대로 이 앱이 보낸 푸시 알림만 모은다. 지금 이 앱이 보내는 알림은 PR 모니터의 CI 완료 푸시(PRD-10)뿐이라, 알림 이력 중 실제로 푸시되는 항목 — CI 시작 이벤트를 뺀 완료 이벤트 가운데 현재 알림 설정(PRD-10 AC8: 끄기·성공만·실패만)이 허용하는 것 — 을 대상으로 한다. 앱에서 「확인」한 알림은 빠진다. 루틴·투두 마감 같은 다른 알림이 생기면 그 알림도 이 영역에 더한다.
- **표시 형태 (AC6)**: 가장 최근 알림 하나를 푸시 배너와 같은 제목(예: 「CI 통과 — dlddu/pocket-aide #7」)과 본문(PR 제목, 없으면 「<워크플로> on <브랜치>」) 두 줄로 보이고, 나머지는 「+ N 더」로 개수만 보인다. 확인할 알림이 없으면 「확인할 알림이 없어요.」, 로그아웃 상태·조회 오류에는 다짐 영역과 같은 문구를 보인다.
- **다른 앱 알림을 모으지 않는다는 명시 (AC6)**: 영역 라벨을 「PocketAide 알림」으로 적어 이 앱이 보낸 알림만 모은다는 것을 위젯에서 바로 드러낸다.
- **알림 갱신 (AC6·AC7)**: 위젯은 30분마다 알림 이력을 다시 가져온다. 앱에서 알림을 확인하면 위젯 타임라인을 즉시 다시 요청한다.
- **진입 대상 (AC8)**: 알림 영역을 누르면 PR 모니터 탭으로 들어간다 — 같은 알림의 푸시를 눌렀을 때(PRD-10 AC7)와 같은 화면이다. 날씨·다음 일정·메일 영역의 진입 대상은 정하지 않는다(PRD 공백 그대로). → 2026-10-05 결정으로 다음 일정·날씨 확정, 메일은 열린 질문.

AC4 구현(위젯 날씨 영역) 중 확정된 사항. (2026-10-04 결정)

- **날씨 제공자 (AC4)**: 키·계정이 필요 없는 공개 예보 API Open-Meteo(`api.open-meteo.com/v1/forecast`)를 위젯이 직접 부른다. Apple WeatherKit은 앱 ID에 별도 기능 등록이 필요해 고르지 않았다. 바꿀 때는 위젯의 조회 한 곳만 바뀐다.
- **위치 (AC4)**: 「현재 위치」는 앱이 마지막으로 받은 위치다. 로그인된 상태로 앱이 시작되거나 로그인을 마친 직후(캘린더 권한 요청 다음), 그리고 앱이 앞으로 나올 때마다 「앱을 사용하는 동안」 위치 권한으로 위치를 한 번 받아, 소수 둘째 자리(약 1km)로 반올림한 좌표와 동네 이름을 위젯과 공유한다. 위젯은 위치를 직접 읽지 않으며, Open-Meteo에 보내는 것은 반올림한 좌표뿐이다(동네 이름은 iOS 역지오코딩으로 얻는다). 권한이 없거나 거부된 상태(거부는 다음에 앱을 열 때 반영)에서는 날씨 영역에 「앱에서 위치 접근을 허용해 주세요.」를 보인다. 「설정된 위치」 입력은 두지 않는다.
- **표시 형태 (AC4)**: 라벨은 동네 이름(알 수 없으면 「날씨」), 그 아래 현재 기온(정수 °)과 날씨 상태(WMO 코드를 「맑음」·「구름 조금」·「흐림」·「비」·「눈」 등으로), 마지막 줄에 「최고 N · 최저 N · 강수 N%」(오늘 최고·최저 기온과 오늘 최대 강수 확률)를 보인다. 조회 오류에는 다른 영역과 같은 「잠시 후 다시 시도할게요.」를 보인다.
- **날씨 갱신 (AC4·AC7)**: 위젯이 30분마다 다시 가져온다. 앱이 새 위치를 저장하면 위젯 타임라인을 즉시 다시 요청한다.
- **진입 대상 (AC8)**: 날씨 영역의 탭 대상은 이번 결정에 포함하지 않는다 — 위젯 기본 링크를 따른다(PRD 공백 그대로). → 2026-10-05 결정 「진입 대상 — 날씨」로 대체.

PRD 공백 정리로 확정한 사항. (2026-10-05 결정)

- **메일 연결 방식 (AC3)**: 앱에서 메일 계정을 계정별 IMAP으로 연결하고, 인증은 각 메일 서비스의 앱 비밀번호로 한다. 기본 메일 앱에 연결된 계정을 그대로 쓰는 방식은 iOS가 그 계정·받은편지함을 다른 앱에 열어주지 않아 택할 수 없다. 여러 계정을 연결하면 받은편지함의 미확인 메일을 합쳐 한 영역에 보인다. **IMAP 접속은 백엔드가 한다** — 기기(앱·위젯)는 IMAP에 직접 접속하지 않고, 앱은 계정 연결 정보를 백엔드에 등록하며 위젯은 다짐·알림 영역처럼 백엔드 API에서 메일 요약을 받는다. 따라서 앱 비밀번호는 서버에 보관된다. Gmail OAuth(Gmail 한정)·요약 없는 메일 앱 바로가기·영역 제외를 검토했으나 계정 범위를 넓게 덮는 IMAP을 골랐다.
- **갱신 간격 (AC7)**: 30분. 구현의 갱신 주기(다짐·알림·다음 일정·날씨 모두 30분)를 요구로 확정한다. 기준은 표시 회전이 아니라 데이터 재조회다. 메일 영역도 같은 간격을 따른다.
- **진입 대상 — 다음 일정 (AC8)**: iOS 캘린더 앱. 위젯 링크는 이 앱만 열 수 있으므로 앱이 전용 링크를 받아 캘린더 앱으로 넘긴다. 캘린더 앱을 여는 공식 URL이 없어 널리 쓰이는 비공식 `calshow:` URL에 기댄다 — iOS 업데이트로 막히면 앱 첫 화면에 머무는 것으로 물러선다. 넘기는 동안 앱이 잠깐 보일 수 있다.
- **진입 대상 — 날씨 (AC8)**: 앱 안에 날씨 전용 화면을 신설한다(AC10). 날씨 앱은 여는 공식 URL이 없고, 위젯 날씨는 Open-Meteo 값이라 날씨 앱 수치와 다를 수 있어 넘기지 않는다.
- **날씨 화면 (AC10)**: 별도 PRD가 아니라 PRD-8의 AC로 둔다 — 위젯 날씨 영역의 연장이라 같은 제공자(Open-Meteo)·같은 공유 위치를 쓴다. 진입 경로는 위젯 날씨 영역뿐이고 하단 탭 바·「더 보기」에는 두지 않는다. 화면이 열릴 때 위젯과 같은 30분 캐시가 있으면 그 값을 먼저 보이고 새로 가져온다.
- **앱 비밀번호 보관 (AC3)**: 백엔드는 IMAP 앱 비밀번호를 앱 레벨에서 AES-256-GCM으로 암호화해 DB에 저장한다(암호문에 키 버전을 붙여 나중에 키 교체·외부 KMS 전환이 가능하게 한다). 키는 다른 백엔드 비밀값과 같은 경로로 주입한다 — AWS SSM Parameter Store → ExternalSecret(`dlddu/flux-cd-apps` `apps/pocket-aide/external-secret.yaml`) → k8s Secret `pocket-aide-secrets` → 환경 변수. 키가 없으면 메일 기능만 꺼지고 서버는 뜬다. 키를 잃으면 저장된 비밀번호를 복호화할 수 없으므로 계정을 다시 연결하는 것이 복구 방법이다. 외부 KMS 봉투 암호화는 개인용 홈랩 서버에 비해 설정 부담이 커 고르지 않았다.
- **앱 비밀번호 삭제 시점 (AC3)**: 계정 연결 해제 시 즉시 삭제한다. 앱 로그아웃으로는 삭제하지 않는다(비밀번호는 기기가 아니라 서버 계정에 묶여 있어, 다시 로그인하면 그대로 쓴다). IMAP 인증 실패(비밀번호 폐기 등)에는 삭제하지 않고 그 계정을 「재연결 필요」로 표시한다.
- **진입 대상 — 메일 (AC8)**: 앱 안에 메일 화면을 신설한다(AC11, iOS 메일 앱으로 넘기지 않는다).
- **메일 화면 (AC11)**: PRD-8의 AC로 둔다. 목록은 계정 합산 + 계정 필터(「열린 PR」 필터와 같은 패턴), 미확인만·최신순·최근 50통. 본문은 열지 않고 미리보기 한 줄만 보인다 — 메일 화면의 목적은 「무엇이 와 있는지 파악」이고, 본문 표시(HTML·원격 이미지·첨부)의 부담을 피한다. 앱은 메일 상태를 바꾸지 않는 읽기 전용이다(백엔드는 IMAP을 읽기 전용으로 연다) — 본문을 보이지 않는 화면에서 읽음 처리를 하면 읽지 않은 메일을 읽은 것처럼 만들기 쉽고, 상태는 메일을 실제로 읽는 곳에서 바뀌는 것이 일관된다. IMAP 계정의 연결·해제·재연결은 이 화면 안에서 한다. 진입 경로는 날씨 화면과 같이 위젯 메일 영역뿐이다.
