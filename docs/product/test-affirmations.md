# 테스트 문서: 자주 읽어줘야 하는 문장 모음 탭

## 검증 대상 AC
- AC1: 문장 추가/편집/삭제 (PRD-5: `prd-affirmations.md`)
- AC2: 노출 빈도 설정 (PRD-5)
- AC3: 앱 내 자동 회전 노출 (PRD-5)
- AC4: 위젯 연계 (PRD-5)

## 달성 가치
- V4: 의도된 반복 노출 — 검증 대상 AC 모두 V4를 달성한다.

## 작성 기준
- 시나리오는 **사용자가 관찰할 수 있는 결과** 단위로 쓴다. 코드 레벨 테스트는 각 시나리오의
  「관련 코드 테스트」에 참고로만 적으며, 시나리오의 검증을 대신하지 않는다.
- 「구현 상태」는 작성 시점(2026-09-29, `main` `7c6cfce`) 코드 기준이다. 시나리오 4는 임시 공간 탭(PRD-4, #64) 착지 뒤
  2026-10-01 `main` `ff90d74` 기준으로 재판정했다.
- 시나리오 ↔ XCUITest 파일 대응(매칭·예외·구현 대기·공백)은 이 문서가 아니라
  `doc-tracker/` 최신 월 파일의 「e2e 매핑」 절에서 판정한다.
- 시나리오 번호는 식별자(`test-affirmations.md#시나리오 N`)의 일부다. 중간 삽입하지 말고 끝에 덧붙인다.

## 테스트 시나리오

### 시나리오 1: 문장을 직접 추가하면 목록에 남는다
- **사전 조건**: 로그인된 상태. 다짐 탭에 문장이 없거나 임의 개수 있음.
- **실행 단계**:
  1. 다짐 탭에 진입한다.
  2. 추가 버튼을 눌러 편집 시트를 연다.
  3. 문장을 입력하고 우선순위를 「높음」으로 고른 뒤 저장한다.
  4. 다른 탭으로 이동했다가 다짐 탭에 다시 진입한다.
  5. 앱을 종료하고 다시 실행해 다짐 탭에 진입한다.
- **기대 결과**:
  - 저장 직후 목록에 입력한 문장이 나타나고, 우선순위 표시가 「높음」이다.
  - 4·5단계 뒤에도 문장과 우선순위가 그대로 남아 있다(서버 영속).
  - 빈 문장은 저장되지 않는다.
- **검증 AC**: AC1, AC2
- **구현 상태**: 구현됨
- **관련 코드 테스트**: `backend/internal/handlers/affirmations_test.go` — `TestCreateThenList`, `TestCreateRejectsEmptyText`, `TestCreateRejectsInvalidPriority`

### 시나리오 2: 기존 문장의 텍스트와 우선순위를 편집한다
- **사전 조건**: 로그인된 상태. 우선순위 「보통」인 문장이 1개 이상 있음.
- **실행 단계**:
  1. 다짐 탭 목록에서 대상 문장을 눌러 편집 시트를 연다.
  2. 텍스트를 수정하고 우선순위를 「낮음」으로 바꾼 뒤 저장한다.
  3. 다짐 탭에 다시 진입한다.
- **기대 결과**:
  - 목록의 해당 행이 수정된 텍스트와 「낮음」 우선순위로 바뀌어 있다.
  - 다른 문장은 변하지 않는다.
  - 취소로 시트를 닫으면 아무것도 바뀌지 않는다.
- **검증 AC**: AC1, AC2
- **구현 상태**: 구현됨
- **관련 코드 테스트**: `backend/internal/handlers/affirmations_test.go` — `TestUpdateHappyPath`, `TestUpdateOtherUserReturns404`

### 시나리오 3: 문장을 삭제하면 목록과 회전 대상에서 빠진다
- **사전 조건**: 로그인된 상태. 문장이 2개 이상 있음.
- **실행 단계**:
  1. 다짐 탭 목록에서 대상 문장을 삭제한다(행 삭제 동작 또는 편집 시트의 삭제 버튼).
  2. 다짐 탭에 다시 진입하고, 상단 회전 문장을 여러 번 넘겨 본다.
- **기대 결과**:
  - 삭제한 문장이 목록에서 사라지고, 재진입 후에도 나타나지 않는다.
  - 상단 회전 노출에도 삭제한 문장이 다시 나오지 않는다.
  - 새 문장 추가(생성 모드) 시트에는 삭제 버튼이 없다.
- **검증 AC**: AC1
- **구현 상태**: 구현됨
- **관련 코드 테스트**: `backend/internal/handlers/affirmations_test.go` — `TestDeleteOtherUserReturns404`

### 시나리오 4: 임시 공간의 메모를 다짐 문장으로 옮긴다
- **사전 조건**: 로그인된 상태. 임시 공간에 메모가 1개 이상 있음.
- **실행 단계**:
  1. 임시 공간 탭에서 메모 하나를 골라 「다짐으로 이동」 동작을 실행한다.
  2. 다짐 탭에 진입한다.
- **기대 결과**:
  - 옮긴 메모의 텍스트가 다짐 목록에 새 문장으로 나타난다(기본 우선순위 「보통」).
  - 임시 공간에서는 해당 메모가 사라진다(이동이므로 복사가 아니다).
- **검증 AC**: AC1
- **구현 상태**: 구현됨 — 임시 공간 카드의 「→ 다짐」 칩이 이동 동작이다. 서버가 메모 텍스트로 우선순위 「보통」(`normal`) 다짐을
  만들고 원본을 지운 뒤, 앱이 그 문장의 우선순위 편집 시트를 바로 연다(취소하면 「보통」 그대로 남는다).
- **관련 코드 테스트**: `backend/internal/handlers/scratchpad_test.go` `TestScratchpadMoveToAffirmation`(텍스트 동일·우선순위 `normal`·다짐 목록 1건·임시 공간 0건)

### 시나리오 5: 우선순위가 높은 문장이 더 자주 노출된다
- **사전 조건**: 로그인된 상태. 우선순위가 「높음」「보통」「낮음」인 문장이 각각 1개씩 있음.
- **실행 단계**:
  1. 다짐 탭 상단 회전 문장을 충분히 많이(예: 300회) 넘기며 노출된 문장을 센다.
     (또는 같은 풀에서 위젯 타임라인 엔트리를 충분히 많이 생성해 센다.)
- **기대 결과**:
  - 노출 횟수가 「높음」 > 「보통」 > 「낮음」 순서다.
  - 「낮음」 문장도 0회가 아니다(완전히 숨겨지지 않는다).
- **검증 AC**: AC2
- **구현 상태**: 구현됨 — 앱·위젯이 같은 `RotationSelector`(가중 추첨)를 쓴다.
- **관련 코드 테스트**: `ios/PocketAideUnitTests/RotationSelectorTests.swift` — `testWeightedDistribution`, `testZeroWeightItemsAreSkipped`, `testSameSeedIsDeterministic`
- **비고**: 분포 단정은 난수에 기대므로 UI 수준에서 검증하려면 시드 고정(`ROTATION_SEED`, 모킹 정책 `DET`)이 필요하다.

### 시나리오 6: 다짐 탭에 들어올 때마다 다른 문장이 회전 노출된다
- **사전 조건**: 로그인된 상태. 문장이 3개 이상 있음.
- **실행 단계**:
  1. 다짐 탭에 진입해 상단 카드의 문장을 기록한다.
  2. 다른 탭으로 나갔다가 다시 진입하기를 여러 번 반복하며 상단 문장을 기록한다.
  3. 상단 카드의 회전 버튼을 눌러 문장이 바뀌는지 본다.
- **기대 결과**:
  - 반복 진입 동안 상단 카드에 2개 이상의 서로 다른 문장이 나타난다.
  - 회전 버튼을 누르면 상단 문장이 갱신된다.
  - 문장이 0개이면 상단 카드 대신 빈 상태 안내가 보인다.
- **검증 AC**: AC3
- **구현 상태**: 구현됨
- **관련 코드 테스트**: `ios/PocketAideUnitTests/RotationSelectorTests.swift` — `testEmptyPoolReturnsNil`, `testSingleItemAlwaysReturnsIt`

### 시나리오 7: 위젯에 다짐 문장이 표시되고 탭의 변경이 반영된다
- **사전 조건**: 로그인된 상태. 문장이 1개 이상 있음. 홈 화면에 PocketAide 위젯(Large)이 추가되어 있음.
- **실행 단계**:
  1. 위젯의 다짐 영역을 확인한다.
  2. 앱에서 새 문장을 추가하고, 기존 문장 하나를 삭제한다.
  3. 위젯 갱신 주기(30분)가 지난 뒤 위젯을 다시 확인한다.
  4. 로그아웃한 상태에서 위젯을 확인한다.
- **기대 결과**:
  - 1단계: 다짐 영역에 등록된 문장 중 하나가 표시된다.
  - 3단계: 삭제한 문장은 더 이상 나오지 않고, 새 문장이 회전 후보에 포함된다.
  - 4단계: 문장 대신 로그인 필요 안내가 보인다.
- **검증 AC**: AC4
- **구현 상태**: 구현됨 — 앱에서 다짐을 추가·편집·삭제하거나 로그인·로그아웃하면 위젯 타임라인을 즉시 다시 요청한다. 상세는 `test-widget.md` 시나리오 7. (2026-10-01 정정 이력 — 작성 시 「구현됨(표시·주기 갱신)」 → 같은 날 「부분 구현」(재요청 호출 없음, 삭제한 문장이 최대 약 11.5시간 남음) → 재요청 추가로 「구현됨」.)
- **관련 코드 테스트**: 없음 (위젯 `AffirmationProvider` 는 `RotationSelector` 를 공유)
- **비고**: 「즉시 반영」을 요구 수준으로 볼지는 PRD-5 AC4 문구(「갱신 주기에 맞춰」)상 요구되지 않는다. 현재 기대 결과는 주기 반영 기준이다.
