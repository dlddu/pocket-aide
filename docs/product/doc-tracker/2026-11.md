### 매칭 규약
- **매칭 단위**: `android/app/src/androidTest/java/com/dlddu/pocketaide/e2e/` 최상위 `*Test.kt` **파일**(2026-11-02 iOS `ios/PocketAideTests/*UITests.swift` 에서 전환 — iOS CI 를 끈 뒤 CI 가 돌리는 E2E 는 `android-instrumented-test.yml` 뿐이다). 파일 안의 `@Test` 메서드 수는 자유다.
  `E2eSupport.kt`(로그인·Compose 조작·실 백엔드 API 헬퍼 `BackendApi`)·`PushSupport.kt`(가짜 FCM 수신부 조회·`RemoteMessage` 전달·알림 셰이드 조작)·`WebhookSupport.kt`(`workflow_run` envelope 을 로컬 SQS 에 주입)·`ApprovalSupport.kt`(승인 키·요청 시드)는 하네스라 매칭 단위가 아니다. iOS `ios/PocketAideTests/` 는 코드로 남아 있지만 CI 가 돌리지 않아 매칭 단위가 아니다(이식할 때 단언의 출처로 쓴다).
  `android/app/src/test/`(JVM 단위)·`ios/PocketAideUnitTests/`(XCTest 단위)와 `backend/**/*_test.go` 도 매칭 단위가 아니다(예외의 대체 검증 수단으로는 적을 수 있다).
- **시나리오 식별자**: `<문서 파일명>#시나리오 <N>`(서수). 문서 중간 삽입으로 번호가 밀리면 식별자가 바뀐 것이므로
  파일 선언과 이 절의 표를 함께 갱신한다.
- **선언**: 각 매칭 단위 파일은 머리에 `// 검증 시나리오: <식별자>` 를 **정확히 한 줄** 둔다. 시나리오를 주검증하지 않는
  스모크·인프라 파일은 `// 검증 시나리오: 없음 (스모크/인프라)` 로 선언하고 아래 비-시나리오 등재 표에 올린다.
  기계 확인: `grep -H '^// 검증 시나리오:' android/app/src/androidTest/java/com/dlddu/pocketaide/e2e/*Test.kt`
- **세지 않는 것**: 셋업에서 다른 화면·경로를 경유하는 것(예: `E2eSupport.kt` `launchSignedIn` 의 OIDC 로그인)은 검증으로
  세지 않는다. 선언된 대상만 센다.
- **네 통**: 모든 시나리오는 **매칭 · 예외 · 구현 대기 · 공백** 중 정확히 하나에 들어간다.

### 구현 대기 (미구현이라 관측 대상 없음)
기능은 있는데 하네스가 그 상태에 도달하지 못하는 것은 여기가 아니라 공백이다. 미구현 근거는 테스트 문서 「구현 상태」 줄 원문이다 — 단 근거 칸이 「코드 실측 —」으로 시작하는 행은 테스트 문서가 「구현됨」인데 시나리오 단계·기대 결과가 요구하는 앱 경로가 코드에 없는 경우이고, 근거는 코드 위치다. 「동작 실측 —」으로 시작하는 행은 경로는 코드에 있으나 하네스가 그 상태에 **도달한 뒤** 기대 결과와 다르게 동작함이 전용 테스트 실행으로 실측된 경우이고(하네스가 도달하지 못하는 것은 여전히 공백), 근거는 실행(run)·관측값과 코드 위치다.
