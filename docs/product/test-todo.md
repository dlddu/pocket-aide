# 테스트 문서: 개인 투두 / 회사 투두 탭

## 검증 대상 AC
- AC1: 두 영역의 완전 분리 (PRD-3: `prd-todo.md`)
- AC2: 투두 기본 CRUD (PRD-3)
- AC3: 영역 전환 시 시각적 구분 (PRD-3)
- AC4: 영역 간 이동 불가 (의도적 제약) (PRD-3)
- AC5: 임시 공간으로부터의 분류 (PRD-3)

## 달성 가치
- V3: 영역 분리된 작업 관리 — 검증 대상 AC 모두 V3을 달성한다.

## 작성 기준
- 시나리오는 **사용자가 관찰할 수 있는 결과** 단위로 쓴다. 코드 레벨 테스트는 각 시나리오의
  「관련 코드 테스트」에 참고로만 적으며, 시나리오의 검증을 대신하지 않는다.
- 「구현 상태」는 작성 시점(2026-10-01, `main` `a00b3c7`) 코드 기준이다. PRD-3 구현은 #53(AC1~AC4)이며,
  AC5는 임시 공간 탭(PRD-4)이 `PlaceholderTab`이라 미구현이다.
- 개인 탭(탭 바 「개인」)과 회사 탭(탭 바 「회사」)은 같은 화면 유형을 영역만 바꿔 쓴다. AC2가 「각 탭에서
  동일하게」를 요구하므로, CRUD 시나리오(3~6)는 **두 탭 각각에서** 수행해야 통과로 본다.
- 시나리오 ↔ XCUITest 파일 대응(매칭·예외·구현 대기·공백)은 이 문서가 아니라
  `doc-tracker/` 최신 월 파일의 「e2e 매핑」 절에서 판정한다.
- 시나리오 번호는 식별자(`test-todo.md#시나리오 N`)의 일부다. 중간 삽입하지 말고 끝에 덧붙인다.

## 테스트 시나리오

### 시나리오 1: 한 영역에 추가한 항목은 다른 영역 목록에 나타나지 않는다
- **사전 조건**: 로그인된 상태. 개인·회사 탭 모두 항목이 없거나 임의 개수 있음.
- **실행 단계**:
  1. 개인 탭에서 제목 「치과 예약 잡기」로 항목을 추가한다.
  2. 회사 탭에서 제목 「분기 리뷰 자료」로 항목을 추가한다.
  3. 두 탭을 오가며 목록을 확인하고, 각 탭에서 당겨서 새로고침한다.
  4. 앱을 종료하고 다시 실행해 두 탭을 확인한다.
- **기대 결과**:
  - 개인 탭 목록에는 「치과 예약 잡기」만, 회사 탭 목록에는 「분기 리뷰 자료」만 보인다.
  - 각 탭 머리의 개수 요약도 자기 영역 항목만 센다.
  - 새로고침·재실행 뒤에도 두 항목이 각자의 영역에만 남아 있다(서버 영속).
- **검증 AC**: AC1
- **구현 상태**: 구현됨 — 두 영역은 별도 테이블(`personal_todos`·`work_todos`)이고, 목록 API가 영역별로 나뉜다.
- **관련 코드 테스트**: `backend/internal/handlers/todos_test.go` — `TestTodoAreasAreSeparateCollections`, `TestTodoUserScopingAndValidation`

### 시나리오 2: 검색은 현재 영역 안에서만 찾는다
- **사전 조건**: 로그인된 상태. 개인 탭에 제목 「세금 신고」, 회사 탭에 제목 「세금계산서 발행」 항목이 있고,
  회사 탭에 메모가 「세금 관련」인 항목이 하나 더 있음.
- **실행 단계**:
  1. 개인 탭 검색창(「개인 영역만 검색…」)에 「세금」을 입력한다.
  2. 회사 탭 검색창(「회사 영역만 검색…」)에 「세금」을 입력한다.
  3. 회사 탭 검색창에 「없는말」을 입력한다.
  4. 검색어를 지운다.
- **기대 결과**:
  - 1단계: 개인 탭에는 「세금 신고」만 나온다. 회사 항목은 나오지 않는다.
  - 2단계: 회사 탭에는 「세금계산서 발행」과 메모가 일치한 항목이 나온다(제목·메모 모두 검색, 대소문자 무시). 개인 항목은 나오지 않는다.
  - 3단계: 결과가 없다.
  - 4단계: 해당 영역의 전체 목록으로 돌아간다.
- **검증 AC**: AC1
- **구현 상태**: 구현됨 — 검색은 현재 탭이 불러온 영역 목록만 거르는 클라이언트 측 필터다.
- **관련 코드 테스트**: `ios/PocketAideUnitTests/TodoSearchTests.swift` — `testEmptyQueryReturnsEverything`, `testMatchesTitleCaseInsensitively`, `testMatchesMemo`, `testNoMatchReturnsEmpty`

### 시나리오 3: 제목·메모·마감일·우선순위를 넣어 항목을 추가한다
- **사전 조건**: 로그인된 상태. 개인 탭과 회사 탭 각각에서 수행.
- **실행 단계**:
  1. 우상단 + 버튼을 눌러 「새 할 일」 시트를 연다.
  2. 제목을 비워 두거나 공백만 넣은 채 저장 버튼 상태를 본다.
  3. 제목·메모를 입력하고, 마감일을 켜서 날짜를 고르고, 우선순위를 「높음」으로 고른 뒤 저장한다.
  4. 다시 + 버튼을 눌러 제목만 입력하고(마감일 끔, 우선순위 「없음」) 저장한다.
  5. 다른 탭으로 갔다가 돌아오고, 앱을 재실행해 확인한다.
- **기대 결과**:
  - 2단계: 저장 버튼이 비활성이다.
  - 3단계: 목록 「할 일」 섹션에 항목이 나타나고, 보조 줄에 마감일·우선순위·메모가 표시된다.
  - 4단계: 제목만 있는 항목이 추가되고, 보조 줄이 없다(마감일·우선순위·메모는 선택 필드).
  - 5단계: 두 항목이 입력한 값 그대로 남아 있다.
  - 할 일 섹션은 마감일이 이른 항목이 먼저, 마감일 없는 항목이 뒤에 온다.
- **검증 AC**: AC2
- **구현 상태**: 구현됨
- **관련 코드 테스트**: `backend/internal/handlers/todos_test.go` — `TestTodoCRUDInBothAreas`, `TestTodoUserScopingAndValidation`(빈 제목·잘못된 날짜·우선순위 거부), `TestTodoListOrdering`; `ios/PocketAideUnitTests/TodoSearchTests.swift` — `testDueDateRoundTrip`, `testDraftEncodingOmitsUnsetOptionals`

### 시나리오 4: 기존 항목을 편집한다
- **사전 조건**: 로그인된 상태. 마감일·우선순위 「보통」·메모가 있는 항목이 1개 이상. 개인 탭과 회사 탭 각각에서 수행.
- **실행 단계**:
  1. 목록에서 항목을 눌러 「할 일 편집」 시트를 연다.
  2. 제목을 바꾸고, 마감일을 끄고, 우선순위를 「없음」으로 바꾸고, 메모를 지운 뒤 저장한다.
  3. 다른 항목을 열어 제목을 바꾼 뒤 취소를 누른다.
  4. 탭에 다시 들어온다.
- **기대 결과**:
  - 2단계: 행의 제목이 바뀌고 보조 줄(마감일·우선순위·메모)이 사라진다.
  - 3단계: 취소한 항목은 바뀌지 않는다.
  - 4단계 뒤에도 2단계 결과가 유지된다. 편집하지 않은 항목은 변하지 않는다.
- **검증 AC**: AC2
- **구현 상태**: 구현됨
- **관련 코드 테스트**: `backend/internal/handlers/todos_test.go` — `TestTodoCRUDInBothAreas`

### 시나리오 5: 항목을 완료하고 다시 되돌린다
- **사전 조건**: 로그인된 상태. 미완료 항목이 2개 이상. 개인 탭과 회사 탭 각각에서 수행.
- **실행 단계**:
  1. 항목 하나의 체크 박스를 눌러 완료한다.
  2. 탭에 다시 들어온다.
  3. 완료된 항목의 체크 박스를 다시 눌러 되돌린다.
- **기대 결과**:
  - 1단계: 항목이 완료 섹션(개인 「완료」, 회사 「DONE」)으로 옮겨지고, 제목에 취소선이 그어진다.
    머리의 개수 요약에서 남은 수가 1 줄고 완료 수가 1 는다.
  - 1단계에서 메모·마감일·우선순위는 그대로 남는다.
  - 2단계 뒤에도 완료 상태가 유지된다.
  - 3단계: 항목이 할 일 섹션으로 돌아오고 취소선이 사라진다.
- **검증 AC**: AC2
- **구현 상태**: 구현됨
- **관련 코드 테스트**: `backend/internal/handlers/todos_test.go` — `TestTodoCRUDInBothAreas`(완료 시각 기록·재저장 시 유지·되돌리기), `TestTodoListOrdering`(완료 항목은 목록 끝)

### 시나리오 6: 항목을 삭제한다
- **사전 조건**: 로그인된 상태. 항목이 2개 이상. 개인 탭과 회사 탭 각각에서 수행.
- **실행 단계**:
  1. 항목 하나를 왼쪽으로 밀어 「삭제」를 누른다.
  2. 다른 항목을 눌러 편집 시트를 열고 「삭제」를 누른다.
  3. + 버튼으로 새 할 일 시트를 연다.
  4. 탭에 다시 들어오고, 앱을 재실행해 확인한다.
- **기대 결과**:
  - 1·2단계: 삭제한 항목이 목록과 개수 요약에서 바로 빠진다.
  - 3단계: 새 할 일(생성 모드) 시트에는 삭제 버튼이 없다.
  - 4단계: 삭제한 항목이 다시 나타나지 않는다. 다른 영역의 항목은 영향이 없다.
- **검증 AC**: AC2
- **구현 상태**: 구현됨 — 삭제 확인 대화상자는 없다(밀어서 삭제는 전체 밀기 비활성으로 한 번 더 눌러야 실행).
- **관련 코드 테스트**: `backend/internal/handlers/todos_test.go` — `TestTodoCRUDInBothAreas`, `TestTodoUserScopingAndValidation`(다른 사용자 항목 삭제 404)

### 시나리오 7: 개인 탭과 회사 탭은 한눈에 구분된다
- **사전 조건**: 로그인된 상태. 두 탭 모두 미완료·완료 항목이 1개 이상.
- **실행 단계**:
  1. 개인 탭에 들어가 화면 전체를 본다.
  2. 회사 탭으로 전환해 같은 위치들을 비교한다.
  3. (인지 확인) 탭 바를 가린 상태로 두 탭의 화면을 무작위 순서로 보여 주고, 어느 영역인지 바로 답할 수 있는지 본다.
- **기대 결과**:
  - 두 탭의 배경·강조색(머리 위 띠, 체크 박스)이 다르다.
  - 화면 제목이 다르다: 개인 「내 일」, 회사 「회사」.
  - 개수 요약 문구가 다르다: 개인 「N개 남음 · M개 완료」, 회사 「N OPEN · M DONE」(고정폭 글꼴).
  - 섹션 제목이 다르다: 개인 「할 일」「완료」, 회사 「OPEN」「DONE」. 회사 탭은 우선순위를 영문 대문자로 표시한다.
  - 검색창 안내 문구가 영역 이름을 포함한다. 행 모서리 둥글기도 다르다.
  - 편집 시트도 열린 탭의 영역 색을 따른다.
  - 3단계: 탭 바 없이도 영역을 바로 답할 수 있다.
- **검증 AC**: AC3
- **구현 상태**: 구현됨
- **관련 코드 테스트**: 없음
- **비고**: PRD-3 AC3의 검증 방법은 「사용자 인지 테스트」다. 1·2단계의 차이 목록은 관찰 가능한 근거이고,
  통과 판단은 3단계로 한다. 색상 값 자체는 `docs/design-system/tokens.md`의 개인·회사 영역 토큰을 기준으로 한다.

### 시나리오 8: 항목을 다른 영역으로 옮기는 수단이 없다
- **사전 조건**: 로그인된 상태. 개인 탭과 회사 탭에 항목이 각각 1개 이상.
- **실행 단계**:
  1. 개인 탭 항목의 편집 시트를 열어 모든 입력·버튼을 확인한다.
  2. 개인 탭 항목을 왼쪽으로 밀어 나오는 동작을 확인한다.
  3. 개인 탭 항목을 길게 누르고, 끌어서 옮기기를 시도한다.
  4. 회사 탭에서 1~3단계를 반복한다.
- **기대 결과**:
  - 편집 시트에는 제목·메모·마감일·우선순위·저장·삭제·취소만 있고, 영역을 고르거나 바꾸는 입력이 없다.
  - 밀기 동작은 「삭제」 하나뿐이다.
  - 길게 누르기 메뉴나 끌어서 옮기기가 없다.
  - 어떤 조작 뒤에도 항목은 원래 영역에 남아 있다.
- **검증 AC**: AC4
- **구현 상태**: 구현됨 — API도 영역을 URL로만 받고, 요청 본문의 `area` 필드는 400으로 거부하며, 다른 영역 경로로 수정·삭제하면 404다.
- **관련 코드 테스트**: `backend/internal/handlers/todos_test.go` — `TestTodoCannotCrossAreas`

### 시나리오 9: 임시 공간의 메모를 개인 또는 회사 투두로 분류한다
- **사전 조건**: 로그인된 상태. 임시 공간에 메모가 2개 이상 있음.
- **실행 단계**:
  1. 임시 공간 탭에서 메모 하나를 골라 「개인 투두로 분류」를 실행한다.
  2. 다른 메모 하나를 골라 「회사 투두로 분류」를 실행한다.
  3. 임시 공간·개인·회사 탭을 차례로 확인한다.
- **기대 결과**:
  - 1단계 메모는 개인 탭에만, 2단계 메모는 회사 탭에만 새 항목으로 나타난다(메모 텍스트가 제목).
  - 두 메모 모두 임시 공간에서 사라진다(이동이므로 복사가 아니다).
  - 분류는 사용자가 대상 영역을 명시적으로 골라야만 일어난다.
- **검증 AC**: AC5
- **구현 상태**: 미구현 — 임시 공간 탭이 `PlaceholderTab`(「준비 중」)이다. PRD-4 구현 후 검증 가능.
- **관련 코드 테스트**: 없음
- **비고**: 분류된 항목의 기본값(메모 텍스트를 제목으로 쓸지, 마감일·우선순위를 비울지)은 PRD-3·PRD-4에 정해져 있지 않다.
  위 기대 결과의 「메모 텍스트가 제목」은 가정이며, PRD-4 구현 때 확정한다.
