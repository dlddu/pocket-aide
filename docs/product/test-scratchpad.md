# 테스트 문서: 임시 공간 탭

## 검증 대상 AC
- AC1: 항목 자동 수집 (PRD-4: `prd-scratchpad.md`)
- AC2: 직접 메모 추가 (PRD-4)
- AC3: 항목 메타데이터 (PRD-4)
- AC4: 항목 분류 이동 (PRD-4)
- AC5: 미분류 항목 카운트 표시 (PRD-4)

## 달성 가치
- V1: 핸즈프리 즉시 캡처 — AC1·AC2·AC3·AC5
- V3: 영역 분리된 작업 관리 — AC4·AC5

## 작성 기준
- 시나리오는 **사용자가 관찰할 수 있는 결과** 단위로 쓴다. 코드 레벨 테스트는 각 시나리오의
  「관련 코드 테스트」에 참고로만 적으며, 시나리오의 검증을 대신하지 않는다.
- 「구현 상태」는 작성 시점(2026-10-05, `main` `fa3b7c8`) 코드 기준이다. PRD-4 구현은 #64(AC2 텍스트 경로·AC3·AC4·AC5)이고,
  숏컷 음성 모드(PRD-6)와 탭 내 음성 입력은 아직 없다. 서버는 입력 방식 `text`·`voice`·`shortcut`과 캡처 시각을 이미 받는다.
- 분류 이동의 **대상 쪽** 세부(투두 항목의 기본값, 다짐 우선순위 시트)는 각 대상의 테스트 문서가 검증한다 —
  `test-todo.md#시나리오 9`, `test-affirmations.md#시나리오 4`. 이 문서는 이동의 공통 규칙과 「루틴」 대상을 다룬다.
- AC5의 배지 위치는 PRD-12 결정에 따라 하단 탭 바가 아니라 「더 보기」 목록의 임시 공간 항목이다. 작성 시점에는
  승인 탭이 없어 임시 공간이 아직 탭 바 네 번째 자리에 있다(시나리오 7 비고).
- 시나리오 ↔ XCUITest 파일 대응(매칭·예외·구현 대기·공백)은 이 문서가 아니라
  `doc-tracker/` 최신 월 파일의 「e2e 매핑」 절에서 판정한다.
- 시나리오 번호는 식별자(`test-scratchpad.md#시나리오 N`)의 일부다. 중간 삽입하지 말고 끝에 덧붙인다.

## 테스트 시나리오

### 시나리오 1: 숏컷 음성으로 말한 내용이 되묻지 않고 임시 공간에 쌓인다
- **사전 조건**: 로그인된 상태. 아이폰 단축어에 PocketAide 음성 캡처가 등록됨. 앱은 종료되어 있음.
- **실행 단계**:
  1. 단축어(또는 Siri)로 음성 캡처를 호출한다.
  2. 「내일 오전에 보험 서류 보내기」라고 말하고 종료한다.
  3. 앱을 열어 임시 공간 탭을 확인한다.
- **기대 결과**:
  - 1~2단계 동안 저장 위치나 분류를 묻는 질문이 한 번도 없다.
  - 3단계: 「오늘」 섹션 맨 위에 발화 내용이 메모로 있고, 메타 줄이 숏컷 표시 점과 함께 「숏컷 · 음성 · HH:mm」이다.
- **검증 AC**: AC1
- **구현 상태**: 미구현 — 앱이 등록한 App Shortcut은 인사 문구를 돌려주는 `ShowHelloIntent` 하나뿐이고, 음성 캡처 의도는 없다
  (PRD-6 숏컷 음성 모드 구현 전). 서버 `POST /api/scratchpad`는 `source: shortcut`과 `captured_at`을 받아 저장한다.
- **관련 코드 테스트**: `backend/internal/handlers/scratchpad_test.go` — `TestScratchpadCreateRecordsMetadata`(숏컷 항목의 입력 방식·캡처 시각 보존)

### 시나리오 2: 탭에서 텍스트로 새 메모를 추가한다
- **사전 조건**: 로그인된 상태. 임시 공간 탭에 메모가 임의 개수 있음.
- **실행 단계**:
  1. 임시 공간 탭의 「새 메모」를 눌러 시트를 연다.
  2. 입력을 비워 두거나 공백만 넣은 채 「저장」 상태를 본다.
  3. 「  엄마 생신 선물  」(앞뒤 공백 포함)을 입력하고 저장한다.
  4. 다른 탭에 갔다가 돌아오고, 앱을 재실행해 확인한다.
- **기대 결과**:
  - 2단계: 「저장」이 비활성이다.
  - 3단계: 시트가 닫히고 「오늘」 섹션 맨 위에 「엄마 생신 선물」(앞뒤 공백 없이)이 나타난다. 분류 대상을 묻지 않는다.
  - 4단계: 재진입·재실행 뒤에도 메모가 남아 있다(서버 영속).
- **검증 AC**: AC2
- **구현 상태**: 구현됨
- **관련 코드 테스트**: `backend/internal/handlers/scratchpad_test.go` — `TestScratchpadCreateRecordsMetadata`, `TestScratchpadValidation`(빈 텍스트 거부)

### 시나리오 3: 탭에서 음성으로 새 메모를 추가한다
- **사전 조건**: 로그인된 상태. 마이크·음성 인식 권한 허용.
- **실행 단계**:
  1. 임시 공간 탭에서 음성 메모 입력을 시작한다.
  2. 「retention 지표 fact-check 하기」라고 말하고 종료한다.
  3. 목록을 확인한다.
- **기대 결과**:
  - 3단계: 발화 인식 결과가 메모로 저장되고, 메타 줄이 「음성 · HH:mm」이다.
- **검증 AC**: AC2
- **구현 상태**: 미구현 — 「새 메모」 시트는 텍스트 입력 칸뿐이고 앱 자체의 음성 입력이 없다. iOS 키보드 받아쓰기로 넣은 내용은
  텍스트 입력으로 기록되어(「탭 내 입력」) 이 시나리오를 충족하지 않는다. 인식 엔진은 PRD-7 소관이다.
- **관련 코드 테스트**: 없음

### 시나리오 4: 메모마다 캡처 시각과 입력 방식이 보인다
- **사전 조건**: 로그인된 상태. 오늘 텍스트로 추가한 메모 하나와 어제 이전에 추가한 메모 하나가 있음.
  (숏컷·음성 경로가 생기면 각 경로로 캡처한 메모도 하나씩.)
- **실행 단계**:
  1. 임시 공간 탭 목록을 본다.
  2. 메모의 메타 줄과 섹션 머리를 확인한다.
- **기대 결과**:
  - 각 메모 위 메타 줄이 「<입력 방식> · HH:mm」이다 — 텍스트는 「탭 내 입력」, 음성은 「음성」, 숏컷은 「숏컷 · 음성」(숏컷 표시 점 포함).
    시각은 캡처한 시각이다.
  - 메모는 캡처 날짜별 섹션(「오늘」 「어제」 그 이전은 날짜)에 최신 순으로 묶이고, 섹션 머리에 「N ITEMS」가 붙는다.
  - 음성으로 캡처한 메모의 본문은 인식 결과 원문이다.
- **검증 AC**: AC3
- **구현 상태**: 부분 구현 — 메타 줄·날짜 섹션은 구현됐고 서버가 세 입력 방식을 저장·반환한다. 앱에서 만들 수 있는 메모는
  텍스트 경로뿐이라 「음성」·「숏컷 · 음성」 표시와 인식 원문은 관찰할 대상이 없다(시나리오 1·3 미구현).
- **관련 코드 테스트**: `backend/internal/handlers/scratchpad_test.go` — `TestScratchpadCreateRecordsMetadata`;
  `ios/PocketAideUnitTests/ScratchpadTests.swift` — `testDecodesServerItemMetadata`, `testGroupsByDayNewestFirst`, `testEmptyListHasNoSections`

### 시나리오 5: 메모를 루틴으로 옮기면 「매일」 루틴이 단계 없이 생기고 원본은 사라진다
- **사전 조건**: 로그인된 상태. 임시 공간에 메모 「저녁 정리」와 다른 메모 하나가 있음.
- **실행 단계**:
  1. 「저녁 정리」 카드의 「→ 루틴」 칩을 누른다.
  2. 임시 공간 목록을 본다.
  3. 루틴 탭을 연다.
  4. 앱을 재실행해 두 탭을 확인한다.
- **기대 결과**:
  - 2단계: 「저녁 정리」만 임시 공간에서 사라지고 다른 메모는 남는다(이동이므로 복사가 아니다).
  - 3단계: 「오늘」 섹션에 「저녁 정리」 루틴이 요약 「매일 · 0 / 0 완료」로 있다 — 주기는 「매일」, 단계는 없다.
    단계는 카드의 「단계」 시트에서 붙일 수 있다.
  - 4단계: 재실행 뒤에도 메모는 임시 공간에 없고 루틴은 루틴 탭에 있다.
- **검증 AC**: AC4
- **구현 상태**: 구현됨 — 서버가 한 트랜잭션으로 루틴을 만들고 임시 공간 원본을 지운다(`prd-routines.md` 결정 사항).
- **관련 코드 테스트**: `backend/internal/handlers/scratchpad_test.go` — `TestScratchpadMoveToRoutine`;
  `ios/PocketAideUnitTests/RoutinesTests.swift` — `testMoveResultCarriesRoutine`

### 시나리오 6: 메모마다 네 대상이 제시되고, 칩을 누른 대상으로만 옮겨진다
- **사전 조건**: 로그인된 상태. 임시 공간에 메모가 5개 있음.
- **실행 단계**:
  1. 각 메모 카드에 있는 이동 칩을 확인한다.
  2. 메모 넷에 각각 「→ 개인」 「→ 회사」 「→ 다짐」 「→ 루틴」을 누른다(「→ 다짐」 뒤 열리는 우선순위 시트는 「취소」).
  3. 임시 공간과 개인·회사·다짐·루틴 탭을 확인한다.
- **기대 결과**:
  - 1단계: 모든 카드에 「→ 개인」 「→ 회사」 「→ 다짐」 「→ 루틴」 네 칩이 있다.
  - 3단계: 칩을 누른 네 메모는 임시 공간에서 사라지고 각자 고른 대상에만 한 건씩 생긴다. 칩을 누르지 않은 메모는
    임시 공간에 남고 어느 대상에도 생기지 않는다 — 분류는 사용자가 대상을 고를 때만 일어난다.
- **검증 AC**: AC4
- **구현 상태**: 구현됨 — 이동 API가 대상별로 항목을 만들고 원본을 지운다. 대상 쪽 세부는 `test-todo.md#시나리오 9`·
  `test-affirmations.md#시나리오 4`·이 문서 시나리오 5가 검증한다.
- **관련 코드 테스트**: `backend/internal/handlers/scratchpad_test.go` — `TestScratchpadMoveToTodoAreas`, `TestScratchpadMoveToAffirmation`,
  `TestScratchpadMoveToRoutine`, `TestScratchpadUserScoping`; `ios/PocketAideUnitTests/ScratchpadTests.swift` — `testDecodesMoveResultForEachTarget`

### 시나리오 7: 미분류 개수 배지가 추가·이동·삭제를 따라간다
- **사전 조건**: 로그인된 상태. 임시 공간에 메모가 2개 있음. 「더 보기」 목록의 임시 공간 항목이 보이는 상태.
- **실행 단계**:
  1. 「더 보기」 목록의 임시 공간 항목 배지와 임시 공간 탭 머리의 「분류되지 않은 메모」 숫자를 본다.
  2. 「새 메모」로 메모 하나를 추가한다.
  3. 메모 하나를 「→ 개인」으로 옮긴다.
  4. 메모 하나를 왼쪽으로 밀어 「삭제」한다.
  5. 앱을 재실행해 배지를 본다.
- **기대 결과**:
  - 1단계: 배지와 머리 숫자가 모두 2다.
  - 2~4단계: 각 조작 직후 배지·머리 숫자가 3 → 2 → 1로 바뀐다(다른 탭으로 다녀오지 않아도).
  - 5단계: 재실행 뒤에도 1이다.
- **검증 AC**: AC5
- **구현 상태**: 부분 구현 — 미분류 개수는 임시 공간 탭 항목의 배지(`.badge`)와 탭 머리 숫자로 표시되고 추가·이동·삭제를
  즉시 따라간다(두 표시가 같은 뷰 모델을 공유). 그러나 승인 탭(PRD-12) 전이라 임시 공간이 아직 하단 탭 바 네 번째 자리에 있어,
  배지가 「더 보기」 목록이 아니라 탭 바에 보인다. 「더 보기」 목록 항목에 배지가 실제로 그려지는지는 탭 구성 변경 때 확인한다(PRD-4 AC5 비고).
- **관련 코드 테스트**: 없음 — 개수는 불러온 목록 길이(`ScratchpadViewModel.unclassifiedCount`)다.
- **비고**: 위젯의 미분류 개수(PRD-8 AC9)는 `test-widget.md#시나리오 9`가 검증한다.
