# PRD: LLM 기반 글쓰기 파트너 키보드 (키보드 확장)

## 달성 가치
- **V5**: 자연어 대화 기반 작업 처리 — 명령 메뉴 대신 자연 대화로 글쓰기 작업을 처리, 음성/텍스트가 같은 대화 인터페이스를 공유
- **V7**: 시스템 전역 글쓰기 보조 — 어떤 앱의 텍스트 입력 창에서도 LLM 기반 편집 사용 가능

## 개요

iOS 키보드 확장(Custom Keyboard Extension)으로 등록되는 글쓰기 파트너. 사용자는 메시지·메일·메모 등 어떤 앱의 입력창에서도 본 키보드로 전환할 수 있다.

본 키보드의 핵심은 **고정된 명령 메뉴가 아니라 자연어 대화**다. 사용자가 트리거를 누르면 자판은 가려지고 **전면 대화 UI**로 진입하여, 음성 또는 텍스트로 LLM에게 자유롭게 지시한다. 받아쓰기·미시 편집(단어 바꾸기, 문장 재배치)·거시 편집(전체 재구성)·백지 작성까지 글쓰기의 전 과정을 같은 대화 안에서 위임한다.

**핵심 사용 흐름**:
1. 호스트 앱(메일·메시지 등) 입력창에서 본 키보드로 전환
2. 트리거 조작 → 자판이 가려지고 전면 대화 UI 진입
3. 호스트 입력창의 텍스트(또는 선택 영역)는 자동으로 컨텍스트로 전달됨 (없어도 됨)
4. 음성 또는 텍스트로 자연어 지시 ("받아써줘", "이 문단 자연스럽게", "마지막 문장만 단호하게", "이 단어를 다른 말로", "이 메일 사과하는 톤으로 다시")
5. LLM 응답은 미리보기 영역에서 확인 → 적용 / 거절 / 이어서 대화
6. 적용 시 호스트 입력창에 반영되고 자판으로 복귀

## Acceptance Criteria

### AC1: iOS 키보드 확장 등록
- **설명**: 본 앱은 iOS의 Custom Keyboard Extension을 제공하며, 사용자는 시스템 설정에서 이를 등록·활성화할 수 있다.
- **달성 가치**: V7
- **검증 방법**: 설정 → 일반 → 키보드에서 본 키보드 등록 가능 여부 확인.

### AC2: 어떤 앱에서든 호출 가능
- **설명**: 등록된 키보드는 텍스트 입력이 가능한 어떤 앱에서도 키보드 전환을 통해 호출할 수 있다.
- **달성 가치**: V7
- **검증 방법**: 메시지·메일·메모·기타 임의 앱에서 본 키보드로 전환 가능한지 확인.

### AC3: 호스트 입력창 컨텍스트 자동 전달
- **설명**: 대화 UI 진입 시 호스트 앱 입력창의 텍스트(또는 사용자가 선택한 영역)가 자동으로 LLM 컨텍스트로 전달된다. 입력창이 비어 있어도 호출은 가능하다(백지 작성용).
- **달성 가치**: V7
- **검증 방법**: 텍스트가 있는 상태/없는 상태 각각에서 대화 UI 진입 후 LLM이 컨텍스트를 인지하는지 확인.

### AC4: 전면 대화 UI 진입·복귀
- **설명**: 키보드의 트리거 조작 시 자판이 가려지고 키보드 영역 전체를 점유하는 전면 대화 UI로 전환된다. 호스트 앱의 입력창·헤더는 화면 상단에 그대로 보여 사용자가 원문과 대조할 수 있다. 사용자가 명시적으로 대화 UI를 닫으면 표준 자판으로 복귀한다.
- **달성 가치**: V5, V7
- **검증 방법**: 트리거 → 자판이 사라지고 대화 UI가 점유하는지 / 닫기 → 자판 복귀하는지 확인.

### AC5: 음성 받아쓰기 (본 앱 경유 녹음·인식)
- **설명**: 대화 UI 안에서 음성 입력으로 받아쓰기·지시를 할 수 있다. 키보드 확장은 기기 마이크에 접근할 수 없으므로 **녹음과 음성 인식은 본 앱이 맡고**, 키보드는 그 결과를 받는다. 녹음 세션이 없을 때 대화 UI의 마이크 버튼을 누르면 본 앱이 잠깐 열려 녹음을 시작하고, 사용자는 원래 앱으로 돌아와 이어서 말한다. 인식은 메인 앱의 STT 엔진(`prd-stt-engine.md` AC2·AC6)이 한다. 인식 결과는 곧바로 호스트 입력창에 덮어쓰지 않고 미리보기에서 검토한다(AC9).
- **달성 가치**: V5, V7
- **의존**: `prd-stt-engine.md` AC2·AC6 · 구현 구조는 엔지니어링 문서 `../engineering/keyboard-voice-input.md`
- **검증 방법**: 녹음 세션이 없는 상태에서 대화 UI의 마이크 버튼 → 본 앱이 열려 녹음을 시작하고, 원래 앱으로 돌아와 말한 내용의 인식 결과가 대화 UI(지시 또는 미리보기)에 도착하는지 확인. 호스트 입력창은 「적용」 전까지 바뀌지 않는지 확인. 같은 발화를 키보드와 메인 앱 진입점(예: 채팅 음성 모드)에서 입력했을 때 결과가 같은지 확인.

### AC6: 자연어 지시로 미시 편집
- **설명**: "마지막 문장만 단호하게", "이 단어를 다른 말로", "여기 부분만 짧게" 등 부분 지칭 편집을 자연어로 수행한다. LLM은 컨텍스트 안의 어느 부분을 편집할지 사용자의 자연어 지시로부터 판단한다.
- **달성 가치**: V5, V7
- **검증 방법**: 부분 지칭이 포함된 다양한 자연어 지시 → 의도한 영역이 편집되는지 확인.

### AC7: 자연어 지시로 거시 편집
- **설명**: 문장 순서 재배치, 문단 재구성, 글 전체 다시 쓰기, 형식 변경(예: 표·리스트로) 등 큰 단위 편집을 자연어로 수행한다.
- **달성 가치**: V5, V7
- **검증 방법**: 글 전체 단위의 다양한 자연어 지시 → 결과 확인.

### AC8: 백지 작성 지원
- **설명**: 호스트 입력창이 비어 있을 때 "친구에게 사과하는 메시지 써줘", "이 일정으로 메일 초안" 같은 백지 작성 지시를 처리한다.
- **달성 가치**: V5, V7
- **검증 방법**: 빈 입력창 + 백지 작성 지시 → 적절한 초안 생성되는지 확인.

### AC9: 미리보기 · 적용 · 거절 · 이어서 대화
- **설명**: LLM 응답은 호스트 입력창에 즉시 덮어쓰지 않는다. 대화 UI의 미리보기 영역에서 결과를 확인한 뒤, 사용자는 (1) 적용 (2) 거절 (3) 이어서 다시 지시 중 하나를 선택한다. 적용 시 호스트 입력창에 반영된다. 부분 적용(LLM이 제안한 결과 중 일부 문장만 채택) 또한 가능하다.
- **달성 가치**: V5, V7
- **검증 방법**: 각 분기(적용/거절/추가 지시/부분 적용)의 동작 확인.

### AC10: 적용 모드 (덮어쓰기 / 선택 영역 / 삽입)
- **설명**: 적용 시 호스트 입력창에 어떻게 반영할지 결정해야 한다. 기본 모드와 선택 옵션은 다음 중에서 결정한다:
  - 입력창 전체 덮어쓰기
  - 선택 영역만 치환
  - 커서 위치에 삽입
- **달성 가치**: V7
- **검증 방법**: 각 모드에서 호스트 입력창에 정확히 반영되는지 확인.
- **참고**: 기본 모드는 열린 질문에서 결정.

### AC11: 한·영 혼용 텍스트 대응
- **설명**: 입력 텍스트가 한·영 혼용일 경우에도 받아쓰기·편집·생성 모두 정상 작동한다.
- **달성 가치**: V7
- **검증 방법**: 한·영 혼용 텍스트로 각 시나리오 수행 시 결과 확인.

### AC12: Full Access 권한 처리
- **설명**: LLM 호출 및 음성 인식기 통신에는 네트워크 접근이 필요하므로 키보드 확장에 "Full Access" 권한이 요구된다. 본 앱은 권한의 필요성을 명확히 안내하고, 권한 없이는 LLM 기능과 음성 받아쓰기가 비활성화됨을 표시한다.
- **달성 가치**: V7
- **검증 방법**: Full Access 미부여 상태에서 대화 UI 진입 → 비활성화 안내 표시 확인.

### AC13: 응답 지연 동안의 UX · 취소
- **설명**: LLM 호출과 음성 인식 모두 시간이 걸린다. 대화 UI는 처리 중임을 명확히 표시하고, 사용자가 취소하거나 다음 지시로 넘어갈 수 있도록 비동기로 처리한다. 처리 중에도 호스트 입력창은 영향받지 않는다.
- **달성 가치**: V5, V7
- **검증 방법**: 호출 중 UI 상태 / 취소 동작 / 호스트 입력창 무영향 확인.

- **받아쓰기와 지시의 구분**: 같은 음성 결과를 「지시」(대화로 보냄)와 「받아쓰기」(미리보기로 보냄) 중 어디로 보낼지 — 사용자가 고를지, LLM이 판단할지.
- **적용 모드의 기본값**: AC10의 세 가지 적용 모드 중 어느 것을 기본으로 할지, 사용자가 매번 선택하게 할지, 컨텍스트(선택 영역 유무)에 따라 자동 분기할지.
- **인증/세션 공유**: 메인 앱과 키보드 확장 간 인증·세션 공유 방식 (App Group, Keychain Sharing 등).
- **프라이버시 고지**: 호스트 앱 입력창의 텍스트가 LLM 서버로 전송되는 점에 대해 사용자에게 어떻게 투명하게 알릴지.
- **대화 이력 보존 범위**: 대화 UI를 한 번 닫았다 다시 열면 이전 대화가 유지되는가, 매 호출마다 새 세션인가. 호스트 앱·입력창이 바뀌면?

## 결정 사항

- **음성 입력 경로 (AC5)**: 키보드 확장은 기기 마이크에 접근할 수 없으므로, 키보드의 음성 입력은 본 앱이 녹음하고 메인 앱 STT 엔진으로 인식한 뒤 결과를 키보드에 넘긴다. 녹음 세션이 없을 때 마이크 버튼은 본 앱을 잠깐 열어 녹음을 시작하고, 사용자는 원래 앱으로 돌아온다. 키보드 확장 안에 별도 인식기를 두지 않는다 — 키보드 음성도 메인 앱 진입점과 같은 엔진을 쓴다(`prd-stt-engine.md` AC2). 구현 구조(세션 유지·결과 전달·플랫폼 제약)는 엔지니어링 문서 `../engineering/keyboard-voice-input.md`에 둔다.
