## 명시된 열린 질문 (PRD에 기록됨)

### PRD-8 (위젯) 관련
- 아이폰 알림 모음의 정의: iOS는 시스템 알림 직접 접근을 제한함. 본 앱이 발행한 알림으로 한정할지, 다른 형태로 정의할지 확인 필요.

### PRD-7 (STT 엔진) 관련
- 키보드 확장 전용 인식기의 구현 형태 (on-device / 네트워크 / 하이브리드).
- 메인 엔진과의 코드·모델 공유 범위 (App Extension 메모리 한계 고려).
- 사용자 정의 어휘의 App Group 동기화 방식.

### PRD-9 (키보드 확장) 관련
- 적용 모드(전체 덮어쓰기 / 선택 영역 / 커서 삽입)의 기본값 결정 필요.
- 메인 앱-키보드 확장 간 인증/세션 공유 메커니즘 결정 필요.
- 입력 텍스트 LLM 전송에 대한 사용자 투명성 안내 방식 결정 필요.
- 대화 이력 보존 범위 (호출 간/호스트 앱 간 세션 정책).

### PRD-10 (GitHub PR·CI 모니터링) 관련
- 백그라운드 폴링 주기 vs. 서버 웹훅 + APNs 푸시 모델 선택.
- 서버 컴포넌트(기존 Go 백엔드) 활용 범위.
- "관심 PR"의 범위 (작성자/리뷰어 한정 vs. CODEOWNERS·팀 리뷰 포함).
- GitHub Enterprise 지원 여부.
- CI 시스템 범위 (GitHub Actions 한정 vs. Checks API 전체).
- GitHub 연결 방식 (OAuth vs. Personal Access Token).
- V9 가치 원안 표현("개발 경험을 줄인다")이 의도(개발 경험에서 발생하는 마찰 감소)와 어긋남 → values.md에서 재서술. 의도 확인 필요.

## 다음 단계 권장

1. **가치 문서 검토** — V1~V8이 사용자 의도와 맞는지 확인. 누락된 가치, 잘못 추론된 가치 수정.
2. **PRD별 AC 검토** — 각 AC가 충분한 완료 조건인지, 누락된 시나리오가 있는지 확인.
3. **열린 질문 해소** — 위젯의 알림 정의, 키보드 확장의 인증 모델·프라이버시 정책 결정.
4. **테스트 문서 작성** — AC 단위로 테스트 시나리오 작성. (현재 47개 AC 모두 미커버)
