# 테스트 문서: 루틴 관리 탭

## 검증 대상 AC
- AC1: 루틴 생성 및 단계 정의 (PRD-2: `prd-routines.md`)
- AC2: 루틴 반복 주기 설정 (PRD-2)
- AC3: 단계 체크 및 완료 처리 (PRD-2)
- AC4: 루틴 수행 이력 조회 (PRD-2)

## 달성 가치
- V8: 일상 루틴의 구조화 — 검증 대상 AC 모두 V8을 달성한다.

## 작성 기준
- 시나리오는 **사용자가 관찰할 수 있는 결과** 단위로 쓴다. 코드 레벨 테스트는 각 시나리오의
  「관련 코드 테스트」에 참고로만 적으며, 시나리오의 검증을 대신하지 않는다.
- 「구현 상태」는 작성 시점(2026-10-05, `main` `fa3b7c8`) 코드 기준이다. PRD-2 구현은 #88(AC1~AC4)이다.
- 「오늘」은 앱이 기기 달력으로 계산한 날짜(`YYYY-MM-DD`)이고 서버는 그 문자열로 요일·일자를 판정한다
  (`prd-routines.md` 결정 사항). 날짜가 지나야 관찰되는 단계(시나리오 4·6·7)는 해당 날짜에 확인한다.
- 루틴 이름·주기 변경은 PRD-2 범위 밖이라(삭제 후 재생성) 시나리오에 넣지 않는다.
- 임시 공간 항목을 「→ 루틴」으로 옮기는 경로는 PRD-4 AC4 소관이라 `test-scratchpad.md`에서 다룬다.
- 시나리오 ↔ XCUITest 파일 대응(매칭·예외·구현 대기·공백)은 이 문서가 아니라
  `doc-tracker/` 최신 월 파일의 「e2e 매핑」 절에서 판정한다.
- 시나리오 번호는 식별자(`test-routines.md#시나리오 N`)의 일부다. 중간 삽입하지 말고 끝에 덧붙인다.

## 테스트 시나리오

### 시나리오 1: 이름과 단계를 넣어 루틴을 만들면 같은 구조로 남는다
- **사전 조건**: 로그인된 상태. 루틴 탭에 루틴이 없거나 임의 개수 있음.
- **실행 단계**:
  1. 루틴 탭 머리의 「새 루틴」을 눌러 시트를 연다.
  2. 이름을 비워 두거나 공백만 넣은 채 「저장」 버튼 상태를 본다.
  3. 이름에 「아침 루틴」을 넣고, 주기는 「매일」 그대로 둔다. 「단계 추가」로 칸을 늘려 「물 한 잔」 「스트레칭」
     「일정 확인」 세 단계를 넣고, 빈 단계 칸 하나를 남긴 채 저장한다.
  4. 다른 탭에 갔다가 돌아오고, 앱을 종료한 뒤 다시 실행해 루틴 탭을 확인한다.
- **기대 결과**:
  - 2단계: 「저장」이 비활성이다.
  - 3단계: 「오늘」 섹션에 「아침 루틴」 카드가 생기고, 요약 줄이 「매일 · 0 / 3 완료」, 진행 표시가 「대기」다.
    단계 셋이 입력한 순서대로 보이고, 빈 칸은 단계로 저장되지 않는다.
  - 4단계: 탭 재진입·재실행 뒤에도 같은 이름·주기·단계 셋·순서가 그대로다(서버 영속).
- **검증 AC**: AC1
- **구현 상태**: 구현됨 — 저장 시 단계 칸의 앞뒤 공백을 다듬고 빈 칸을 버린다.
- **관련 코드 테스트**: `backend/internal/handlers/routines_test.go` — `TestRoutineCreateKeepsStructure`, `TestRoutineValidation`;
  `ios/PocketAideUnitTests/RoutinesTests.swift` — `testDraftEncodesWireKeys`, `testDecodesRoutineWithSteps`

### 시나리오 2: 만든 뒤에도 단계 시트에서 단계를 더하고 지울 수 있다
- **사전 조건**: 로그인된 상태. 오늘 활성화된 루틴(예: 시나리오 1의 「아침 루틴」, 단계 3개)이 있음.
- **실행 단계**:
  1. 카드의 「단계」 버튼을 눌러 「아침 루틴 · 단계」 시트를 연다.
  2. 입력 칸을 비운 채 「단계 추가」 버튼 상태를 본다.
  3. 「비타민 먹기」를 입력하고 「단계 추가」를 누른다.
  4. 시트를 다시 열어 「스트레칭」 옆의 빼기 버튼을 누른다.
  5. 앱을 재실행해 카드를 확인한다.
- **기대 결과**:
  - 2단계: 「단계 추가」가 비활성이다.
  - 3단계: 카드의 단계 목록 끝에 「비타민 먹기」가 붙고 요약 줄 분모가 4가 된다.
  - 4단계: 「스트레칭」이 카드에서 사라지고 분모가 3이 된다.
  - 5단계: 재실행 뒤에도 「물 한 잔」 「일정 확인」 「비타민 먹기」 세 단계가 남아 있다.
- **검증 AC**: AC1
- **구현 상태**: 구현됨 — 단계 삭제에는 확인 단계가 없고, 지운 단계의 과거 체크도 함께 지워진다(결정 사항).
- **관련 코드 테스트**: `backend/internal/handlers/routines_test.go` — `TestRoutineCreateKeepsStructure`(단계 추가·삭제 왕복)

### 시나리오 3: 네 가지 반복 주기를 고르고, 오늘 활성 여부에 따라 나뉘어 보인다
- **사전 조건**: 로그인된 상태. 오늘 요일을 W, 오늘 일자를 D라 한다(예: 2026-10-05 → 월요일, 5일).
- **실행 단계**:
  1. 「새 루틴」 시트에서 주기 세그먼트를 「특정 요일」로 바꾸고, 요일을 하나도 고르지 않은 채 「저장」 상태를 본다.
  2. 「특정 요일」로 W가 **아닌** 요일 둘을 골라 「저녁 정리」를 저장한다.
  3. 「매주」로 바꿔 요일 하나를 고른 뒤 다른 요일을 눌러 본다. W 하나만 골라 「주간 회고」를 저장한다.
  4. 「매월」로 바꿔 스테퍼로 D가 아닌 일자를 골라 「관리비 확인」을 저장한다.
  5. 「매일」로 「물 마시기」를 저장한다.
- **기대 결과**:
  - 1단계: 「저장」이 비활성이다(「특정 요일」은 요일이 하나 이상, 「매주」는 정확히 하나여야 한다).
  - 3단계: 「매주」에서는 다른 요일을 누르면 선택이 그 요일로 옮겨 간다(항상 하나).
  - 「오늘 · N」 섹션에 「주간 회고」(요약 「매주 W요일」)와 「물 마시기」(「매일」)가 단계 체크 카드로 보인다.
  - 「오늘 쉬는 루틴」 섹션에 「저녁 정리」(고른 두 요일, 예: 「화·목 · 단계 0개」)와 「관리비 확인」(「매월 N일」)이
    보이고, 요일 주기 루틴에는 요일 막대에서 고른 요일이 강조된다. 쉬는 루틴에는 체크할 단계가 나오지 않는다.
  - 머리의 날짜(「M월 d일 · E요일」)가 기기 날짜와 같다.
- **검증 AC**: AC2
- **구현 상태**: 구현됨 — 「매월」 스테퍼 범위는 1~31이다.
- **관련 코드 테스트**: `backend/internal/handlers/routines_test.go` — `TestRoutineDayShowsOnlyScheduledRoutines`, `TestRoutineValidation`;
  `backend/internal/routines/schedule_test.go` — `TestScheduleMatches`, `TestScheduleNormalized`;
  `ios/PocketAideUnitTests/RoutinesTests.swift` — `testScheduleSummaries`

### 시나리오 4: 주기가 돌아온 날에 루틴이 「오늘」로 올라온다
- **사전 조건**: 로그인된 상태. 시나리오 3의 루틴 넷이 있음.
- **실행 단계**:
  1. 「저녁 정리」가 고른 요일 중 하나가 된 날 루틴 탭을 연다(이미 열려 있었다면 당겨서 새로고침한다).
  2. 「관리비 확인」의 일자가 된 날 루틴 탭을 연다.
  3. 「주간 회고」 요일이 아닌 날 루틴 탭을 연다.
- **기대 결과**:
  - 1단계: 「저녁 정리」가 「오늘」 섹션 카드로 올라와 있다. 사용자가 따로 켜지 않는다.
  - 2단계: 「관리비 확인」이 「오늘」 섹션에 있다. 고른 일자가 그 달에 없으면(예: 31일 → 9월) 그 달의 마지막 날에 올라온다.
  - 3단계: 「주간 회고」는 「오늘 쉬는 루틴」에 있다. 「물 마시기」는 매일 「오늘」에 있다.
- **검증 AC**: AC2
- **구현 상태**: 구현됨 — 탭이 열릴 때와 당겨서 새로고침할 때 그날 날짜로 다시 불러온다. 짧은 달의 마지막 날 판정은
  서버 일정 판정으로 확정되며, 앱에서 관찰하려면 해당 날짜를 기다려야 한다.
- **관련 코드 테스트**: `backend/internal/routines/schedule_test.go` — `TestScheduleMatches`(「monthly 31 in short month」
  「monthly 31 in february」 포함), `TestScheduledOnRespectsStartDay`; `ios/PocketAideUnitTests/RoutinesTests.swift` — `testDayFormatUsesCalendarDay`

### 시나리오 5: 단계를 모두 체크하면 그날 루틴이 완료된다
- **사전 조건**: 로그인된 상태. 오늘 활성화된 루틴에 단계가 3개 있고 아무것도 체크되지 않음.
- **실행 단계**:
  1. 첫 단계를 누른다.
  2. 나머지 두 단계를 차례로 누른다.
  3. 앱을 재실행해 카드를 확인한다.
  4. 마지막으로 누른 단계를 다시 눌러 체크를 푼다.
- **기대 결과**:
  - 1단계: 단계에 체크 표시와 취소선이 생기고, 요약 줄이 「1 / 3 완료」, 진행 표시가 「33%」로 바뀐다.
  - 2단계: 「3 / 3 완료」가 되고 진행 표시가 「완료」, 카드 테두리가 강조된다.
  - 3단계: 재실행 뒤에도 세 단계 체크와 「완료」가 유지된다(서버 영속).
  - 4단계: 「2 / 3 완료」·「67%」로 돌아가고 완료 강조가 사라진다.
- **검증 AC**: AC3
- **구현 상태**: 구현됨
- **관련 코드 테스트**: `backend/internal/handlers/routines_test.go` — `TestRoutineChecksCompleteTheDay`;
  `ios/PocketAideUnitTests/RoutinesTests.swift` — `testDayProgressAndCompletion`

### 시나리오 6: 체크는 그날에만 유효하고, 단계 없는 루틴은 완료되지 않는다
- **사전 조건**: 로그인된 상태. 「매일」 루틴 둘 — 단계 2개짜리(오늘 모두 체크해 「완료」)와 단계 없는 것.
  「오늘 쉬는 루틴」에 하나 이상.
- **실행 단계**:
  1. 오늘 단계 없는 루틴 카드를 본다.
  2. 「오늘 쉬는 루틴」 행을 누른다.
  3. 다음 날 루틴 탭을 연다.
- **기대 결과**:
  - 1단계: 단계 없는 루틴은 「0 / 0 완료」·「대기」이고 「완료」가 되지 않는다.
  - 2단계: 단계 체크 화면이 아니라 이력 시트가 열린다 — 쉬는 날에는 체크할 수단이 없다.
  - 3단계: 어제 「완료」였던 루틴의 단계가 모두 체크 해제된 상태로 「0 / 2 완료」·「대기」에서 다시 시작한다.
- **검증 AC**: AC3
- **구현 상태**: 구현됨 — 체크는 단계 × 날짜로 기록되고, 활성화되지 않은 날짜의 체크는 서버가 409로 거부한다.
- **관련 코드 테스트**: `backend/internal/handlers/routines_test.go` — `TestRoutineCheckRejectsUnscheduledDay`, `TestRoutineChecksCompleteTheDay`

### 시나리오 7: 이력 시트에서 지난 30일의 일자별 상태를 본다
- **사전 조건**: 로그인된 상태. 「특정 요일」 루틴(단계 2개)을 며칠 전에 만들어, 활성화된 날 중 하루는 모두 체크,
  하루는 하나만 체크, 하루는 체크하지 않음.
- **실행 단계**:
  1. 오늘 카드의 「이력」(또는 「오늘 쉬는 루틴」 행)을 눌러 이력 시트를 연다.
  2. 30칸 격자와 그 아래 일자별 목록을 본다.
  3. 「닫기」로 시트를 닫는다.
- **기대 결과**:
  - 머리가 「<루틴 이름> · 30일」이고, 요약 줄이 「<주기> · 예정 N일 중 M일 완료」다.
  - 일자별 목록은 최근 날짜가 위이고, 모두 체크한 날은 「완료」, 하나만 체크한 날은 「미완료 1/2」,
    체크하지 않은 활성일은 「미완료 0/2」, 활성화되지 않은 날과 루틴을 만들기 전 날짜는 「쉬는 날」이다.
  - 격자 칸은 완료·일부 체크·미체크·쉬는 날이 서로 다르게 칠해진다.
- **검증 AC**: AC4
- **구현 상태**: 구현됨 — 과거 날짜의 분모는 현재 단계 수다(결정 사항). 단계를 지운 뒤에는 과거 날짜의 「미완료 n/m」 분모도 바뀐다.
- **관련 코드 테스트**: `backend/internal/handlers/routines_test.go` — `TestRoutineHistoryByDay`;
  `backend/internal/routines/schedule_test.go` — `TestScheduledOnRespectsStartDay`;
  `ios/PocketAideUnitTests/RoutinesTests.swift` — `testHistoryStatusAndSummary`
