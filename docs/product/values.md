# PocketAide 제품 가치 문서

> 이후 모든 PRD/AC/테스트의 최우선 판단 기준이 되는 문서.

## 제품 소유자

- [사용자 본인 / 단독 소유자]

## 제품 개요

iOS 기반 개인 비서 앱. 음성·텍스트 입력 모두 지원하며, 한국어/영어 혼용 환경에서 즉시 캡처·작업 관리·정보 통합·글쓰기 보조를 제공한다.

---

## 제품 가치

### V1: 핸즈프리 즉시 캡처
- **유형**: 구체적
- **설명**: 양손이 자유롭지 않은 상황(운전, 보행, 회의 직후 등)에서 음성 한 번으로 1단계 만에 저장 완료. 시스템(아이폰 숏컷)에서 직접 호출 가능하며, 저장 시 되묻기 없음.
- **측정 기준**: 호출에서 저장 완료까지 사용자 추가 입력 0회.

### V2: 한·영 혼용 음성 인식 정확도
- **유형**: 추상적
- **설명**: 한 문장 안에 한국어와 영어가 섞여 있는 자연스러운 코드스위칭 발화를 정확히 인식한다. 외래어·고유명사·기술 용어가 등장해도 사용자가 다시 말하지 않아도 된다.

### V3: 영역 분리된 작업 관리
- **유형**: 추상적
- **설명**: 개인 일과 회사 일을 한 공간에 섞지 않는다. 컨텍스트 스위칭 부담을 줄이고, 보안·심리적 분리를 지원한다.

### V4: 의도된 반복 노출
- **유형**: 추상적
- **설명**: 사용자가 자기에게 자주 되새겨주고 싶은 문장(다짐, 가치, 메모, 인용)을 의도적으로 반복 노출한다. 앱 내 전용 탭과 위젯 양쪽에서 노출된다.

### V5: 자연어 대화 기반 작업 처리
- **유형**: 추상적
- **설명**: 명령어나 폼이 아니라 자연 대화로 정보를 묻고 작업을 처리한다. 음성/텍스트 모두 동일한 대화 인터페이스를 제공한다.

### V6: 일상 정보 통합 시야
- **유형**: 구체적
- **설명**: 일정·메일·날씨·자주 읽는 문장·아이폰 알림을 **하나의 위젯 1개**에서 한 번에 본다. 정보를 보기 위해 여러 앱을 열지 않는다.

### V7: 시스템 전역 글쓰기 보조
- **유형**: 추상적
- **설명**: 메시지·메일·메모 등 어떤 앱의 텍스트 입력 창에서도 LLM 기반 편집을 즉시 사용할 수 있다. 앱을 전환하거나 텍스트를 복사·붙여넣기할 필요가 없다.

### V8: 일상 루틴의 구조화
- **유형**: 추상적
- **설명**: 사용자의 반복적인 일상 흐름(아침/저녁 루틴, 주간 루틴 등)을 구조화하여 가시화·관리한다.

### V9: 개발 워크플로우 인지 부하 감소
- **유형**: 추상적
- **설명**: 사용자가 개발 업무 중 겪는 마찰과 인지 부하를 줄인다. 작업 중 컨텍스트 스위칭을 최소화하기 위해, 별도로 GitHub 웹/데스크톱을 열거나 CI 결과를 직접 확인하러 가지 않아도 진행 중인 작업의 상태(PR·CI)를 한 화면에서 파악하고, 상태 변화는 시스템 푸시로 받아본다.
- **비고**: 원안 표현 "개발 경험 및 인지 부하를 줄인다"는 문자 그대로 읽으면 "개발 경험을 줄인다"가 되어 의도와 어긋난다. 의도(개발 경험에서 발생하는 마찰을 줄인다)에 맞게 위와 같이 재서술함. 의도와 다르면 수정 필요.

### V10: 자동화에 대한 즉시 승인 통제
- **유형**: 구체적
- **설명**: CI·배포 파이프라인·에이전트 같은 자동화가 사람의 판단을 기다릴 때, 사용자는 자리에 없어도 폰에서 요청 내용을 확인하고 승인·거절을 결정한다. 자동화는 사람의 결정 때문에 불필요하게 멈춰 있지 않고, 사람은 위험한 동작에 대한 최종 통제권을 잃지 않는다. 기한 안에 결정되지 않은 요청은 명시적으로 만료되어, 침묵이 승인으로 해석되는 일이 없다.
- **측정 기준**:
  - 승인 요청 푸시 수신부터 결정 완료까지 목록 탐색·검색 0회 (알림에서 곧바로 결정 지점에 도달).
  - 사용자가 명시적으로 승인하지 않은(또는 사용자가 켜 둔 자동 승인 모드가 아닌) 요청이 승인 상태로 바뀌는 경로 0개. 만료된 요청은 어떤 경로로도 승인되지 않는다.
- **비고**: V9(개발 워크플로우 인지 부하 감소)와 같은 개발·자동화 도메인이지만 축이 다르다. V9는 상태를 *파악*하는 부담을 줄이는 가치이고, V10은 자동화에 대해 *결정*을 내리는 가치다. 잘못 파악하면 다시 보면 되지만 잘못 승인하면 되돌릴 수 없으므로(예: 프로덕션 배포), 통제·안전 관련 AC를 V9의 편의 기준과 섞지 않기 위해 분리한다. 출처: gatekeeper 레포의 pocket-aide 통합 (PRD-12).

## 가치 간 관계

- **V1, V2, V5**는 음성 인터페이스 핵심 가치 — 서로 보완 관계.
- **V3, V8**은 작업/일상 구조 가치 — 서로 독립.
- **V4, V6**은 노출/시야 가치 — 위젯에서 교차.
- **V7**은 시스템 통합 가치이자 V5의 정신을 시스템 입력창으로 확장 — 키보드 확장에서 V5와 보완 관계.
- **V9**는 다른 가치와 독립된 신규 도메인(개발 워크플로우). V3(영역 분리된 작업 관리)와는 "업무 컨텍스트의 분리" 측면에서 약하게 인접 — 회사/개인 작업 분리와 개발/비개발 작업 분리는 다른 축이지만 컨텍스트 관리라는 정신을 공유.
- **V10**은 V9와 같은 개발·자동화 도메인에서 "관찰"이 아닌 "결정·통제" 축을 담당한다. V9와는 푸시 인프라(APNs)와 알림 → 앱 진입 흐름을 공유하는 보완 관계이며, 안전 기준이 충돌하면 V10을 우선한다(편의를 위해 통제를 약화하지 않는다).
