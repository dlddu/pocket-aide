## 1. 서비스 개요 (참고)

PocketAide 제품 개요와 가치는 [`../product/values.md`](../product/values.md)를 따른다. 이 여정은 **이미 구현된 동작**을 다룬다 — 작성 시점(`main` `01bc08f`) 기준으로 임시 공간의 텍스트 메모 추가·메타 줄·분류 이동(PRD-4 #64)과 개인·회사 투두의 분리·CRUD·임시 공간으로부터의 분류(PRD-3)가 착지해 있다. 화면 문구와 동작은 `ScratchpadView`·`ScratchpadViewModel`·`TodoListView`·`TodoEditSheet`와 서버 `POST /api/scratchpad`·`POST /api/scratchpad/{id}/move`·`PATCH /api/todos/{area}/{id}`에서 가져왔다. 구현 전인 것은 표시한다: 위젯의 미분류 개수(PRD-8 AC9), 숏컷 음성 캡처(PRD-6), 승인 탭 도입에 따른 탭 바 재구성(PRD-12).

탭 위치에 관한 사실: 현재 앱 탭은 일곱 개라 iOS가 앞 네 개(다짐 · PR 모니터 · 채팅 · 임시공간)만 탭 바에 두고 개인·회사·루틴은 「더 보기」 안에 넣는다. PRD-12 재구성(`tokens.md` §7 — 다짐 · PR 모니터 · 승인 · 채팅 · 더 보기) 뒤에는 임시 공간도 「더 보기」로 들어간다.

다루지 않는 것: 운전 중 숏컷 음성 캡처(`JRN-voice-capture-while-driving`의 몫 — 그 여정은 분류로 넘기는 지점까지만 보고, 분류 정리 자체는 이 여정이 맡는다), 다짐 우선순위 시트의 세부(`JRN-affirmation-daily-exposure`), 루틴 단계 편집(`JRN-morning-routine-start`), 회사 투두를 실제로 처리·완료하는 일.

## 2. 여정 정의

**대상 사용자 (페르소나)**
사용자 본인. 하루에 회사 미팅이 몇 개씩 있고(가정), 미팅마다 자기 몫의 액션 아이템이 두세 개씩 떨어진다. 미팅 중에는 노트북이 화면 공유에 쓰이거나 닫혀 있어 폰으로 적는 일이 많다(가정). 미팅 도중 회사 일과 무관한 개인 일(「치과 예약」, 「택배 반품」)이 떠오르기도 한다. 개인 일과 회사 일을 한 목록에 섞어 두면 퇴근 뒤에도 회사 일이 눈에 밟혀, 둘을 나눠 두고 싶어 한다(V3).

**진입 맥락**
회사 회의실에서 미팅이 막 끝났다. 폰에 PocketAide가 로그인된 상태로 설치되어 있다. 다음 미팅이나 자리로 이동하기까지 몇 분 정도 여유가 있다. 임시 공간에는 이전에 던져 둔 미분류 메모가 몇 개 남아 있을 수 있다.

**트리거**
미팅에서 자기 이름이 붙은 할 일이 몇 개 정해졌다 — "자리 가기 전에 적어 두지 않으면 하나는 잊는다." 미팅 중 떠오른 개인 일 하나도 같이 남기고 싶다.

**사용자 목표**
미팅에서 받은 할 일을 잊기 전에 빠르게 남기고, 정리할 여유가 생겼을 때 회사 일은 회사 목록으로, 개인 일은 개인 목록으로 나눠 둔다. 정리가 끝나면 임시 공간에 남은 것이 없어 더 신경 쓰지 않아도 된다.

**완료 기준**
미팅 직후 임시 공간에 추가한 메모가 전부 분류 이동(`POST /api/scratchpad/{id}/move` 성공) 또는 삭제(`DELETE /api/scratchpad/{id}` 성공)로 임시 공간을 떠나 미분류 개수에서 빠진다. 회사 투두로 옮긴 항목 가운데 기한이 있는 것은 회사 탭 편집 시트에서 마감일이 저장된다(`PATCH /api/todos/work/{id}` 성공). 기한 없는 일만 있었다면 앞의 조건만으로 완료로 본다.

## 3. 단계별 상세

> 단계 식별자는 순번이 아닌 슬러그를 쓴다. 순서가 바뀌어도 식별자는 유지한다.

### `STP-jot-action-items` 미팅이 끝나자마자 할 일을 던져두기

- **사용자 행동**: 앱을 열어 임시 공간 탭의 「새 메모」를 누르고, 미팅에서 받은 할 일을 하나씩 적어 저장한다(「Q4 로드맵 초안 금요일까지 공유」, 「윤정한테 retention 데이터 요청」). 미팅 중 떠오른 개인 일(「치과 예약 잡기」)도 같은 방식으로 적는다. 저장할 때 어디로 보낼지는 고르지 않는다.
- **터치포인트**: 임시 공간 탭(현재 탭 바 네 번째 자리), 「새 메모」 버튼, 메모 입력 시트(빈 입력이면 「저장」 비활성), 「오늘」 섹션 맨 위에 쌓이는 메모 카드(메타 줄 「탭 내 입력 · HH:mm」)
- **생각·감정**: "일단 다 적어 두고, 정리는 이따가." / "회사 거랑 개인 거랑 섞였는데… 지금은 상관없지."
- **페인포인트 / 이탈 위험**: 할 일 세 개를 한 메모에 몰아 적기 쉽다 — 분류하면 메모 전체가 투두 제목 하나가 되어(`prd-todo.md` 결정 사항) 회사 목록에서 따로 완료할 수 없다 → 입력 시트 안내 문구로 「한 줄에 하나」를 권하고(가정 — PRD 미정의), 메모 쪼개기를 PRD-4 후속 후보로 둔다. 메모마다 「새 메모」 → 입력 → 「저장」을 반복해야 해 네다섯 개면 번거롭다 → 저장 후 시트를 닫지 않고 다음 메모를 이어 쓰는 연속 입력을 후보로 둔다(가정). 저장 요청이 실패하면 시트가 먼저 닫혀 적은 글이 사라진다(`ScratchpadView`가 `onSave`에서 시트를 닫은 뒤 서버에 보낸다) → 실패 시 입력을 되살리거나 기기에 보관한다(가정)(PRD-4 AC2, AC3).

### `STP-scan-unclassified` 정리할 여유가 생겼을 때 쌓인 메모를 훑어보기

- **사용자 행동**: 자리에 돌아오거나 다음 미팅 전 빈 시간에 임시 공간을 다시 열어, 머리의 「분류되지 않은 메모」 개수와 날짜 섹션을 보며 방금 미팅 메모와 그 전부터 남아 있던 메모를 구분한다.
- **터치포인트**: 탭 바 임시 공간 배지(PRD-12 재구성 뒤에는 「더 보기」 목록의 임시 공간 항목 배지), 탭 머리 개수, 「오늘」·「어제」·날짜 섹션과 「N ITEMS」, 메모 카드 메타 줄의 캡처 시각. 위젯의 「임시 공간 · 미분류 n개」(PRD-8 AC9, 구현 전)
- **생각·감정**: "7개? 미팅에서 다섯 개 적었고 두 개는 어제 거네."
- **페인포인트 / 이탈 위험**: 미팅이 연달아 있으면 정리할 틈 없이 메모만 쌓이고, 앱을 다시 열 계기가 없으면 그대로 묻힌다 → 위젯의 미분류 개수(PRD-8 AC9)가 앱 밖에서 알린다 — 구현 전이므로 그 전까지는 탭 바 배지가 유일한 신호다. PRD-12 재구성 뒤에는 임시 공간이 「더 보기」 안으로 들어가 배지가 탭 바에서 보이지 않는다 → 위젯 AC9를 PRD-12 탭 재구성보다 먼저 또는 함께 구현한다(가정 — 순서 미정). 어느 미팅에서 나온 메모인지는 캡처 시각으로만 짐작한다 → 미팅 이름 태그는 「캡처 시 분류하지 않는다」(PRD-4 핵심 철학)와 부딪히므로 두지 않고 시각 표시로 충분한지 사용 중 확인한다(가정)(PRD-4 AC3, AC5).

### `STP-sort-by-area` 메모마다 영역을 골라 옮기기

- **사용자 행동**: 메모 카드를 위에서부터 읽으며 카드 아래 칩을 하나씩 누른다 — 미팅 할 일은 「→ 회사」, 개인 일은 「→ 개인」. 가끔 미팅에서 들은 좋은 말은 「→ 다짐」, 반복되는 준비 작업은 「→ 루틴」으로 보낸다. 적어 놓고 보니 필요 없는 메모는 왼쪽으로 밀어 「삭제」한다.
- **터치포인트**: 메모 카드의 이동 칩 네 개(「→ 개인」 「→ 회사」 「→ 다짐」 「→ 루틴」 — 대상 영역 강조색 테두리), 스와이프 「삭제」, 이동 직후 카드가 목록에서 빠지고 머리 개수·탭 배지가 줄어드는 반응
- **생각·감정**: "이건 회사, 이건 내 거." — 한 장씩 처리할 때마다 머릿속이 비워지는 느낌. 잘못 누르면 "어, 개인으로 갔네?"
- **페인포인트 / 이탈 위험**: 칩 네 개가 한 줄에 작게 붙어 있고 누르는 즉시 이동한다 — 「→ 개인」과 「→ 회사」를 잘못 누르면 되돌리기가 없고, 투두는 영역 간 이동도 의도적으로 막혀 있다(PRD-3 AC4) → 이동 직후 몇 초간 「되돌리기」를 제공하는 것을 PRD-4 후속 후보로 둔다(가정 — 토스트 컴포넌트는 디자인 시스템에 아직 없다). 그 전까지 복구 경로는 분기 표 참조. 이동 실패 시 서버 오류 원문(`String(describing:)`)이 목록 위에 그대로 표시되어 무엇이 잘못됐는지 알기 어렵다 → 사용자 문구로 바꾸고 「다시 시도」를 둔다(가정). 회사·개인 판단이 애매한 일(「회사 동료 결혼식 축의금」)은 어디에도 못 넣고 남는다 → 사용자가 정하는 영역이므로 기본값을 두지 않는다(PRD-3 AC5 「명시적으로 분류」)(PRD-4 AC4, AC5 · PRD-3 AC4, AC5).

### `STP-clear-scratchpad` 임시 공간이 비었는지 확인하기

- **사용자 행동**: 마지막 카드를 옮기고 나서 머리 개수가 0이 되고 빈 상태 안내가 뜨는 것을 본다. 남은 메모가 있으면 다음에 다시 보기로 하고 둔다.
- **터치포인트**: 탭 머리 「분류되지 않은 메모」 0, 빈 상태 문구 「분류할 메모가 없습니다. 떠오르는 대로 새 메모에 던져두세요.」, 탭 바 배지 사라짐(PRD-4 AC5)
- **생각·감정**: "깔끔하다. 이제 미팅 일은 회사 목록에만 있다."
- **페인포인트 / 이탈 위험**: 0이 되었다는 것 말고는 방금 옮긴 것들이 어디로 갔는지 요약이 없어, 확인하려면 각 탭을 직접 열어야 한다 → 빈 상태에 「방금 회사 3 · 개인 1로 옮김」 같은 요약을 보이는 것을 후보로 둔다(가정 — PRD 미정의). 애매해서 남긴 메모가 계속 0이 아닌 개수로 남으면 배지가 늘 켜져 있어 신호로서의 힘이 약해진다 → 오래 남은 메모를 따로 드러낼지는 사용 중 확인한다(가정)(PRD-4 AC5).

### `STP-fill-work-details` 회사 투두에서 마감일과 우선순위를 채우기

- **사용자 행동**: 「더 보기」 → 「회사」로 가서 OPEN 목록에서 방금 옮긴 항목을 찾아 누르고, 「할 일 편집」 시트에서 마감일을 켜 날짜를 고르고 우선순위를 정해 저장한다. 제목이 미팅 중 휘갈긴 문장이면 다듬기도 한다. 개인 쪽 항목도 필요하면 같은 방식으로 채운다.
- **터치포인트**: 「더 보기」 목록의 회사 항목, 회사 탭(머리 「n OPEN · n DONE」, 검색창 「회사 영역만 검색…」, OPEN 섹션), 편집 시트(제목 · 메모 · 마감일 토글과 날짜 · 「우선순위 (선택)」 · 「저장」)
- **생각·감정**: "로드맵 초안은 금요일, 데이터 요청은 오늘." — 할 일이 일정 감각을 갖게 된다.
- **페인포인트 / 이탈 위험**: 임시 공간에서 옮긴 투두는 마감일이 없어서(`prd-todo.md` 결정 사항) 목록 정렬상 마감일 있는 항목들 **아래**에 놓인다(`ORDER BY due_date IS NULL, due_date, created_at DESC`) — 기존 항목이 많으면 방금 옮긴 것을 찾느라 스크롤해야 한다 → 검색창으로 찾거나, 이동 직후 해당 항목을 강조하는 것을 후보로 둔다(가정). 개인·회사 탭이 지금은 「더 보기」 안이라 임시 공간에서 넘어오려면 두 번 더 눌러야 하고, 옮긴 직후 바로 편집하는 경로가 없다 → 다짐 이동처럼 이동 직후 편집 시트를 여는 방식(`ScratchpadView`의 다짐 우선순위 시트)을 투두에도 둘지 검토한다(가정 — 「캡처 시점에는 분류하지 않는다」는 캡처 단계의 원칙이라 분류 단계에서 시트를 여는 것과 충돌하지 않는다). 세부를 채우지 않고 넘어가도 문제는 없다 — 마감이 필요 없는 일도 있다(PRD-3 AC2, AC3).

## 4. 분기·예외 흐름

| 상황 | 처리 | 이어지는 단계 |
|---|---|---|
| 중도 이탈 — 메모만 적고 바로 다음 미팅으로 감 | 메모는 서버에 저장되어 임시 공간에 남는다. 탭 바 배지(재구성 뒤에는 「더 보기」 배지)와 위젯 미분류 개수(PRD-8 AC9, 구현 전)가 정리할 것이 있음을 알린다 | `STP-scan-unclassified` |
| 중도 이탈 — 분류 도중 다른 일로 앱을 떠남 | 이미 옮긴 메모는 대상 영역에 있고 나머지는 임시 공간에 그대로 남는다(이동은 메모 단위). 다시 열면 남은 것부터 이어서 옮긴다 | `STP-sort-by-area` |
| 실패 케이스 — 「새 메모」 저장 실패(네트워크 없음·서버 오류) | 시트는 이미 닫혔고 목록 위에 오류 원문이 뜬다. 적은 글은 사라지므로 다시 적어야 한다(현재 동작). 입력 보존은 후보(가정) | `STP-jot-action-items` |
| 실패 케이스 — 이동 실패 | 서버가 대상 생성과 원본 삭제를 한 트랜잭션으로 처리하므로 둘 다 일어나지 않는다(`prd-todo.md` 결정 사항). 원본 카드가 임시 공간에 남아 있고 목록 위에 오류 원문이 뜬다. 당겨서 새로고침한 뒤 같은 칩을 다시 누른다 | `STP-sort-by-area` |
| 실패 케이스 — 영역을 잘못 골라 옮김(「→ 개인」으로 갈 것을 「→ 회사」로) | 되돌리기와 영역 간 이동이 없다(PRD-3 AC4). 잘못 간 탭에서 항목을 스와이프 삭제하고, 맞는 탭에서 「+」로 같은 제목을 새로 추가한다. 다짐·루틴으로 잘못 간 경우도 그 탭에서 삭제 후 다시 만든다 | `STP-fill-work-details` |
| 실패 케이스 — 한 메모에 할 일 여러 개를 몰아 적음 | 분류하면 메모 전체가 투두 제목 하나가 된다. 분류 전에 할 일마다 「새 메모」로 다시 적고 원본은 삭제하거나, 회사 탭으로 옮긴 뒤 편집 시트에서 제목을 줄이고 나머지를 「+」로 추가한다 | `STP-jot-action-items` |
| 우회 경로 — 미팅실에서 걸어 나오며 음성으로 캡처 | 숏컷 음성 캡처(PRD-6, 구현 전)로 말하면 「숏컷 · 음성」 메모로 임시 공간에 쌓이고, 이후 정리는 같은 흐름을 탄다. 운전 중 캡처는 `JRN-voice-capture-while-driving` 참조 | `STP-scan-unclassified` |
| 우회 경로 — 처음부터 영역이 분명한 할 일 | 임시 공간을 거치지 않고 회사·개인 탭의 「+」로 바로 추가할 수 있다. 이 경우 이 여정을 타지 않는다 | `STP-fill-work-details` |
| 우회 경로 — 할 일이 아닌 메모(결정 사항·들은 말·반복 준비) | 되새길 말은 「→ 다짐」(우선순위 시트가 열린다 — `JRN-affirmation-daily-exposure`), 정기 미팅 준비처럼 반복되는 일은 「→ 루틴」(「매일」·단계 없음으로 생기므로 루틴 탭에서 주기를 바꾼다), 기록용이면 삭제 | `STP-sort-by-area` |
| 외부 지연 — 위젯 미분류 개수 갱신 | 위젯 AC9 구현 전이라 해당 없음. 구현 뒤에는 분류 직후 위젯 숫자가 앱 배지와 바로 같지 않을 수 있다(WidgetKit 갱신 시점 — 가정). 서버 이동 자체는 즉시 반영된다 | 해당 없음 |
