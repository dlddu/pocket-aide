# 사용자 여정: 메시지 작성 중 사용자 — 키보드 확장으로 즉시 편집

## 페르소나

- **이름/역할**: 한·영 혼용 환경에서 메시지·메일을 자주 작성하는 사용자.
- **상황**: iOS의 메일/메시지/메모/Slack 등 임의의 텍스트 입력 화면에서 글을 쓰는 중. 작성한 문장의 어조가 어색하거나, 영어 표현이 필요하거나, 오타가 의심됨.
- **목표**: 작성 중인 텍스트를 다른 앱으로 이동하지 않고 **현재 입력창 안에서** 다듬는다. 복사·붙여넣기·앱 전환 없이 한 흐름으로.

## 달성 가치

- **V7 시스템 전역 글쓰기 보조** — 호스트 앱과 무관하게 동일한 LLM 편집 인터페이스를 입력창 위에 직접 제공. 본 여정 전체가 V7의 단일 구현 경로.
- **V2 한·영 혼용 음성 인식 정확도** — 보조 가치. 키보드 확장의 편집 명령(번역·교정·어조)이 한·영 혼용 텍스트에 대해 정상 작동하는 흐름을 포함하므로 V2의 텍스트 측면 검증을 겸한다.

## 사전 조건

- 본 키보드가 시스템 키보드로 **등록**되어 있고 **Full Access 권한이 부여**되어 있다.
- 미등록/미권한 상태는 본 여정의 진입 자체가 불가하므로 별도 온보딩 여정에서 다룬다 (현재 미정의 — 향후 작성 후보).

## 단계 흐름

### S1: 호스트 앱에서 텍스트 작성 중

- **사용자 행동**: 메일·메시지·메모 등 임의 앱의 입력창에 한·영 혼용 초안을 입력. 작성된 텍스트를 그대로 두거나 일부를 선택한다.
- **시스템 응답**: 시스템 기본 키보드가 표시되어 있는 일반 입력 상태. 본 키보드는 아직 활성화되지 않은 상태.
- **시각화 mockup**: screen-keyboard-extension.html (host: Mail composer 영역)
- **관련 AC**: PRD-9 / AC2 (어떤 앱에서든 호출 가능)

### S2: 키보드 전환 — PocketAide 키보드 활성화

- **사용자 행동**: 키보드 좌하단의 🌐(globe) 버튼을 길게 누르거나 탭하여 PocketAide 키보드로 전환.
- **시스템 응답**: 키보드 영역 상단에 LLM 툴바(편집 명령 칩 그룹 + Full Access 상태 표시 + 자유 지시 입력란)가 나타난다. 표준 QWERTY 영역은 하단 유지.
- **시각화 mockup**: screen-keyboard-extension.html (LLM toolbar 영역)
- **관련 AC**: PRD-9 / AC1, AC2, AC6

### S3: 편집 명령 선택 (어조 / 길이 / 번역 / 교정)

- **사용자 행동**: 툴바의 명령 칩 중 하나를 탭. 예: "정중하게", "짧게", "한→영", "교정". 또는 자유 지시 입력란에 명령 텍스트를 입력.
- **시스템 응답**: 현재 입력창의 텍스트(또는 선택 영역)를 대상으로 LLM 호출 시작. 툴바에 비동기 처리 중 인디케이터 표시.
- **시각화 mockup**: screen-keyboard-extension.html (command chips + async loading state 영역)
- **관련 AC**: PRD-9 / AC3, AC4, AC5

### S4: 응답 대기 — 비동기 UX

- **사용자 행동**: 처리 중에도 표준 키 영역으로 다른 입력을 계속할 수 있다. 필요 시 인터럽트 가능.
- **시스템 응답**: 툴바에 처리 중 상태 유지. 호스트 앱의 입력창은 변경되지 않은 상태로 보존.
- **시각화 mockup**: screen-keyboard-extension.html (async loading state 영역)
- **관련 AC**: PRD-9 / AC8

### S5: 결과 적용 — 입력창 텍스트 대체

- **사용자 행동**: 응답 결과를 확인하고 적용을 수락(또는 취소).
- **시스템 응답**: 호스트 앱 입력창의 대상 텍스트가 LLM 결과로 대체된다. 한·영 혼용이었던 부분은 목적에 맞게 변환된 상태(번역 명령이었다면 영어로, 교정이었다면 같은 언어 분포 유지).
- **시각화 mockup**: screen-keyboard-extension.html (host mail body — 결과 반영 후 상태)
- **관련 AC**: PRD-9 / AC3, AC7

### S6: 호스트 앱 흐름 복귀

- **사용자 행동**: 키보드를 시스템 기본으로 되돌리거나 그대로 둔 채 호스트 앱의 송신/저장 액션을 수행.
- **시스템 응답**: 호스트 앱은 변경된 텍스트를 자기 데이터로 보관/송신. PocketAide 측은 별도 상태를 남기지 않는다(세션 종료).
- **시각화 mockup**: (없음 — 호스트 앱 영역, mockup 범위 밖)

## 가치 달성 평가

- **V7**: S2~S5 한 흐름 전체가 "앱 전환 없이 입력창 위에서 LLM 편집"을 직접 구현. 외부 흐름(복사·붙여넣기·앱 진입·결과 복사·붙여넣기 복귀)이 단일 키보드 전환으로 압축됨. ✅
- **V2**: S5에서 한·영 혼용 텍스트가 명령 의도에 맞게 변환되는지로 검증 가능. PRD-9 / AC7에서 동일 요구를 명시. ✅

## 끊긴 연결 / 미해결

- **사전 조건 온보딩** (키보드 등록 + Full Access 부여)에 대한 별도 여정 미작성. PRD-9 / AC1, AC6는 정의되어 있으나 mockup이 없어 향후 페르소나 추가가 필요하면 별도 여정 후보로 둔다.
- **프라이버시 안내 흐름**: PRD-9 열린 질문(키보드가 입력하는 텍스트의 LLM 전송 투명성). 결정 후 본 여정의 S2 또는 S3 어딘가에 권한/투명성 단계를 삽입해야 할 수 있음 — 현재 미반영.
