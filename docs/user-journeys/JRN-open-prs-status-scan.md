## 1. 서비스 개요 (참고)

PocketAide 제품 개요와 가치는 [`../product/values.md`](../product/values.md)를 따른다. 이 여정은 **이미 구현된 동작**을 다룬다 — 작성 시점(`main` `7f6c2d9`) 기준으로 PRD-10의 「열린 PR」 시트(AC1~AC5·AC9·AC10, #94·#98)가 착지했고 `test-github-monitor.md` 해당 시나리오가 모두 「구현됨」이다. 화면 문구와 동작은 `PRMonitorView`(머리의 열린 PR 버튼)·`OpenPullRequestsSheet`·`OpenPullRequestsViewModel`·`GitHubPullRequests.swift`(검색 갈래·CI 종합 상태·필터·오류 분류)에서 가져왔다.

구조에 관한 사실: 「열린 PR」은 탭이 아니라 PR 모니터 탭 머리의 아이콘 버튼(`arrow.triangle.pull`, 접근성 라벨 「열린 PR」)으로 여는 시트다. GitHub 조회는 서버를 거치지 않는다 — 앱이 기기 키체인에 저장한 Personal Access Token으로 `api.github.com` GraphQL 검색을 직접 부른다(PRD-10 결정 사항). 목록은 검색 `is:pr is:open archived:false`의 세 갈래 — 작성자, 리뷰 요청, 리뷰함(내가 작성하지 않은 PR) — 를 합친 것이고 갈래마다 최대 50개다.

다루지 않는 것: CI 완료 푸시에서 시작해 이력 항목을 「확인」하는 흐름(`JRN-ci-push-to-ack`의 몫 — 이 여정은 사용자가 스스로 목록을 열어 보는 「파악」만 본다), 승인 요청 처리(`JRN-approval-push-to-decision`), GitHub에서 실제로 리뷰를 쓰거나 실패를 고치는 일(V9 「범위 밖」 — 이 여정은 GitHub로 넘기는 지점에서 끝난다), 알림 설정·제외 레포 관리(PRD-10 AC6·AC8).

## 2. 여정 정의

**대상 사용자 (페르소나)**
사용자 본인. 여러 레포에 동시에 PR 몇 개를 열어 두고, 동료 PR의 리뷰어로도 자주 지정된다(가정). CI 결과는 푸시로 받지만, 리뷰 요청이나 「내 PR 중 아직 막혀 있는 것」은 푸시로 오지 않아 직접 확인해야 한다. 이를 확인하려고 노트북을 열어 GitHub의 Pull requests 화면을 띄우는 것이 번거롭다.

**진입 맥락**
스탠드업 직전, 점심 뒤, 미팅 사이처럼 노트북 앞이 아닌 짧은 틈이다(가정 — PRD-10 대표 시나리오 2 「점심시간 폰을 켜고」). PocketAide에 로그인되어 있고, 앱은 백그라운드에 남아 있거나 새로 연다. GitHub 계정은 이미 연결했을 수도, 아직 안 했을 수도 있다.

**트리거**
"오늘 내 PR 중에 막힌 게 있나? 내가 리뷰해 줘야 하는 건?" — 다음 할 일을 정하기 전에 내 PR과 리뷰 상태를 한 번에 알고 싶다.

**사용자 목표**
GitHub를 열지 않고 폰에서, 내가 손대야 할 PR(CI가 실패한 내 PR, 리뷰를 기다리는 남의 PR)이 무엇인지 알아내는 것. 손댈 게 있으면 그 PR로 바로 넘어가고, 없으면 없다는 것을 확신하고 다른 일로 돌아가는 것.

**완료 기준**
「열린 PR」 시트에서 새로고침이 성공해(GitHub 검색 응답 수신) 「마지막 갱신 HH:MM」이 이번 조회 시각으로 표시된 뒤, 다음 중 하나가 일어난다: (a) CI 실패 또는 리뷰어 역할인 PR 행을 눌러 GitHub PR 페이지로 넘어간다, (b) 「CI 실패만」·「리뷰 요청만」 필터가 「조건에 맞는 PR이 없습니다」를 보이거나 목록이 「열려 있는 PR이 없습니다」여서 조치할 것이 없음을 확인한다. 이 이벤트를 앱에서 수집하는 경로는 아직 없다(가정 — 지표 절 참조).

## 3. 단계별 상세

> 단계 식별자는 순번이 아닌 슬러그를 쓴다. 순서가 바뀌어도 식별자는 유지한다.

### `STP-connect-github` 처음 한 번 GitHub 토큰 연결하기

- **사용자 행동**: 「열린 PR」 시트를 처음 열면 연결 안내가 나온다. GitHub 설정에서 Personal Access Token(classic은 `repo` 범위)을 만들어 복사해 와 붙여 넣고 「연결」을 누른다. 확인이 끝나면 `@핸들`이 보이고 바로 목록을 불러온다.
- **터치포인트**: 「열린 PR」 시트의 연결 폼(안내 두 줄, `ghp_…` 입력 칸, 「연결」 → 「확인 중…」), 연결 오류 문구, 연결 후 계정 줄(`@핸들` · 「토큰 바꾸기」 · 「연결 해제」), 폰 브라우저의 GitHub 토큰 생성 화면(앱 밖)
- **생각·감정**: "토큰을 폰에서 만들어야 하네… 범위가 뭐였지?" / 연결되면 "됐다, 이제 안 해도 되지."
- **페인포인트 / 이탈 위험**: 폰에서 GitHub 설정에 들어가 토큰을 만들고 범위를 고르고 긴 문자열을 복사해 오는 과정이 이 여정에서 가장 무겁다 — 여기서 포기하면 열린 PR 기능 전체를 쓰지 않는다 → OAuth 흐름(PRD-10 「후속 작업」)으로 대체하고, 그 전까지는 연결 안내에 토큰 생성 페이지로 가는 링크를 두는 것을 후보로 둔다(가정 — 현재 안내는 문장뿐이다). 조직 레포는 토큰을 만든 뒤 조직 SSO 승인까지 해야 보인다 → 연결 직후 접근 권한 배너(AC9)가 이를 알린다. 토큰은 이 기기 키체인에만 저장되므로 기기를 바꾸거나 앱에서 로그아웃하면 다시 해야 한다(PRD-10 AC1 결정 사항)(PRD-10 AC1, AC9).

### `STP-open-open-prs` PR 모니터에서 「열린 PR」 시트 열기

- **사용자 행동**: PR 모니터 탭으로 가서, 머리 오른쪽 아이콘 세 개 중 PR 모양 아이콘을 눌러 「열린 PR」 시트를 연다.
- **터치포인트**: 하단 탭 바의 「PR 모니터」, 탭 머리 아이콘 버튼(열린 PR · 알림 설정 · 제외 레포 관리 — 미확인 배지 옆), 시트 머리 「열린 PR」·「완료」
- **생각·감정**: "열린 PR은… 이 아이콘이었나?"
- **페인포인트 / 이탈 위험**: 진입이 글자 없는 아이콘 하나뿐이고 옆의 종·필터 아이콘과 나란히 있어, 자주 쓰지 않으면 어디서 여는지 잊는다 → 아이콘 옆 짧은 라벨이나 PR 모니터 화면 안의 「열린 PR n개」 요약 줄을 후보로 둔다(가정). PR 모니터 탭은 열면 먼저 CI 알림 이력을 보여 주므로, 열린 PR을 보러 왔는데 이력의 미확인 카드에 주의가 먼저 간다 — 두 목적(푸시 이력 정리 vs. 열린 PR 파악)이 한 화면 진입을 공유한다(PRD-10 결정 사항 「모니터링 화면 구성」)(PRD-10 AC2).

### `STP-pull-refresh` 당겨서 최신 상태로 새로고침하기

- **사용자 행동**: 목록 위 「마지막 갱신 HH:MM」을 보고, 오래됐으면 목록을 당겨 새로고침한다. 처음 여는 경우에는 스피너가 돌다 목록이 채워진다.
- **터치포인트**: 「마지막 갱신 HH:MM」, 당겨서 새로고침, 첫 로딩 스피너(AC10), 새로고침 실패 시 갱신 시각 아래 오류 문구
- **생각·감정**: "11:02? 아까 본 거네. 다시 받아 보자."
- **페인포인트 / 이탈 위험**: 시트를 다시 열어도 자동으로 새로 조회하지 않는다 — 시트는 앱이 켜진 뒤 첫 진입에서만 불러오고(`OpenPullRequestsSheet`의 `.task`가 `hasLoaded`일 때 건너뜀), 뷰 모델은 PR 모니터 탭이 들고 있어 앱이 백그라운드에 남아 있는 동안 아침에 본 목록이 점심에도 그대로 나온다. 갱신 시각을 놓치면 오래된 CI 상태를 지금 상태로 믿는다 → 시트를 열 때 마지막 갱신이 일정 시간(예: 5분) 넘게 지났으면 자동으로 새로고침하는 것을 PRD-10 AC5 보완 후보로 둔다(가정 — 기준 시간 미정). 레이트 리밋에 걸리면 재설정 시각까지 새로고침이 계속 실패한다(AC9 배너)(PRD-10 AC5, AC9, AC10).

### `STP-scan-statuses` 목록에서 CI 상태와 내 역할 훑어보기

- **사용자 행동**: 갱신 시각 내림차순 목록을 위에서부터 훑으며 카드마다 오른쪽 위 CI 배지(진행 중 · 성공 · 실패 · 상태 없음)와 아래 줄의 「작성자 · 역할 · 상대 시각」을 본다.
- **터치포인트**: PR 카드(레포 이름 · CI 배지 · 「#번호 제목」 · 작성자 · 「작성자」/「리뷰어」 · 「n분 전」), 빈 상태 「열려 있는 PR이 없습니다」(AC10)
- **생각·감정**: "내 거 둘은 성공, 하나는 실패. 리뷰어로 걸린 게 셋이네."
- **페인포인트 / 이탈 위험**: 「리뷰어」 역할에는 리뷰 요청을 받은 PR과 내가 이미 리뷰를 제출한 PR이 함께 들어간다(검색 갈래 「리뷰함」 — 리뷰를 제출하면 요청이 사라져 목록에서 빠지는 것을 막으려는 PRD-10 AC2 결정). 그래서 「아직 해야 할 리뷰」와 「이미 끝낸 리뷰」를 카드만 보고 구별할 수 없다 → 역할 라벨을 「리뷰 요청」/「리뷰함」으로 나누는 것을 후보로 둔다(가정 — 서버를 거치지 않으므로 검색 갈래 정보를 그대로 쓰면 된다). 상대 시각은 PR 갱신 시각이라 CI가 언제 끝났는지는 보이지 않는다. 갈래마다 50개를 넘는 PR은 말없이 잘린다(가정 — 1인 사용에서는 드물 것)(PRD-10 AC2, AC3, AC10).

### `STP-narrow-by-filter` 필터로 손댈 PR만 남기기

- **사용자 행동**: 목록 위 알약 필터에서 「CI 실패만」을 눌러 막힌 PR을, 「리뷰 요청만」을 눌러 리뷰어 PR을 남긴다. 다 봤으면 「전체」로 되돌리거나 그대로 둔다.
- **터치포인트**: 필터 알약 「전체 · 내 PR만 · 리뷰 요청만 · CI 실패만」(하나만 켜짐), 필터 결과 0개 안내 「조건에 맞는 PR이 없습니다」 + 「「X」 필터를 끄면 열린 PR n개를 모두 볼 수 있습니다.」
- **생각·감정**: "실패한 건 하나뿐이네. 다행." / 0개면 "막힌 건 없다."
- **페인포인트 / 이탈 위험**: 필터는 하나만 켜져서 「내 PR 중 CI 실패」처럼 겹친 조건은 볼 수 없다 — 다만 「CI 실패만」은 리뷰어 PR의 실패도 함께 보여 주어, 남의 PR 실패까지 섞인다 → 겹친 조건이 실제로 자주 필요한지 사용 중 확인한다(가정). 「리뷰 요청만」은 이름과 달리 이미 리뷰한 PR도 남긴다(`STP-scan-statuses` 페인포인트와 같은 원인) → 라벨을 「리뷰어」로 바꾸거나 갈래를 나눈다(가정). 마지막 필터는 기기에 저장되어 다음에 열 때도 켜져 있다 — 「CI 실패만」을 켜 둔 채 잊으면 다음에 「PR이 하나뿐인가?」로 오해할 수 있다 → 필터가 켜진 동안 목록 머리에 「전체 n개 중 m개」를 보이는 것을 후보로 둔다(가정)(PRD-10 AC4).

### `STP-hand-off-to-github` 손댈 PR을 눌러 GitHub로 넘어가기

- **사용자 행동**: 손댈 PR 카드를 누른다. 앱이 GitHub PR 페이지를 연다(GitHub 앱이 설치되어 있으면 유니버설 링크로 앱이, 아니면 Safari가 열린다 — 가정). 거기서 실패한 체크를 보거나, 리뷰를 남기거나, 노트북에서 이어 할 일로 기억해 둔다.
- **터치포인트**: PR 카드 탭(`openURL`), GitHub 앱 또는 Safari의 PR 페이지(앱 밖), 「완료」로 시트 닫기
- **생각·감정**: "이 실패만 보고, 리뷰는 자리 가서 하자." — 할 일이 정해져 머릿속이 정리된다.
- **페인포인트 / 이탈 위험**: 카드를 누르면 PR 페이지가 열리고 실패한 워크플로우 실행으로 바로 가지 않는다 — 실패 실행 링크는 PR 모니터 이력의 그룹 카드(AC11)에 있지만, 열린 PR 카드와 이력 그룹 사이에 연결이 없다 → CI 실패 카드에서 같은 PR의 이력 그룹으로 가는 길(또는 실패 실행 링크)을 후보로 둔다(가정). 앱을 떠나면 돌아올 때 시트는 그대로 열려 있지만, 다른 PR을 보려면 다시 PocketAide로 전환해야 한다. 이 단계는 처리 표시를 남기지 않는다 — 열린 PR 목록에는 「확인」 개념이 없고 PR이 닫히거나 머지되어야 목록에서 빠진다(PRD-10 AC2)(PRD-10 AC2, AC3).

## 4. 분기·예외 흐름

| 상황 | 처리 | 이어지는 단계 |
|---|---|---|
| 우회 경로 — 이미 연결된 상태(재방문) | 연결 폼 없이 계정 줄과 목록이 바로 보인다 | `STP-open-open-prs` |
| 실패 케이스 — 토큰 연결 실패(오타·만료·네트워크) | 연결 폼 아래 오류 문구가 뜨고 입력은 남는다. 고쳐서 다시 「연결」 | `STP-connect-github` |
| 실패 케이스 — 토큰 거부(HTTP 401: 만료·폐기) | 시트 맨 위 「GitHub 토큰이 거부되었습니다」 배너 → 「토큰 다시 연결」이 연결 폼을 연다. 새 토큰으로 연결해 새로고침이 성공하면 배너가 사라진다(AC9) | `STP-connect-github` |
| 실패 케이스 — 권한 부족(403·조직 SAML로 가려진 PR) | 「접근 권한이 부족합니다」 배너가 숨긴 PR 개수와 SSO 승인·토큰 범위 확인을 안내 → 「토큰 바꾸기」. 볼 수 있는 PR은 그대로 목록에 남는다(AC9) | `STP-connect-github` |
| 실패 케이스 — 레이트 리밋 | 「GitHub 요청 한도에 도달했습니다」 배너와 재설정 시각 → 「다시 시도」. 재설정 전에는 다시 시도해도 배너가 남는다. 직전 목록이 있으면 그대로 보인다(AC9) | `STP-pull-refresh` |
| 실패 케이스 — 네트워크·서버 오류 | 배너가 아니라 문구로 보인다: 목록이 있으면 「마지막 갱신」 아래 오류 문구와 함께 직전 목록 유지, 목록이 없으면 「열린 PR을 불러오지 못했습니다」. 당겨서 다시 시도 | `STP-pull-refresh` |
| 중도 이탈 — 토큰 만들러 GitHub에 갔다가 돌아오지 않음 | 저장된 것이 없어 다음에 시트를 열면 연결 폼부터 다시 시작한다 | `STP-connect-github` |
| 중도 이탈 — 기기 변경·앱 로그아웃·「연결 해제」 | 토큰이 이 기기 키체인에만 있으므로 연결 안내로 돌아간다(PRD-10 AC1 결정 사항) | `STP-connect-github` |
| 우회 경로 — 열린 PR이 0개 또는 필터 결과 0개 | 「열려 있는 PR이 없습니다」 또는 「조건에 맞는 PR이 없습니다」로 조치할 것이 없음을 확인하고 끝낸다(완료 기준 (b)) | 해당 없음 |
| 우회 경로 — CI 결과를 이미 푸시로 받음 | 결과 확인과 처리 표시는 `JRN-ci-push-to-ack`에서 한다. 이 여정은 리뷰어 PR 파악에만 쓴다 | `STP-narrow-by-filter` |
| 외부 지연 — 방금 연 PR이 목록에 없음 | GitHub 검색 색인 반영이 늦을 수 있다(가정). 잠시 뒤 당겨서 새로고침한다 | `STP-pull-refresh` |
| 외부 지연 — CI 진행 중 | 「진행 중」 배지로 남는다. 끝나면 CI 완료 푸시가 오므로(PRD-10 AC6) 목록을 반복해 새로고침하지 않아도 된다 | 해당 없음 |
