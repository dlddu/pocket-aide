## 1. 서비스 개요 (참고)

PocketAide 제품 개요와 가치는 [`../product/values.md`](../product/values.md)를 따른다. 이 여정은 PRD-6(아이폰 숏컷 음성 모드)이 정한 **목표 동작**을 다룬다. 작성 시점(`main` `d4bedac`)에 PRD-6과 PRD-7은 구현 전이다 — 앱이 등록한 App Shortcut은 인사 문구를 돌려주는 `ShowHelloIntent` 하나뿐이고, 음성 인식 엔진도 채택 전이다. 반면 캡처가 도착할 자리는 이미 있다: 서버 `POST /api/scratchpad`는 입력 방식 `shortcut`과 캡처 시각(`captured_at`)을 받아 저장하고, `ScratchpadView`는 「숏컷 · 음성 · HH:mm」 메타 줄과 숏컷 표시 점을 그린다. 그래서 `STP-find-capture`·`STP-check-transcript`의 화면은 구현 기준이고, 앞의 세 단계는 PRD와 화면 mockup `screen-shortcut-capture`에서 가져와 실제 구현과 다를 수 있다.

다루지 않는 것: 숏컷을 아이폰 단축어 앱에 처음 등록하는 설정(AC1의 준비 작업 — 운전 전에 한 번 한다), 임시 공간 메모를 영역별로 나누는 정리 작업 자체(남은 후보 「회사 미팅 직후 메모 분류」 여정의 몫 — 이 여정은 분류로 넘기는 지점까지만 본다).

## 2. 여정 정의

**대상 사용자 (페르소나)**
사용자 본인. 출퇴근길에 운전하는 동안 할 일·아이디어가 자주 떠오르지만 손과 눈을 쓸 수 없어 대부분 도착 전에 잊는다(가정). 폰은 차량 거치대에 있거나 CarPlay에 연결되어 있다(가정). 말할 때 한국어 문장에 영어 기술 용어·고유명사가 자연스럽게 섞인다(「retention 데이터 fact-check 한 번 더 돌리기」).

**진입 맥락**
PocketAide 음성 캡처를 단축어에 등록해 둔 상태(Siri 문구, 사이드 버튼·동작 버튼 연결)로 운전 중이다. 폰은 잠겨 있고 앱은 종료되어 있다. 로그인은 되어 있다.

**트리거**
운전 중 떠오른 생각 하나 — "아, 윤정한테 메일 보내야 하는데. 이거 내리면 까먹겠다."

**사용자 목표**
도로에서 눈과 손을 떼지 않고, 떠오른 말을 그대로 한 번만 말해 어딘가에 확실히 남기는 것. 나중에 다시 말하거나 고쳐 쓸 필요 없이 그 메모를 바로 쓸 수 있는 것.

**완료 기준**
운전 중 호출한 캡처가 호출부터 저장까지 사용자의 추가 입력 0회(V1 측정 기준)로 임시 공간에 `source: shortcut` 메모로 저장되고(`POST /api/scratchpad` 성공), 도착 뒤 사용자가 그 메모를 다시 말하거나 지우고 새로 쓰지 않은 채 분류 이동한다(`POST /api/scratchpad/{id}/move` 성공, PRD-4 AC4).

## 3. 단계별 상세

> 단계 식별자는 순번이 아닌 슬러그를 쓴다. 순서가 바뀌어도 식별자는 유지한다.

### `STP-invoke-hands-free` 손 대지 않고 캡처 호출하기

- **사용자 행동**: 운전하면서 「Siri야, 포켓에이드에 메모」처럼 등록한 문구로 음성 캡처를 부른다. 신호 대기 중이라면 사이드 버튼·동작 버튼으로 부르기도 한다.
- **터치포인트**: Siri(폰 또는 CarPlay), 아이폰 단축어 액션(PRD-6 AC1), 사이드 버튼·동작 버튼
- **생각·감정**: "까먹기 전에 빨리." / "제대로 알아들었나?"
- **페인포인트 / 이탈 위험**: Siri가 영어 앱 이름 「PocketAide」를 한국어 문장 안에서 못 알아들으면 엉뚱한 응답이 나오고, 운전 중에 다시 말하다 포기하기 쉽다 → App Shortcut 문구에 한국어로 부르기 쉬운 문구를 함께 등록하고, 사용자가 단축어 이름을 직접 바꿔 부를 수 있음을 안내한다(가정 — PRD 미정의). 운전 중 버튼 호출은 손을 쓰게 하므로 기본 진입점은 음성 호출로 둔다. 앱을 열지 않고 백그라운드에서 녹음하려면 iOS가 허용하는 방식(오디오 녹음 인텐트와 라이브 액티비티 등)이 필요하다 → 구현 방식은 PRD-6 구현 시 확정한다(가정)(PRD-6 AC1).

### `STP-speak-thought` 떠오른 생각을 그대로 말하기

- **사용자 행동**: 녹음이 시작되었다는 신호를 듣고, 떠오른 내용을 한·영이 섞인 평소 말투 그대로 말한다(「윤정한테 다음 주 화요일 미팅 가능한지 메일 보내고, retention 데이터 fact-check 한 번 더 돌리기」).
- **터치포인트**: 잠금 화면 녹음 오버레이(「녹음 중 · 임시공간으로 자동 저장」, 경과 시간, 실시간 인식 문구 — `screen-shortcut-capture`), 녹음 시작 음향·햅틱(가정)
- **생각·감정**: "말만 하면 되네." / "fact-check 같은 건 알아들으려나."
- **페인포인트 / 이탈 위험**: 운전 중에는 화면을 볼 수 없어 「녹음 중」 표시와 실시간 인식 문구가 전달되지 않는다 — 녹음이 시작됐는지 몰라 말을 머뭇거리면 앞부분이 잘린다 → 호출 즉시(목표 1초 이내) 녹음을 시작하고 시작을 소리·햅틱으로 알린다(신호 방식은 가정 — PRD 미정의). 차량 소음·내비게이션 음성이 섞이면 인식이 흔들린다 → STT 모델 평가에 차량 환경 발화를 포함한다(가정)(PRD-6 AC2, AC5 · PRD-7 AC1, AC3).

### `STP-finish-unasked` 묻는 것 없이 끝내고 운전으로 돌아가기

- **사용자 행동**: 말을 마치고 잠깐 멈춘다. 침묵이 감지되면(mockup 기준 2초) 캡처가 끝나고, 사용자는 아무것도 고르지 않은 채 운전을 이어 간다.
- **터치포인트**: 침묵 감지 자동 종료, 사이드 버튼 종료, 오버레이의 「저장 후 종료」·「취소」(`screen-shortcut-capture`), 저장 완료 음향·햅틱(가정)
- **생각·감정**: "됐다, 이제 잊어도 된다." — 머릿속에서 그 일을 내려놓는다.
- **페인포인트 / 이탈 위험**: 저장됐는지 확인할 수단이 화면뿐이면 운전 중에는 "저장된 건가?" 하는 불안이 남아 머릿속에서 내려놓지 못한다 → 저장 완료를 짧은 소리로 알린다(가정 — PRD 미정의). 생각을 정리하느라 2초 넘게 멈추면 말 도중에 끝나 버린다 → 침묵 기준을 실제 운전 중 발화로 조정한다(PRD-6 AC3 「예: 침묵 감지」 — 기준값 미정). 종료 뒤 결과가 3초 넘게 걸리면 즉시 캡처로 느껴지지 않는다(PRD-7 AC5). 이 단계에서 분류·태그·확인 질문은 없다(PRD-6 AC3, AC4 · PRD-4 AC1).

### `STP-find-capture` 도착 후 임시 공간에서 캡처 찾기

- **사용자 행동**: 차를 세운 뒤(또는 그날 저녁) 앱을 열어 임시 공간으로 가서, 「오늘」 섹션 맨 위의 방금 캡처한 메모를 찾는다.
- **터치포인트**: 임시 공간 탭 — 미분류 배지(PRD-12 탭 재구성 뒤에는 「더 보기」 목록의 임시 공간 항목), 머리의 「분류되지 않은 메모」 개수, 「오늘」 섹션, 메모 카드의 숏컷 표시 점과 메타 줄 「숏컷 · 음성 · HH:mm」. 위젯의 「임시 공간 · 미분류 n개」(PRD-8 AC9, 구현 전)
- **생각·감정**: "아까 운전하면서 말한 거 어디 있지… 여기 있네."
- **페인포인트 / 이탈 위험**: 캡처했다는 사실을 잊으면 임시 공간을 열지 않아 메모가 그대로 묻힌다 → 위젯의 미분류 개수(PRD-8 AC9)로 앱 밖에서 먼저 보이게 한다. PRD-12 탭 재구성 뒤에는 임시 공간이 「더 보기」 안으로 들어가 진입이 두 번 걸린다 → 「더 보기」 목록의 배지(PRD-4 AC5)와 위젯 개수가 대신 알린다. 메타 줄은 캡처 시각을 보여 주므로, 운전 중 여러 개를 남겼어도 시각으로 구분할 수 있다(PRD-4 AC3, AC5).

### `STP-check-transcript` 인식 결과를 확인하고 분류로 넘기기

- **사용자 행동**: 메모 본문을 읽어 말한 내용이 그대로 옮겨졌는지 — 특히 영어 단어와 이름 — 확인하고, 카드의 이동 칩(「→ 개인」·「→ 회사」·「→ 다짐」·「→ 루틴」) 하나를 눌러 분류로 넘긴다.
- **터치포인트**: 메모 카드 본문, 이동 칩, 이동 뒤 대상 영역(투두·다짐·루틴)
- **생각·감정**: "fact-check까지 정확히 들어갔네. 회사 일로 보내자." / 틀렸다면 "아, 이거 다시 적어야 하나?"
- **페인포인트 / 이탈 위험**: 인식이 틀린 경우 임시 공간에는 본문 편집 수단이 없다 — 스와이프 삭제 후 「새 메모」로 다시 쓰거나, 먼저 투두로 옮긴 뒤 투두 편집 시트에서 고쳐야 한다(`ScratchpadView` 기준) → 임시 공간 본문 편집을 PRD-4 후속 후보로 두고, 반복해서 틀리는 단어는 사용자 단어장(PRD-7 AC3)에 더한다. 원본 음성을 다시 들어 볼 수 없어 무엇을 말했는지 기억에 의존한다 → PRD-6 AC4의 「원본 음성 메타데이터」 범위(음성 파일 보관 여부)를 구현 전에 정한다 — 현재 `scratchpad_items` 테이블에는 음성 관련 칼럼이 없다(PRD-6 AC4 · PRD-4 AC4 · PRD-7 AC3).

| 실패 케이스 — Siri가 호출 문구를 못 알아들음 | Siri의 일반 응답이 나오고 캡처는 시작되지 않는다. 문구를 다시 말하거나, 신호 대기 중 버튼으로 부른다 | `STP-invoke-hands-free` |
| 실패 케이스 — 저장 시점 네트워크 없음(터널·지하 주차장) | 처리 방식 PRD 미정의. 기기에 보관했다가 연결되면 `captured_at`을 캡처 시각으로 보내 저장하는 것을 제안한다(가정) — 그래야 메모가 캡처 순서대로 「오늘」 섹션에 놓인다 | `STP-find-capture` |
| 실패 케이스 — 로그인 만료 | 처리 방식 PRD 미정의. 캡처를 기기에 보관하고, 다음 앱 실행에서 로그인한 뒤 올리는 것을 제안한다(가정) | `STP-find-capture` |
| 실패 케이스 — 인식 결과가 틀림 | 임시 공간에서 본문을 고칠 수 없다. 삭제 후 「새 메모」로 다시 쓰거나, 투두로 옮긴 뒤 편집 시트에서 고친다 | `STP-check-transcript` |
| 중도 이탈 — 말을 잘못 시작함 | 손을 쓸 수 있으면 오버레이의 「취소」로 버린다. 운전 중이면 그대로 저장되게 두고 도착 뒤 스와이프로 지운다 | `STP-check-transcript` |
| 중도 이탈 — 생각하다 침묵 기준을 넘겨 말 도중에 끝남 | 앞부분은 메모 하나로 저장된다. 다시 호출해 나머지를 말하면 메모 두 개로 나뉘어 쌓인다(분류 때 각각 처리) | `STP-invoke-hands-free` |
| 우회 경로 — 차를 세운 상태 | 숏컷 대신 앱을 열어 임시 공간 「새 메모」에서 텍스트로 쓴다(PRD-4 AC2). 탭 내 음성 입력은 구현 전 | `STP-find-capture` |
| 외부 지연 — 인식 결과가 늦게 옴 | 종료 뒤 결과까지 3초 미만이 목표(PRD-7 AC5). 넘으면 저장 완료 신호를 결과 대기와 분리해 먼저 줄지 구현 시 결정한다(가정) | `STP-finish-unasked` |
