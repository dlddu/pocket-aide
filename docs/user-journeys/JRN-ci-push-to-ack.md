## 1. 서비스 개요 (참고)

PocketAide 제품 개요와 가치는 [`../product/values.md`](../product/values.md)를 따른다. 이 여정은 PR 모니터 탭(RootView 7번째 탭)과 GitHub Actions `workflow_run` 푸시(PRD-10)의 **현재 구현 범위**(AC6·AC7·AC11~AC15)를 다룬다. 열린 PR 목록(AC2~AC5)·알림 설정(AC8)·오류 배너(AC9)는 아직 구현 전이라 다루지 않는다.

## 2. 여정 정의

**대상 사용자 (페르소나)**
사용자 본인. 여러 레포에 PR을 올리고 GitHub Actions 결과를 기다리는 개발자. PR을 올린 뒤에는 슬랙·다른 작업으로 돌아가며, "CI 통과했나?"를 확인하려고 GitHub 탭을 다시 여는 일이 잦다.

**진입 맥락**
PR을 열었거나 브랜치에 푸시해서, 제외하지 않은 레포에서 워크플로우가 실행되기 시작했다. 폰은 주머니나 책상 위에 잠겨 있다.

**트리거**
잠금 화면에 도착한 CI 결과 푸시("CI 실패 — pocket-aide #42").

**사용자 목표**
GitHub를 들여다보지 않고도 CI 결과를 알고, 손봐야 할 것만 골라 처리한 뒤 "처리했다"는 표시를 남겨 다시 신경 쓰지 않는 것.

**완료 기준**
푸시로 알게 된 이력 항목에 사용자가 "확인" 버튼을 눌러 `acknowledged_at`이 기록되고, 미확인 배지가 그만큼 줄어든다.

## 3. 단계별 상세

> 단계 식별자는 순번이 아닌 슬러그를 쓴다. 순서가 바뀌어도 식별자는 유지한다.

### `STP-push-glance` 잠금 화면에서 CI 결과 보기

- **사용자 행동**: 잠금 화면에 도착한 푸시를 보고 결과(통과/실패)와 대상 PR을 파악한다.
- **터치포인트**: iOS 잠금 화면 알림 (APNs 푸시)
- **생각·감정**: "실패네. #42구나." / 통과면 "됐다" 하고 하던 일로 돌아간다.
- **페인포인트 / 이탈 위험**: 알림 제목만으로 어느 PR·워크플로우인지 모르면 결국 GitHub를 연다 → 제목에 결과·레포·PR 번호, 본문에 PR 제목과 워크플로우를 담는다. PR 없는 실행은 `repo — conclusion · workflow`로 표시한다(PRD-10 AC6).

### `STP-open-from-push` 푸시를 눌러 해당 항목으로 들어가기

- **사용자 행동**: 실패 푸시를 탭해 앱을 연다. PR 모니터 탭에서 그 이벤트가 속한 그룹 카드가 강조된 채로 보인다.
- **터치포인트**: PR 모니터 탭 — 이력 목록(그룹 카드, 푸시 진입 강조)
- **생각·감정**: "같은 PR에서 다른 워크플로우는 통과했네." — 그룹 헤더의 종합 상태로 한눈에 파악.
- **페인포인트 / 이탈 위험**: 목록 맨 위가 아니라 엉뚱한 곳이 열리면 다시 찾아야 한다 → deep link `pocketaide://pr-monitor?eventId=<id>`로 해당 항목을 강조(5초 후 자동 해제). 푸시 탭만으로는 확인 처리되지 않는다(PRD-10 AC7, AC13).

### `STP-check-details` 링크로 실패 원인 보기

- **사용자 행동**: 항목의 `↗ 런`(또는 `↗ PR`, `↗ 커밋`) 링크를 눌러 GitHub에서 실패한 스텝을 확인하고 앱으로 돌아온다.
- **터치포인트**: 앱 내 브라우저 → GitHub Actions 실행 페이지
- **생각·감정**: "xcodebuild에서 터졌구나. 이건 자리에 가서 고치자."
- **페인포인트 / 이탈 위험**: 링크를 열었다는 이유로 항목이 사라지면 나중에 할 일이 묻힌다 → 외부 링크 탭은 확인 처리하지 않는다. 돌아와도 미확인으로 남는다(PRD-10 AC11, AC12).

### `STP-ack-item` 확인 버튼으로 처리하기

- **사용자 행동**: 처리할 계획이 선 항목의 "확인" 버튼을 누른다.
- **터치포인트**: PR 모니터 탭 — 이력 행의 "확인" 버튼, 상단 미확인 배지, 그룹 헤더 미확인 수
- **생각·감정**: "이건 봤다. 다음." — 배지 숫자가 줄어드는 것으로 정리된 느낌.
- **페인포인트 / 이탈 위험**: 한 PR에 이벤트가 여러 건 쌓이면 하나씩 누르기 번거롭다 → 그룹 헤더의 "모두 확인"으로 일괄 처리할 수 있다(PRD-10 AC15). 확인한 항목은 dim·취소선으로 내려가고 확인 시각이 남는다(PRD-10 AC11, AC12).

## 4. 분기·예외 흐름

| 상황 | 처리 | 이어지는 단계 |
|---|---|---|
| 우회 경로 — 통과 결과라 원인 확인이 필요 없음 | 링크를 열지 않고 바로 "확인" | `STP-ack-item` |
| 우회 경로 — 같은 PR의 이벤트를 한 번에 처리 | 그룹 헤더 "모두 확인"으로 그룹 내 미확인 항목 일괄 확인 (PRD-10 AC15) | `STP-ack-item` |
| 중도 이탈 — 푸시를 놓치거나 무시함 (APNs 발송 실패 포함) | 이력은 푸시보다 먼저 저장되므로, 나중에 PR 모니터 탭을 직접 열면 미확인 그룹이 맨 위에 있다 | `STP-open-from-push` |
| 실패 케이스 — 링크를 열고 돌아옴 | 링크 탭은 확인이 아니므로 항목은 미확인 그대로. 이어서 확인 버튼으로 처리 | `STP-ack-item` |
| 변형 — PR 없는 실행 (main 직접 푸시 등) | 푸시 제목 fallback, 이력은 커밋(`head_sha`) 단위 그룹 | `STP-open-from-push` |
| 외부 지연 — CI가 아직 실행 중 | "CI 시작" 푸시가 먼저 오고(PRD-10 AC14), 완료 푸시는 실행이 끝나야 온다. 이력 저장 실패 시 약 30초 뒤 재시도 | 해당 없음 |
| 이탈 — 제외한 레포의 실행 | 푸시·이력 모두 만들어지지 않는다 | 해당 없음 (여정 밖 종료) |
