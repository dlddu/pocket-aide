## 1. 서비스 개요 (참고)

PocketAide 제품 개요와 가치는 [`../product/values.md`](../product/values.md)를 따른다. 이 여정은 PRD-12(승인 게이트, gatekeeper 통합)가 정한 **목표 동작**을 다룬다. PRD-12는 작성 시점(2026-10-05)에 구현 전이므로, 화면·문구는 PRD와 결정 사항에서 가져왔고 실제 구현과 다를 수 있다.

다루지 않는 것: 호출자 키 발급·폐기(AC13·AC14 — 승인 요청을 받기 전에 한 번 하는 설정), 자동 응답 모드 설정(AC9), 처리 이력 훑어보기(AC8). 이 여정은 요청 하나가 도착해서 결정될 때까지만 본다.

## 2. 여정 정의

**대상 사용자 (페르소나)**
사용자 본인. 클러스터 작업을 Claude Code 세션과 k3s MCP 같은 에이전트에 맡기고, 되돌리기 어려운 작업(리소스 생성·삭제, 배포)은 실행 전에 사람의 승인을 받도록 걸어 둔 개발자. 지금 승인을 요청하는 호출자는 homelab-k3s-mcp(쓰기 도구 승인 게이트), session-platform agent, pure-agent 세 곳이다. 에이전트에 일을 맡긴 뒤에는 자리를 뜨거나 다른 일을 하는 경우가 많다.

**진입 맥락**
에이전트나 CI에 작업을 맡겨 두었고, 그 작업이 승인 게이트가 걸린 동작에 도달했다. 자동 응답 모드는 `없음`이다. 폰은 주머니나 책상 위에 잠겨 있다.

**트리거**
잠금 화면에 도착한 승인 요청 푸시(「승인 요청 · k3s-mcp」 / 「deployment/dear-baby-api 삭제 (namespace: prod) …」).

**사용자 목표**
자리로 돌아가거나 에이전트 콘솔을 열지 않고도 무엇을 허락해 달라는 것인지 이해하고, 만료되기 전에 승인 또는 거절을 내려 맡긴 작업이 불필요하게 멈춰 있지 않게 하는 것. 그러면서도 위험한 동작을 실수로 허락하지 않는 것.

**완료 기준**
요청이 사용자의 명시적 결정으로 `APPROVED` 또는 `REJECTED`가 되어 처리 방식 「수동 결정」으로 기록되고, 호출자의 다음 결과 조회(`GET /api/external/approvals/{id}`)가 그 상태를 받는다. 승인 탭 배지가 1 줄어든다.

## 3. 단계별 상세

> 단계 식별자는 순번이 아닌 슬러그를 쓴다. 순서가 바뀌어도 식별자는 유지한다.

### `STP-request-glance` 잠금 화면에서 승인 요청 알아보기

- **사용자 행동**: 잠금 화면에 도착한 푸시에서 어느 호출자가 무엇을 하려는지 대략 파악한다.
- **터치포인트**: iOS 잠금 화면 알림 (APNs 푸시 — 제목 「승인 요청 · {키 이름}」, 본문 `context` 앞부분)
- **생각·감정**: "k3s-mcp가 prod에서 뭘 지우려고 하네. 아까 맡긴 정리 작업인가?"
- **페인포인트 / 이탈 위험**: 본문이 잘려 있어 판단 근거가 부족하다 → 본문은 4KB 안에서 앞부분만 보여주고, 판단은 상세에서 하도록 유도한다(AC10). 잠금 화면에 배포 대상 같은 내부 정보가 노출된다 → 앱이 따로 제어하지 않고 iOS 「미리보기 표시」 설정에 맡긴다(PRD-12 결정 사항). 호출자가 이름을 속일 수 있다 → 제목에는 호출자가 밝힌 `requesterName`이 아니라 사용자가 붙인 키 이름을 쓴다(AC10, AC13).

### `STP-open-request` 푸시를 눌러 요청 상세 열기

- **사용자 행동**: 푸시를 탭해 앱을 열고, 그 요청의 상세 화면에서 남은 시간을 확인한다.
- **터치포인트**: 승인 탭 — 요청 상세 (딥링크로 곧바로 진입, 만료 카운트다운)
- **생각·감정**: "4분 남았네. 급하게 정하지 않아도 되겠다." / 남은 시간이 짧으면 "빨리 봐야겠다."
- **페인포인트 / 이탈 위험**: 목록이 열려 다시 찾아야 하면 시간이 흐른다 → 푸시를 누르면 해당 요청 상세로 곧바로 들어간다. 푸시를 누른 것만으로는 결정되지 않는다(AC10). 앱이 꺼져 있어도 같은 상세로 열린다(AC10).

### `STP-judge-context` 요청 내용을 읽고 판단하기

- **사용자 행동**: `context` 전문을 읽고, 요청자 이름과 실제 키 이름이 맞는지, 경고 표시가 있는지 보고 허락할지 정한다.
- **터치포인트**: 요청 상세 — `context` 전문, 요청자 이름, 호출자 키 이름, `externalId`, 생성 시각, 「폐기된 키로 생성됨」 경고(해당 시)
- **생각·감정**: "맡긴 정리 작업 맞고, 대상도 맞다. 승인." / "이건 내가 시킨 적 없는데?" — 모르는 요청이면 거절 쪽으로 기운다.
- **페인포인트 / 이탈 위험**: `context`만으로는 판단할 정보가 부족한데 호출자에게 되물을 방법이 없다 → 거절이 안전한 기본값임을 받아들이고, 호출자가 `context`를 충분히 쓰도록 호출자 쪽을 개선한다(가정 — 되묻기 기능은 PRD-12 범위 밖). 요청자 이름과 키 이름이 다르거나 폐기된 키 경고가 있다 → 상세에 둘을 함께 보여 의심 신호가 드러나게 한다(AC6, AC14).

### `STP-confirm-decision` 승인·거절을 확정하기

- **사용자 행동**: 「승인」 또는 「거절」을 누르고 확인 단계에서 확정한다. 요청이 대기 목록에서 빠지고 배지가 줄어드는 것을 본다.
- **터치포인트**: 요청 상세 — 승인·거절 버튼, 확인 다이얼로그, 결정 결과(처리 시각·처리 방식), 승인 탭 배지
- **생각·감정**: "됐다. 에이전트가 이제 이어서 하겠지." — 배지가 줄어드는 것으로 처리했다는 느낌.
- **페인포인트 / 이탈 위험**: 잘못 눌러 위험한 동작을 허락한다 → 확인 단계를 두고, 확정된 결정은 되돌릴 수 없음을 분명히 한다(AC7, V9 비고 「결정에서는 통제를 편의보다 우선」). 확정 직후 자동화가 실제로 진행했는지 알 수 없다 → 이 여정에서는 결정 결과와 처리 시각까지만 보여준다(가정 — 호출자 진행 결과를 알려주는 것은 PRD-12 후속 작업의 웹훅 이후).

## 4. 분기·예외 흐름

| 상황 | 처리 | 이어지는 단계 |
|---|---|---|
| 우회 경로 — 잠금 화면에서 바로 거절 | 알림을 길게 눌러 「거절」 → 잠금 해제 없이 `REJECTED`, 결과가 알림으로 안내된다(AC11) | 해당 없음 (여정 완료) |
| 우회 경로 — 잠금 화면에서 바로 승인 | 「승인」 → 잠금 해제(Face ID/암호)를 먼저 요구, 해제 후 `APPROVED`. 해제를 취소하면 결정되지 않는다(AC11) | 해당 없음 (여정 완료) / 취소 시 `STP-open-request` |
| 중도 이탈 — 푸시를 놓치거나 무시함 | 승인 탭 배지로 대기 요청이 있음을 알고, 대기 목록에서 직접 연다(AC5) | `STP-open-request` |
| 외부 지연 — 결정하기 전에 만료됨 | 카운트다운이 0이 되면 결정 버튼이 비활성화되고 상태가 「만료」로 바뀐다. 호출자는 `EXPIRED`를 받고 중단한다. 여전히 필요하면 호출자가 새 요청을 만든다(AC4, AC6) | 해당 없음 (여정 미완료 종료) |
| 실패 케이스 — 결정을 보내는 중 네트워크·서버 오류 | 결정되지 않았다는 안내와 함께 버튼이 원래 상태로 돌아온다. 재시도로 다시 결정한다(AC12). 잠금 화면 액션 실패도 자동으로 결정되지 않는다(AC11) | `STP-confirm-decision` |
| 실패 케이스 — 다른 기기에서 먼저 처리됨 | 409와 함께 「이미 처리됨」 안내, 먼저 내려진 결정을 보여준다(AC7) | 해당 없음 (여정 완료 — 다른 기기에서) |
| 위험 신호 — 요청자 이름과 키 이름이 다르거나 「폐기된 키로 생성됨」 경고 | 출처를 의심하고 거절한다. 폐기된 키의 대기 요청은 자동 처리되지 않고 사용자 결정을 기다린다(AC14) | `STP-confirm-decision` |
| 이탈 — 자동 응답 모드가 켜져 있음 | 요청이 생성 즉시 자동 승인·거절되고 푸시가 오지 않는다. 대기 목록 상단 배너로 모드가 켜져 있음을 안다(AC9) | 해당 없음 (여정 밖 종료) |
