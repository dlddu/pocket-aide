## 1. 서비스 개요 (참고)

PocketAide 제품 개요와 가치는 [`../product/values.md`](../product/values.md)를 따른다. 이 여정은 PRD-9(LLM 글쓰기 파트너 키보드)가 정한 **목표 동작**을 다룬다. 작성 시점(`main` `e01a18d`)에 PRD-9는 구현 전이다 — 키보드 확장 타깃(`PocketAideKeyboard`)은 등록되어 있지만 `KeyboardViewController`는 「Insert hello from pocket-aide」 버튼과 다음 키보드 전환 버튼만 있는 뼈대다. Full Access 요청(`RequestsOpenAccess`)과 메인 앱과의 App Group·키체인 공유 권한은 이미 선언되어 있다. LLM을 부르는 백엔드 API도 아직 없고 앱의 채팅 탭도 자리표시다. 그래서 이 문서의 화면 문구는 화면 mockup `screen-keyboard-extension`(메일 작성 중 「글쓰기 파트너」 대화 UI)에서 가져왔고, 실제 구현과 다를 수 있다.

iOS 제약에 관한 사실(구현 전에 확인할 것): 키보드 확장은 호스트 입력창 전체 텍스트가 아니라 커서 앞뒤 일부와 선택 영역만 읽을 수 있고, 입력창에 쓸 때는 커서 위치에 삽입하거나 앞 글자를 지우는 방식만 쓸 수 있다(가정 — `UITextDocumentProxy` 기준). Apple 키보드 확장 가이드는 확장이 기기 마이크에 접근할 수 없다고 적고 있어, PRD-9 AC5의 키보드 안 음성 받아쓰기는 현재 iOS에서 가능한 방식부터 확인해야 한다(가정). 비밀번호 같은 보안 입력창이나 사용자 지정 키보드를 막은 앱에서는 iOS가 시스템 키보드로 바꾼다.

다루지 않는 것: 앱 안 AI 채팅 탭에서 대화하는 흐름(PRD-1 — 같은 V5지만 별도 여정), 운전 중 음성 캡처(`JRN-voice-capture-while-driving`), 호스트 앱(메일·메시지)에서 메시지를 실제로 보내는 일.

## 2. 여정 정의

**대상 사용자 (페르소나)**
사용자 본인. 회사 메일·슬랙 메시지를 폰으로 자주 쓰고, 한국어 문장에 영어 용어가 섞인다(「Q4 roadmap 리뷰 일정」). 쓰고 나서 톤이 장황하거나 너무 사과조인 것이 마음에 걸리면, 지금은 글을 복사해 다른 AI 앱에 붙여 넣고 고친 결과를 다시 복사해 온다(가정). 이 앱 전환과 복사·붙여넣기가 귀찮아 그냥 보내 버리는 일이 많다.

**진입 맥락**
메일 앱에서 새 메일(또는 답장)을 쓰는 중이다. 본문 초안이 입력창에 있거나, 아직 비어 있다. PocketAide 키보드는 설정에서 추가해 두었고 Full Access도 허용했다. PocketAide 앱에는 로그인되어 있다.

**트리거**
초안을 다시 읽다가 "너무 길고 변명 같네. 짧고 단호하게 바꾸고 싶다." — 또는 빈 답장 창 앞에서 "이 일정 변경 요청, 뭐라고 쓰지?"

**사용자 목표**
메일 앱을 떠나지 않고, 복사·붙여넣기 없이, 원하는 방향을 말로 지시해 고친 글을 확인한 뒤 입력창에 바로 반영하는 것. 원문과 비교해 마음에 들 때만 반영하는 것.

**완료 기준**
글쓰기 파트너 대화 UI에서 미리보기를 받은 뒤 사용자가 「적용」을 눌러 키보드 확장이 호스트 입력창에 결과를 써 넣는 데 성공하고(입력창 쓰기 호출 성공), 자판으로 돌아온다(PRD-9 AC9·AC10). 이후 호스트 앱에서 보내는지는 앱이 관찰할 수 없다(가정).

## 3. 단계별 상세

> 단계 식별자는 순번이 아닌 슬러그를 쓴다. 순서가 바뀌어도 식별자는 유지한다.

### `STP-enable-keyboard` 처음 한 번 키보드를 추가하고 Full Access 허용하기

- **사용자 행동**: iOS 설정 → 일반 → 키보드 → 새로운 키보드 추가에서 PocketAide를 고르고, 「전체 접근 허용」을 켠다. 시스템 경고(입력한 내용이 전송될 수 있다는 안내)를 읽고 허용한다.
- **터치포인트**: iOS 설정의 키보드 목록과 Full Access 토글·시스템 경고, PocketAide 앱 안의 설정 안내(PRD-9 AC12 — 형태 미정, 가정)
- **생각·감정**: "전체 접근? 내가 치는 거 다 보내는 거 아냐?" — 망설임
- **페인포인트 / 이탈 위험**: iOS의 Full Access 경고가 「입력한 모든 내용」을 언급해 불안을 키우고, 여기서 끄면 LLM·음성 기능이 모두 비활성이다(PRD-9 AC12) → 앱 안에서 먼저 「대화 UI를 연 동안의 컨텍스트만 서버로 보낸다」는 범위를 설명하고 설정으로 보내는 안내 화면을 두는 것을 후보로 둔다(가정 — PRD-9 열린 질문 「프라이버시 고지」). 설정 경로가 깊어 앱에서 바로 열 수 없다(가정 — 앱 설정 화면까지만 열 수 있다)(PRD-9 AC1, AC12).

### `STP-open-partner` 입력창에서 키보드를 바꿔 글쓰기 파트너 열기

- **사용자 행동**: 메일 본문을 쓰다가 🌐 키를 눌러(또는 길게 눌러 골라) PocketAide 키보드로 바꾸고, 트리거를 눌러 자판을 가린 전면 대화 UI를 연다. 위에는 메일 앱의 받는 사람·제목·본문이 그대로 보인다.
- **터치포인트**: 시스템 🌐 키, PocketAide 키보드의 트리거(형태 미정 — 가정), 대화 UI 머리 「PA 글쓰기 파트너 · Full Access · 자판」, 하단 띠 「🌐 길게 눌러 키보드 변경 · LLM·음성은 네트워크를 사용해요」(`screen-keyboard-extension`)
- **생각·감정**: "이 메일 그대로 보면서 고칠 수 있겠네."
- **페인포인트 / 이탈 위험**: 키보드를 바꾸고 다시 트리거를 누르는 두 단계가 매번 필요하다 — 자주 쓰면 기본 자판까지 PocketAide 키보드로 둘지 고민하게 된다 → PocketAide 키보드의 자판 자체가 쓸 만해야 하는지, 대화 UI 전용으로만 쓰고 바로 다른 키보드로 돌아가게 할지 정한다(가정 — PRD-9는 「표준 자판으로 복귀」만 정한다). 비밀번호·전화번호 같은 보안 입력창이나 사용자 지정 키보드를 막은 앱에서는 키보드가 바뀌지 않는다. 키보드 확장은 메모리 한도가 작아 대화 UI가 무거우면 iOS가 확장을 종료할 수 있다(가정)(PRD-9 AC2, AC4).

### `STP-give-instruction` 원문을 확인하고 말이나 글로 지시하기

- **사용자 행동**: 대화 UI 맨 위 컨텍스트 카드(「메일 본문 · 컨텍스트」 — 본문 앞부분)를 보고, 아래 입력란에 「더 짧고 단호하게, 사과 톤은 빼고」처럼 지시를 적거나 음성 버튼을 눌러 말한다. 입력창이 비어 있으면 「윤정님께 내일 분기 리뷰를 오후 3시로 미루자는 메일 써줘」처럼 백지 작성을 지시한다.
- **터치포인트**: 컨텍스트 카드, 대화 말풍선(내 지시 · PA 응답), 컴포저(입력 · 음성 · 전송), 처리 중 표시와 취소(AC13)
- **생각·감정**: "이 정도로 말하면 알아듣겠지." / 음성이면 "Q4 roadmap 같은 건 제대로 받아쓰려나."
- **페인포인트 / 이탈 위험**: 키보드 확장은 입력창 전체가 아니라 커서 앞뒤 일부와 선택 영역만 읽을 수 있어, 긴 메일에서는 컨텍스트 카드에 본문 일부만 잡힐 수 있다 → 무엇이 컨텍스트로 잡혔는지 카드에 그대로 보여 주고, 잡히지 않은 경우 「전체 선택 후 다시 열기」를 안내하는 것을 후보로 둔다(가정 — PRD-9 AC3는 「텍스트(또는 선택 영역)」 자동 전달만 정한다). 자판이 가려진 상태에서 지시를 글로 쓰려면 대화 UI 안에 별도의 입력 수단이 필요하다 — 키보드 안의 키보드다 → 기본 지시 수단을 음성으로 두고 글 입력은 보조로 둘지 정한다(가정). 그런데 키보드 확장의 마이크 접근은 iOS가 막아 왔다(Apple 가이드) → PRD-7 AC6(키보드 전용 인식기)의 구현 형태를 정하기 전에 키보드 안 녹음이 가능한지부터 확인한다(가정). 호스트 입력창의 글이 LLM 서버로 간다는 것이 이 단계에서 처음 실제로 일어난다(PRD-9 열린 질문 「프라이버시 고지」)(PRD-9 AC3, AC5, AC6, AC7, AC8, AC11, AC13 · PRD-7 AC6).

### `STP-review-preview` 미리보기에서 바뀐 글을 확인하기

- **사용자 행동**: 응답이 오면 미리보기(「미리보기 · 메일 본문 전체」)에서 지워질 문장과 새 문장을 보고, 원문(위에 보이는 메일 본문)과 대조한다. 마음에 안 들면 「이어서 대화 →」로 「인사는 남겨줘」처럼 추가 지시를 하거나 「거절」한다.
- **터치포인트**: 미리보기 카드(지워질 문장 취소선 · 새 문장), 「적용」·「거절」·「이어서 대화 →」(`screen-keyboard-extension`), 부분 적용 선택(AC9 — 형태 미정, 가정)
- **생각·감정**: "훨씬 낫네. 근데 첫 인사는 살리고 싶다."
- **페인포인트 / 이탈 위험**: 키보드 영역은 화면 아래 절반 정도라 메일 전체를 다시 쓴 결과는 미리보기에서 스크롤해야 하고, 위의 원문도 일부만 보인다 → 바뀐 부분만 강조하는 비교 표시(mockup의 취소선)를 기본으로 두고, 전체 결과는 펼쳐 보게 한다(가정). LLM 응답에는 몇 초가 걸린다 — 기다리는 동안 처리 중 표시와 취소가 필요하고, 그동안 호스트 입력창은 그대로여야 한다(PRD-9 AC13). 거절하거나 대화 UI를 닫으면 대화가 남는지 정해지지 않았다(PRD-9 열린 질문 「대화 이력 보존 범위」)(PRD-9 AC9, AC13).

### `STP-apply-to-field` 적용 방식을 고르고 입력창에 반영하기

- **사용자 행동**: 적용 모드(「전체 덮어쓰기 · 선택 영역만 · 커서에 삽입」)를 확인하고 「적용」을 누른다. 결과가 메일 본문에 들어가고 대화 UI가 닫혀 자판으로 돌아온다. 메일 앱에서 마지막으로 훑어보고 보낸다.
- **터치포인트**: 적용 모드 표시와 선택, 「적용」, 호스트 입력창 반영, 자판 복귀, 메일 앱의 「보내기」(앱 밖)
- **생각·감정**: "됐다. 복사·붙여넣기 없이 끝났네."
- **페인포인트 / 이탈 위험**: 키보드 확장은 입력창 전체를 한 번에 바꿀 수 없어 「전체 덮어쓰기」는 앞 글자를 지우고 새로 넣는 방식이 된다 — 커서 뒤 글자나 서식(메일의 인용·서명)이 남거나 깨질 수 있다(가정) → 덮어쓰기 전에 지울 범위를 미리보기에 표시하고, 서명·인용 블록은 컨텍스트에서 빼는 것을 후보로 둔다(가정). 기본 모드가 정해지지 않았다 — 선택 영역이 있으면 「선택 영역만」, 없으면 「전체 덮어쓰기」로 자동 분기하는 안을 제안한다(가정 — PRD-9 열린 질문 「적용 모드의 기본값」). 적용 뒤 되돌리기는 호스트 앱의 실행 취소(흔들기 등)에 기대야 하고, 앱마다 동작이 다르다(가정)(PRD-9 AC9, AC10).

## 4. 분기·예외 흐름

| 상황 | 처리 | 이어지는 단계 |
|---|---|---|
| 실패 케이스 — Full Access 미허용 | 대화 UI 진입 시 LLM·음성 기능이 비활성임을 안내한다(PRD-9 AC12). 설정에서 허용한 뒤 다시 연다 | `STP-enable-keyboard` |
| 실패 케이스 — PocketAide 앱에 로그인되지 않음 | 처리 방식 PRD 미정의(열린 질문 「인증/세션 공유」). 위젯처럼 공유 키체인의 토큰을 읽고, 없으면 「앱에서 로그인이 필요해요.」를 보이는 것을 제안한다(가정 — 키체인 공유 권한은 이미 선언됨) | 해당 없음 |
| 실패 케이스 — 보안 입력창·사용자 지정 키보드를 막은 앱 | iOS가 시스템 키보드로 바꿔 PocketAide 키보드를 쓸 수 없다. 다른 입력창에서 쓰거나 다른 앱에서 쓴 뒤 옮긴다 | 해당 없음 |
| 실패 케이스 — 네트워크 없음·LLM 오류 | 대화 UI에 오류와 다시 시도를 보이고, 호스트 입력창은 바뀌지 않는다(PRD-9 AC13 — 문구 미정, 가정) | `STP-give-instruction` |
| 실패 케이스 — 음성 받아쓰기 불가(마이크 제약·권한) | 키보드 안 녹음이 막히면 글 입력으로 지시한다. 메인 앱을 잠깐 열어 녹음하는 우회가 가능한지는 구현 시 확인(가정) | `STP-give-instruction` |
| 실패 케이스 — 컨텍스트가 일부만 잡힘 | 컨텍스트 카드에서 잡힌 범위를 확인하고, 본문을 전체 선택한 뒤 다시 연다(가정) | `STP-give-instruction` |
| 중도 이탈 — 응답을 기다리다 취소 | 처리를 취소하고 같은 대화에서 다시 지시하거나 닫는다. 호스트 입력창은 그대로다(PRD-9 AC13) | `STP-give-instruction` |
| 중도 이탈 — 대화 UI를 닫거나 다른 앱으로 감 | 자판으로 돌아가고 입력창은 그대로다. 다시 열었을 때 이전 대화가 남는지는 미정(열린 질문 「대화 이력 보존 범위」). iOS가 확장을 종료하면 대화는 사라진다(가정) | `STP-open-partner` |
| 우회 경로 — 결과가 마음에 안 듦 | 「이어서 대화 →」로 추가 지시하거나 「거절」 후 새로 지시한다 | `STP-give-instruction` |
| 우회 경로 — 결과의 일부만 쓰고 싶음 | 부분 적용으로 고른 문장만 반영한다(PRD-9 AC9 — 고르는 방식 미정, 가정) | `STP-apply-to-field` |
| 우회 경로 — 빈 입력창에서 시작(백지 작성) | 컨텍스트 없이 지시하면 초안을 만든다(PRD-9 AC8). 적용 모드는 「커서에 삽입」이 자연스럽다(가정) | `STP-review-preview` |
| 실패 케이스 — 적용했는데 서식·서명이 깨짐 | 호스트 앱의 실행 취소로 되돌린다(앱마다 다름 — 가정). 대화 UI를 다시 열어 범위를 좁혀 지시한다 | `STP-give-instruction` |
| 외부 지연 — LLM·음성 인식 응답 | 처리 중임을 보이고 비동기로 처리해, 기다리는 동안 취소하거나 다음 지시로 넘어갈 수 있게 한다(PRD-9 AC13) | `STP-review-preview` |
