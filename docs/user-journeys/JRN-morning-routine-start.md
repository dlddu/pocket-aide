## 1. 서비스 개요 (참고)

PocketAide 제품 개요와 가치는 [`../product/values.md`](../product/values.md)를 따른다. 이 여정은 루틴 탭(PRD-2, `RoutinesView`)의 **현재 구현 범위**(`main` `c4c4da7` 기준)를 다룬다. 루틴 탭은 iPhone에서 하단 탭 바가 아니라 「더 보기」 목록에 있다 — 현재 `RootView`에서는 일곱 번째 탭이라 그렇고, PRD-12 탭 재구성 결정(`tokens.md` §7, 2026-10-05) 뒤에도 「더 보기」 안 임시공간·개인·회사 다음 네 번째 자리에 남는다. 루틴 이름·주기 변경은 PRD-2 범위 밖(삭제 후 재생성)이고, 루틴 알림·위젯 노출은 현재 없다.

## 2. 여정 정의

**대상 사용자 (페르소나)**
사용자 본인. 아침에 하고 싶은 일(물 한 잔, 스트레칭, 일정 확인 등)이 정해져 있지만, 머릿속에만 두면 날마다 순서가 흐트러지고 몇 가지를 빠뜨린다. 일어나서 가장 먼저 폰을 집는다(가정).

**진입 맥락**
아침 루틴을 한 번 정의해 둔 상태에서, 아침에 일어나 폰을 집어 든다. 처음 쓰는 날에는 루틴을 정의하는 것부터 시작한다.

**트리거**
아침에 일어나 폰 잠금을 푼 순간 — "오늘 아침 할 거 뭐였지?" (현재 앱이 먼저 알려 주지 않으므로 트리거는 사용자 기억에 의존한다)

**사용자 목표**
정해 둔 아침 흐름을 빠뜨리지 않고 순서대로 끝내고, "오늘 아침은 다 했다"는 확신을 갖는 것. 여러 날에 걸쳐 루틴이 얼마나 지켜지는지 보는 것.

**완료 기준**
그날 아침 루틴의 마지막 단계를 체크해 루틴이 「완료」 상태가 된다 — 카드 진행 표시가 「완료」로 바뀌고, 서버의 그날 단계 체크가 모두 기록된다(`PATCH /api/routines/{id}/days/{day}/steps/{stepID}` 응답의 루틴 완료).

## 3. 단계별 상세

> 단계 식별자는 순번이 아닌 슬러그를 쓴다. 순서가 바뀌어도 식별자는 유지한다.

### `STP-define-routine` 아침 루틴 정의하기

- **사용자 행동**: 루틴 탭 머리의 「새 루틴」을 눌러 시트 한 장에서 이름(「아침 루틴」)을 쓰고, 반복 주기를 고르고(기본 「매일」), 「단계 추가」로 칸을 늘려 단계를 순서대로 넣은 뒤 저장한다. 처음 한 번만 거치는 단계다.
- **터치포인트**: 더 보기 → 루틴 탭 — 「새 루틴」 시트(이름 · 주기 세그먼트 · 매월 스테퍼 · 단계 입력, 편집 시트 패턴)
- **생각·감정**: "아침에 하는 거 다 적어 두자." / "순서도 이대로면 되겠지."
- **페인포인트 / 이탈 위험**: 이름과 주기는 저장 뒤 바꿀 수 없다 — 바꾸려면 루틴을 지우고 다시 만들어야 하고, 지우면 이력도 함께 사라진다 → 시트에서 이름·주기가 나중에 바뀌지 않는다는 점을 알리거나, PRD-2 후속으로 이름·주기 편집을 검토한다. 빈 단계 칸은 저장되지 않으므로 칸을 넉넉히 늘려도 괜찮다(PRD-2 AC1, AC2).

### `STP-open-today` 아침에 오늘 루틴 열기

- **사용자 행동**: 앱을 열고 「더 보기」에서 「루틴」을 눌러, 「오늘 · N」 섹션 맨 위의 아침 루틴 카드를 찾는다.
- **터치포인트**: 더 보기 목록(네 번째 항목) → 루틴 탭 — 머리 날짜(「M월 d일 · E요일」), 「오늘 · N」 섹션, 루틴 카드(요약 줄 「매일 · 0 / 3 완료」, 진행 표시 「대기」)
- **생각·감정**: "아, 오늘도 이거 세 개." / "루틴이 어디 있더라… 더 보기 안이었지."
- **페인포인트 / 이탈 위험**: 루틴 탭이 「더 보기」 안에 있어 진입이 두 번 걸리고, 앱이 먼저 알려 주지 않으니 아예 열지 않고 하루를 시작하기 쉽다 PRD-12 탭 재구성에서도 루틴은 「더 보기」에 남기로 정해졌으므로(`tokens.md` §7) 탭 위치로는 풀리지 않는다 → 앱이 먼저 알려 주는 수단 — 루틴 활성 시각 리마인드 알림(PRD-8 AC6 알림 모음에도 더해진다) 또는 위젯에 오늘 루틴 진행률 노출(PRD-8 여섯 영역에 루틴은 없다) — 을 PRD-2 후속 후보로 둔다(현재 PRD 범위 밖). 오늘 활성화되지 않은 루틴은 「오늘 쉬는 루틴」으로 분리되어 아침 루틴만 위에 보인다(PRD-2 AC2).

### `STP-check-steps` 단계 하나씩 체크하기

- **사용자 행동**: 단계를 실제로 하면서 카드의 단계 행을 하나씩 누른다. 잘못 누르면 다시 눌러 푼다.
- **터치포인트**: 루틴 카드 — 단계 행(체크 원 + 취소선), 요약 줄 「n / m 완료」, 진행 막대, 진행 표시(「33%」 등)
- **생각·감정**: "물 마셨고, 체크." / "다음은 스트레칭."
- **페인포인트 / 이탈 위험**: 체크는 서버 응답이 온 뒤에야 화면에 반영되어, 망이 느리면 눌렀는지 헷갈려 두 번 누르기 쉽다(두 번 누르면 체크가 풀린다) → 누르는 즉시 표시를 바꾸고 실패 시 되돌리는 낙관적 갱신을 검토한다. 실패하면 목록 위에 오류 원문 문자열이 그대로 나온다 → 사람이 읽을 문구와 재시도로 바꾼다(PRD-2 AC3).

### `STP-complete-routine` 마지막 단계로 그날 완료 확인하기

- **사용자 행동**: 마지막 단계를 체크하고, 카드가 「완료」로 바뀐 것을 확인한 뒤 앱을 닫는다.
- **터치포인트**: 루틴 카드 — 「m / m 완료」, 진행 표시 「완료」, 강조된 카드 테두리
- **생각·감정**: "오늘 아침은 끝." — 다 했다는 확신으로 하루를 시작한다.
- **페인포인트 / 이탈 위험**: 완료 표시가 테두리·글자 변화뿐이라 성취감이 약하다 → 완료 순간의 피드백(햅틱 등)을 후속 후보로 둔다(가정 — PRD 미정의). 단계가 없는 루틴은 「0 / 0」에서 완료되지 않는다(결정 사항) — 4절 분기 참조(PRD-2 AC3).

### `STP-review-history` 지난 아침들 돌아보기

- **사용자 행동**: 며칠 뒤 카드의 「이력」을 눌러 지난 30일 격자와 일자별 목록을 훑어보고 닫는다. 완료 기준 이후의 선택 단계로, 다음 날 루틴을 이어 갈 동기가 된다.
- **터치포인트**: 이력 시트 — 머리 「<루틴 이름> · 30일」, 요약 줄 「<주기> · 예정 N일 중 M일 완료」, 30칸 히트맵, 일자별 「완료」/「미완료 n/m」/「쉬는 날」 목록
- **생각·감정**: "이번 주는 거의 다 했네." / "주말마다 비는구나."
- **페인포인트 / 이탈 위험**: 과거 날짜의 분모가 현재 단계 수라, 단계를 바꾼 뒤에는 지난날의 「미완료 n/m」이 실제와 달라 보인다(결정 사항) → 시트에 분모 기준을 한 줄로 안내한다. 지난날의 체크는 앱에서 고칠 수단이 없다(가정 — 서버는 활성일이면 지난 날짜 체크를 받지만 앱에 진입점이 없다)(PRD-2 AC4).

## 4. 분기·예외 흐름

| 상황 | 처리 | 이어지는 단계 |
|---|---|---|
| 우회 경로 — 임시 공간 메모를 루틴으로 옮김 | 임시 공간 카드의 「→ 루틴」으로 그 텍스트를 이름으로 하는 「매일」 루틴이 단계 없이 생긴다. 카드의 「단계」 시트에서 단계를 붙인다(PRD-4 AC4) | `STP-define-routine` |
| 실패 케이스 — 단계 없는 루틴 | 「0 / 0 완료」·「대기」에서 완료되지 않는다. 「단계」 시트에서 단계를 추가한다 | `STP-define-routine` |
| 실패 케이스 — 체크 요청 실패(네트워크·서버) | 체크 표시는 바뀌지 않고 목록 위에 오류 문구가 나온다. 다시 누르거나 당겨서 새로고침한 뒤 이어서 체크한다 | `STP-check-steps` |
| 중도 이탈 — 일부만 체크하고 앱을 닫음 | 체크는 단계 × 날짜로 서버에 남아, 같은 날 다시 열면 이어서 체크할 수 있다. 날짜가 넘어가면 이력에 「미완료 n/m」으로 남는다 | `STP-check-steps` |
| 변형 — 단계 구성을 바꾸고 싶음 | 「단계」 시트에서 단계를 추가하거나 빼기 버튼으로 지운다. 삭제에는 확인 단계가 없고 그 단계의 과거 체크도 함께 지워진다(결정 사항) | `STP-check-steps` |
| 변형 — 이름·주기를 바꾸고 싶음 | 편집 수단이 없어 스와이프 「삭제」 후 다시 만든다. 삭제는 확인 없이 즉시 실행되고 단계·체크 이력이 함께 지워진다(`ON DELETE CASCADE`) | `STP-define-routine` |
| 변형 — 오늘이 주기상 쉬는 날 | 루틴이 「오늘 쉬는 루틴」에 있고 체크할 단계가 나오지 않는다. 행을 누르면 이력 시트가 열린다 | `STP-review-history` |
| 외부 지연 — 자정을 넘겨 앱을 그대로 복귀 | 루틴 탭은 탭 진입·당겨서 새로고침 때만 그날 날짜로 다시 불러오므로, 백그라운드에서 같은 탭으로 돌아오면 전날 목록이 남을 수 있다(코드 기준 — 포그라운드 복귀 재조회 없음, 실기기 확인 필요). 당겨서 새로고침하면 체크가 비워진 새 날로 시작한다 | `STP-open-today` |
