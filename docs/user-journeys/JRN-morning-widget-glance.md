## 1. 서비스 개요 (참고)

PocketAide 제품 개요와 가치는 [`../product/values.md`](../product/values.md)를 따른다. 이 여정은 **구현된 위젯 동작**을 기준으로 한다 — 작성 시점(`main` `0908a6a`)에 홈 화면 위젯은 Large 크기 하나이고, 날씨(#111)·다음 일정(#102)·다짐(#29)·PocketAide 알림(#106) 네 영역이 실제 값을 보이며, 날씨 영역은 앱 안의 날씨 화면으로, 다음 일정 영역은 iOS 캘린더 앱으로 넘긴다(#162). 메일 영역은 「곧 추가」 자리표시이고, 임시 공간 미분류 수 영역은 아직 없다(PRD-8 AC3·AC9·AC11 구현 전). 화면 문구와 동작은 `PocketAideWidget`·`AffirmationProvider`(타임라인)·`Sections/*`·`PocketAideApp.handleDeepLink`·`WeatherView`에서 가져왔다.

구조에 관한 사실: 위젯은 30분마다 타임라인을 다시 만든다 — 다짐·알림은 백엔드 API, 날씨는 Open-Meteo, 다음 일정은 기기 캘린더(EventKit)에서 읽는다. 위젯은 권한을 요청할 수도, 위치를 직접 읽을 수도 없다 — 캘린더 권한과 위치는 앱이 시작되거나 앞으로 나올 때 앱이 받아 위젯과 공유한다(PRD-8 결정 사항). 날씨 화면은 위젯 날씨 영역에서만 들어갈 수 있고 탭 바·「더 보기」에는 없다.

다루지 않는 것: 위젯의 다짐 영역을 읽고 다짐 탭으로 들어가는 흐름(`JRN-affirmation-daily-exposure`의 `STP-widget-glance`·`STP-widget-to-app`), PR 모니터로 넘어간 뒤 알림을 「확인」하는 일(`JRN-ci-push-to-ack`), 임시 공간 정리(`JRN-meeting-notes-triage`), iOS 캘린더 앱 안에서 일정을 다루는 일.

## 2. 여정 정의

**대상 사용자 (페르소나)**
사용자 본인. 아침에 일어나 폰을 집으면 날씨 앱, 캘린더 앱, 슬랙·GitHub 알림을 차례로 열어 오늘을 가늠하던 습관이 있다(가정). 출근 준비 중이라 손이 바쁘고, 앱을 여러 개 오가기보다 한 번 보고 폰을 내려놓고 싶다. 출장·외근으로 다른 동네에서 아침을 맞는 날도 있다(가정).

**진입 맥락**
홈 화면 첫 페이지에 PocketAide 위젯(Large)을 두었다. 앱에는 로그인되어 있고, 캘린더·위치 권한은 앱을 처음 열 때 허용했다. 아침에 잠금을 풀고 홈 화면이 보인 순간이다.

**트리거**
아침에 폰을 처음 열었을 때 — "오늘 날씨는? 첫 일정이 몇 시였지? 밤새 뭐 온 거 있나?"

**사용자 목표**
앱을 여러 개 열지 않고 홈 화면 한 번으로 오늘의 날씨·일정·밤사이 알림을 파악하고, 더 봐야 할 것만 한 번 눌러 확인한 뒤 하루를 시작하는 것.

**완료 기준**
아침 첫 잠금 해제 시점에 위젯이 30분 안에 만든 엔트리를 보이고 있고 날씨·다음 일정·알림 영역이 안내 문구(권한·로그인·오류)가 아닌 실제 값을 표시한다(타임라인 생성 시 각 영역 상태로 확인). 더 볼 것이 있으면 사용자가 영역을 눌러 앱이 `pocketaide://weather`·`pocketaide://calendar`·`pocketaide://pr-monitor` 중 하나를 받아 해당 화면에 도달한다(`handleDeepLink` 수신). 날씨 앱·캘린더 앱을 홈 화면에서 따로 열지 않았는지는 앱이 관찰할 수 없어 자기 보고로 본다(가정).

## 3. 단계별 상세

> 단계 식별자는 순번이 아닌 슬러그를 쓴다. 순서가 바뀌어도 식별자는 유지한다.

### `STP-place-widget` 위젯을 두고 앱에서 권한을 열어 두기

- **사용자 행동**: 홈 화면 편집에서 PocketAide 위젯(Large)을 첫 페이지에 추가한다. 위젯의 일정·날씨 영역에 「앱에서 캘린더 접근을 허용해 주세요.」·「앱에서 위치 접근을 허용해 주세요.」가 보이면, 앱을 한 번 열어 알림 → 캘린더 → 위치 권한 요청을 차례로 허용한다.
- **터치포인트**: iOS 위젯 갤러리(「PocketAide — 하루를 한눈에 — 다짐과 일상 정보를 모아 봅니다.」), 위젯의 권한 안내 문구, 앱 시작 직후 시스템 권한 대화상자 세 개, 허용 직후 위젯 즉시 갱신 요청
- **생각·감정**: "위젯이 왜 비어 있지? 아, 앱을 열어야 하는구나." / "권한을 세 번이나 묻네."
- **페인포인트 / 이탈 위험**: 위젯은 스스로 권한을 요청할 수 없어, 앱을 열기 전까지 안내 문구만 보인다 — 안내가 「앱에서 허용해 주세요」뿐이라 무엇을 해야 하는지는 알지만, 처음 설치한 직후에는 위젯이 고장 난 것처럼 보인다 → 위젯 안내를 누르면 앱이 열리며 바로 해당 권한을 요청하도록 하는 것을 후보로 둔다(가정 — 지금 일정 영역 탭은 캘린더 앱으로, 날씨 영역 탭은 날씨 화면으로 간다). 앱 시작 직후 권한 요청 세 개가 연달아 나오면 내용을 읽지 않고 거부하기 쉽다(PRD-8 결정 사항 「캘린더 권한 요청 시점」). 위젯 크기는 Large 하나뿐이라 홈 화면 한 페이지의 절반을 차지한다(PRD-8 AC1)(PRD-8 AC1, AC2, AC4).

### `STP-morning-glance` 아침에 홈 화면에서 위젯을 한 번 훑기

- **사용자 행동**: 잠금을 풀고 홈 화면의 위젯을 위에서부터 훑는다 — 왼쪽 위 날씨(동네 이름, 현재 기온·상태, 「최고 N · 최저 N · 강수 N%」), 오른쪽 위 다음 일정(첫 일정 제목과 「14:00 — 15:30」, 나머지 시작 시각과 제목, 「+ N 더」), 가운데 다짐, 아래 「PocketAide 알림」(가장 최근 CI 알림 두 줄과 「+ N 더」).
- **터치포인트**: 위젯 Large의 다섯 칸(날씨 · 다음 일정 · 다짐 · 메일 「곧 추가」 · PocketAide 알림)
- **생각·감정**: "14도, 강수 60%. 우산 챙기고. 10시 스탠드업이 첫 일정이네. 밤사이 CI 하나 실패했구나." — 앱을 열지 않고 머릿속에 오늘이 잡힌다.
- **페인포인트 / 이탈 위험**: 위젯 어디에도 언제 가져온 값인지 보이지 않는다 — 최대 30분 전 값이 정상이지만, 백엔드 조회(다짐)가 실패하면 타임라인 전체가 60분 뒤로 미뤄져(`AffirmationProvider`의 오류 백오프) 백엔드와 무관한 날씨·일정 엔트리까지 오래 묵는다 → 오류 백오프를 백엔드 영역에만 적용하거나 영역별 「n분 전」 표시를 후보로 둔다(가정). 위젯은 앱이 마지막으로 받은 위치의 날씨를 보이므로, 출장지에서 아침을 맞아도 앱을 열기 전까지는 어제 있던 동네 날씨가 보인다 — 동네 이름이 라벨에 있어 알아챌 수는 있다(PRD-8 결정 사항 「위치」). 알림 영역은 이 앱이 보낸 CI 완료 푸시만 모으므로(라벨 「PocketAide 알림」) 슬랙·메일 등 다른 알림은 여전히 각 앱에서 봐야 한다(PRD-8 AC6 비고). 메일 칸은 「곧 추가」 자리만 차지하고, 임시 공간 미분류 수는 아직 보이지 않는다(AC3·AC9 구현 전)(PRD-8 AC1, AC2, AC4, AC6, AC7).

### `STP-check-weather-detail` 날씨 영역을 눌러 오늘 시간별 예보 보기

- **사용자 행동**: 강수 확률이 애매하면 날씨 영역을 누른다. 앱이 열리며 탭 위에 날씨 화면이 뜨고, 현재 상태 아래 시간별 예보를 가로로 넘겨 퇴근 시간대 비 여부를 본다. 필요하면 주간 예보까지 보고 「닫기」로 닫는다.
- **터치포인트**: 위젯 날씨 영역(`pocketaide://weather`), 앱 날씨 화면(동네 이름 · 현재 기온·상태·체감·최고/최저·최대 강수 확률 · 「시간별 예보」 24시간 · 「주간 예보」 7일 · 갱신 시각 · 당겨서 새로고침 · 「닫기」)
- **생각·감정**: "6시쯤부터 비네. 우산 챙기자."
- **페인포인트 / 이탈 위험**: 날씨 화면은 위젯과 같은 30분 캐시 값을 먼저 보이고 새로 가져오므로, 열자마자 숫자가 바뀔 수 있다(PRD-8 결정 사항 「날씨 화면」). 날씨 화면은 위젯에서만 열 수 있어, 앱 안에서 다시 보고 싶으면 홈 화면으로 나가 위젯을 다시 눌러야 한다 → 의도된 결정이지만 사용 중 불편이 크면 「더 보기」 진입을 재검토한다(가정). 「닫기」를 누르면 앱이 마지막으로 열려 있던 탭이 나와, 하루를 시작하려던 흐름에 다른 화면이 끼어든다(PRD-8 AC10).

### `STP-check-schedule` 일정 영역을 눌러 캘린더에서 오늘 일정 보기

- **사용자 행동**: 일정이 「+ N 더」로 잘렸거나 장소·참석자를 봐야 하면 일정 영역을 누른다. PocketAide가 잠깐 열렸다가 iOS 캘린더 앱의 오늘 날짜로 넘어간다.
- **터치포인트**: 위젯 다음 일정 영역(`pocketaide://calendar`), 잠깐 보이는 PocketAide 화면, iOS 캘린더 앱(비공식 `calshow:` URL)
- **생각·감정**: "점심 미팅 장소가 어디였지… 아, 여기."
- **페인포인트 / 이탈 위험**: 위젯 링크는 이 앱만 열 수 있어 PocketAide를 거쳐 캘린더로 넘어간다 — 넘어가는 동안 앱 화면이 잠깐 번쩍인다. `calshow:`는 공식 URL이 아니어서 iOS 업데이트로 막히면 캘린더 대신 PocketAide 다짐 탭에 머문다(PRD-8 결정 사항 「진입 대상 — 다음 일정」) → 그때 사용자는 홈 화면으로 나가 캘린더 앱을 직접 연다. 위젯은 7일 안의 일정 중 최대 3개만 보여 오늘 일정이 많으면 첫 화면에서 다 보이지 않는다(PRD-8 AC2, AC8).

### `STP-check-notifications` 알림 영역을 눌러 밤사이 알림 확인하기

- **사용자 행동**: 알림 영역에 실패 알림이나 「+ N 더」가 보이면 누른다. 앱의 PR 모니터 탭이 열리고 밤사이 쌓인 CI 결과 이력 그룹을 훑는다. 처리할 것을 확인하는 일은 `JRN-ci-push-to-ack`로 이어진다.
- **터치포인트**: 위젯 「PocketAide 알림」 영역(`pocketaide://pr-monitor`), 앱 PR 모니터 탭(미확인 배지 · 미확인 그룹 카드)
- **생각·감정**: "실패 하나, 통과 둘. 실패한 건 출근해서 보자."
- **페인포인트 / 이탈 위험**: 위젯은 가장 최근 알림 하나만 두 줄로 보이고 나머지는 개수뿐이라, 실패가 최근 알림 뒤에 묻히면 위젯만으로는 놓친다 → 실패 알림을 우선 표시하거나 「실패 n」 개수를 따로 보이는 것을 후보로 둔다(가정). 앱에서 「확인」하기 전까지는 같은 알림이 위젯에 계속 남는다 — 이는 의도된 동작이다(PRD-8 결정 사항 「알림 모음의 대상」)(PRD-8 AC6, AC8).

| 실패 케이스 — 백엔드 조회 오류 | 다짐·알림 영역에 「잠시 후 다시 시도할게요.」이고, 위젯 전체의 다음 갱신이 60분 뒤로 미뤄져 날씨·일정도 그동안 다시 가져오지 않는다(`AffirmationProvider` 백오프) | `STP-morning-glance` |

| 실패 케이스 — 캘린더 앱으로 넘기지 못함(`calshow:` 차단) | PocketAide 다짐 탭에 머문다(PRD가 정한 후퇴 동작). 홈 화면으로 나가 캘린더 앱을 직접 연다 | 해당 없음 |
| 실패 케이스 — 메일 칸을 누름 | 메일 칸은 자리표시라 위젯 기본 링크 `pocketaide://root`를 따르는데 앱이 처리하지 않아 마지막으로 연 탭이 열린다(AC11 구현 전) | 해당 없음 |
| 외부 지연 — 위치가 바뀜(출장·외근) | 위젯은 앱이 마지막으로 받은 위치를 쓴다. 앱을 한 번 열면 새 위치를 받아 위젯 갱신을 요청한다(반영 시점은 iOS가 정함) | `STP-morning-glance` |
| 외부 지연 — 위젯 갱신 시점 | 30분 주기와 앱의 즉시 갱신 요청 모두 iOS 위젯 갱신 예산 안에서 시스템이 반영 시점을 정한다(PRD-8 AC7). 위젯에 갱신 시각 표시는 없다 | 해당 없음 |
| 우회 경로 — 일정이 3개를 넘음 | 위젯에는 3개와 「+ N 더」만 보인다. 일정 영역을 눌러 캘린더 앱에서 본다 | `STP-check-schedule` |
| 우회 경로 — 위젯 없이 앱만 연다 | 다짐·PR 모니터는 탭으로 갈 수 있지만, 날씨 화면은 위젯에서만 열린다 — 위젯을 지우면 날씨 화면에 들어갈 길이 없다(PRD-8 결정 사항) | 해당 없음 |
| 우회 경로 — 임시 공간에 쌓인 메모가 궁금함 | 위젯 미분류 수 영역(AC9)이 구현 전이라 앱을 열어 임시 공간을 확인한다 — `JRN-meeting-notes-triage` | 해당 없음 |
