# 주석 정책 — 필요성

이 레포의 주석은 **필요 사유를 한 문장으로 댈 수 있는 것만** 남긴다. 사유 없는 주석은 아무도 검증하지 않은 채 낡아 가고, 읽는 사람의 주의를 필요한 주석과 나눠 가진다. 지운 주석은 git 이력에 남는다.

| 문서 | 담는 것 |
| --- | --- |
| 이 문서 | 필요성 시험 · 유지 대상 · 판정 규칙 · 판정 절차 · 범위 · 지문 사각지대 |
| [`ledger.md`](ledger.md) | 판정 원장 — 파일 집합별 현재 주석 줄 수 · 지문 · 판정 칸(`완료`/`—`) |
| [`passes/`](passes/) | 판정 상세 — 패스 하나 = 파일 하나(`<판정일>-<slug>.md`): 제거 목록(불필요 유형) · 유지 목록(필요 사유 한 문장) |

기준의 출처는 reconciler 모델 `tbm_pocket-aide-comment-necessity` 와 그 템플릿 `templates/comment-necessity.tbm.md` 의 고정부다. 이 문서는 그것을 이 레포에 적용한 본문이다.

## 필요성 시험

> 이 주석을 지우면, 이 코드를 고치러 온 사람이 틀린 판단을 하거나 그 판단에 필요한 사실을 확인하는 데 상당한 비용을 치르는가?

예라면 그 결과(무엇을 틀리게 되는가, 무엇을 어디서 다시 찾아야 하는가)를 적은 한 문장이 **필요 사유**다. 한 문장으로 댈 수 없으면 지운다 — 애매함은 보존의 근거가 아니다.

## 유지 대상

- **기계가 읽는 주석** — 시험 면제이고 지문·판정 모두에서 빠진다. 도구 공통 지시자(shebang · `//go:` · `nolint` · `shellcheck` · `yaml-language-server:` 등, 템플릿 고정부)와 이 레포 고유의 셋:
  - `swiftlint:` — SwiftLint 지시자
  - `mock-exception:` — e2e 모킹 정책(`tbm_pocket-aide-e2e-mock-policy`)의 표기 규약
  - `검증 시나리오:` — 시나리오 e2e 매핑 선언(`tbm_pocket-aide-scenario-e2e`)
- **doc 주석** — 공개 API(`ios/Shared` 패키지의 `public` 선언, Go 의 exported 식별자·패키지)에 붙은 doc 주석의 **첫 문장**(줄바꿈과 무관하게 선언을 요약하는 한 문장). 이 수준은 사유를 따로 대지 않는다. 첫 문장 뒤의 본문과 비공개 선언의 doc 주석은 시험을 받는다.
- **필요 사유가 있는 주석** — 이 레포에서 흔한 사유: iOS 플랫폼 제약(키체인·App Group·위젯 타임라인 갱신·키보드 확장 샌드박스), 시뮬레이터·XCUITest·`ASWebAuthenticationSession` 의 함정, 외부 API(GitHub 웹훅·SQS·APNs·OpenRouter)의 문서화되지 않은 동작, 동시성·순서 계약, 레포 밖 인프라 설정과의 짝(API Gateway 매핑·EFS·DLQ). 예시이지 면제가 아니다 — 이 종류라도 주석마다 사유를 댄다.

## 판정 규칙

- **사유는 결과를 말한다.** 「중요함」·「참고용」·「나중에 필요할 수 있음」은 사유가 아니다.
- **불필요의 흔한 유형**: 코드 재진술, 저장소 문서 재진술, 주석 재진술(같은 사실의 정본이 다른 주석에 있음), PR·커밋 이력 재진술, 작업 흔적(누가·언제·끝난 TODO·경위), 장식·구분선, 소감·추측, 주석 처리된 코드. 목록은 시험을 대신하지 않는다.
- **더 나은 자리가 있으면 옮긴다.** 이름·타입·테스트·저장소 문서로 옮겨 코드가 스스로 말하게 할 수 있으면 옮기고 주석은 지운다. 옮기는 변경은 같은 PR 에 둔다.
- **틀린 주석**은 사유가 있으면 고치고, 없으면 지운다. 코드·문서와 어긋나면 주석이 틀린 것으로 본다.
- **같은 사실은 한 자리에.** 여러 자리가 같은 사실을 말하면 그 사실을 어길 사람이 읽는 자리 하나를 정본으로 남기고 나머지는 지운다.
- **유지는 기록으로 끝난다.** 남기는 주석(또는 같은 사유를 공유하는 묶음)마다 사유 한 문장을 그 패스의 `passes/` 유지 목록에 적는다. 사유를 적지 않은 유지는 판정 완료가 아니다.

## 판정 절차

1. `ledger.md` 에서 판정 칸이 `—` 인 행을 고른다. 한 번의 판정(패스)은 행 단위로, 주석 400줄까지 가져간다.
2. 주석마다 시험을 적용해 지우거나 · 고치거나 · 옮기거나 · 사유와 함께 남긴다.
3. `passes/<판정일>-<slug>.md` 에 제거 목록(불필요 유형)과 유지 목록(사유 한 문장)을 적는다. 같은 범위의 증분 재판정은 새 파일을 만들지 않고 원래 패스 파일에 절을 더한다.
4. 해당 행의 줄 수·지문을 `python3 scripts/comment-policy/check_ledger.py --rows` 의 출력으로 갱신하고 판정 칸을 `완료` 로, 결과 칸에 요약과 패스 파일 링크를 적는다.
5. 게이트(`python3 scripts/comment-policy/check_ledger.py`)가 초록이어야 한다. CI 워크플로 `comment-policy` 가 PR 과 `main` push 마다 같은 검사를 돌린다.

주석을 **새로 들이는** PR(판정 패스가 아닌 기능 PR 포함)도 게이트를 지나야 한다 — 원장 「읽는 법」의 마지막 항목대로 자기 파일의 행만 고친다.

## 범위

범위는 **레포 전체에서 제외 세 부류를 뺀 것**이다. 새 디렉터리는 등록 없이 자동으로 범위에 든다.

- ① 문서 — `docs/`, 모든 `*.md`
- ② 편집 불가 — 벤더·의존성·빌드 산출물 디렉터리, 락 파일, 머리 5줄에 `DO NOT EDIT`·`@generated` 표식이 있는 파일
- ③ 주석 문법 없음 — 바이너리, JSON·CSV·키 같은 데이터

이 밖의 이유(「CI 워크플로라서」, 「설정 파일이라서」)로는 빼지 않는다. 언어군(파일 이름 → 주석 문법)과 제외의 정확한 규칙은 `scripts/comment-policy/scan.sh` 가 reconciler 모델의 as-is 지문 스크립트와 **같은 규칙**으로 구현한다 — 그 출력의 sha256 이 모델이 관측하는 지문과 같다(`check_ledger.py` 가 `지문:` 으로 출력한다). 모델 스크립트가 바뀌면 이 파일도 같이 바꾼다.

**레포 고유 제외**는 아래 `comment-scope-exclude` 블록에 한 줄에 ERE 하나로 적고, 줄마다 부류(①②③)를 이 산문에 적는다. 부류를 댈 수 없는 제외는 둘 수 없다. 현재 레포 고유 제외는 **없다** — 블록이 비어 있으면 고정부만 적용된다.

## 지문 사각지대

지문(과 게이트)은 줄머리 주석(L) · Python docstring(D) · 줄 끝 주석(E) 세 표면을 결정적으로 뽑는다. 다음은 뽑히지 않거나 잘못 뽑힌다 — 오탐·누락 모두 결정적이다.

- MIXED(HTML 류)·MARKUP(XML·plist·`*.entitlements`) 파일과 줄 중간 `#` 이 주석이 아닌 HASH 파일(`Dockerfile`·`.gitignore` 류·`.env*`)의 줄 끝 주석
- `*` 로 시작하지 않는 블록 주석 연속 줄, Python 밖의 docstring 성격 문자열
- 줄 스캐너의 문자열 추적 한계(정규식 리터럴 등)
- 사람의 문장이 기계가 읽는 주석의 문자열을 **담으면**(예: 본문에 `//go:build` 를 인용) 그 줄은 지문에서 빠진다. 판정은 파일을 읽어서 하므로 그런 줄도 같은 시험을 받는다.
