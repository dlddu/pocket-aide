## 1. 문제

PRD-9 AC5는 키보드의 글쓰기 파트너 대화 UI 안에서 음성으로 받아쓰고 지시할 수 있어야 한다고 정한다. 그런데 iOS 키보드 확장은 기기 마이크에 접근할 수 없다(Apple 키보드 확장 가이드). 그래서 PRD-9 AC5·PRD-7 AC6이 전제한 「키보드 확장 안의 자체 음성 인식기」는 녹음 단계부터 성립하지 않는다.

## 2. 결정 — 본 앱이 녹음하고 인식한다

1. **키보드에서 마이크 버튼 탭**: 본 앱(PocketAide)을 잠깐 열어 녹음 세션을 시작한다. 본 앱은 백그라운드 오디오 모드로 녹음을 유지하고, 사용자는 원래 앱으로 돌아온다.
2. **본 앱이 녹음과 음성 인식을 처리**: 인식 로직은 본 앱에 둔다 — 메인 앱 STT 엔진(PRD-7: Whisper, 자체 서버 등)과 LLM 후처리 같은 별도 로직을 자유롭게 넣는다.
3. **App Group으로 결과 전달**: 키보드가 결과를 받아 `textDocumentProxy.insertText()`로 입력한다.

이 구조에서 키보드 확장은 녹음도 인식도 하지 않는다. 마이크 버튼, 세션 상태 표시, 결과 수신, 입력창 반영만 맡는다.

## 4. 흐름

### 4.1 세션이 없을 때 (첫 마이크 탭)

1. 사용자가 키보드 대화 UI의 마이크 버튼을 누른다.
2. 키보드가 App Group의 세션 상태를 읽는다 — 녹음 세션 없음.
3. 키보드가 본 앱을 연다(예: `pocketaide://voice/start?req=<id>` — 방식은 §6.1).
4. 본 앱이 마이크 권한을 확인(첫 사용이면 요청)하고 녹음 세션을 시작한 뒤, 세션 상태를 `recording`으로 App Group에 기록한다. 화면에는 「녹음 중 — 왼쪽 위 ◀로 돌아가세요」 안내를 보인다(문구 가정).
5. 사용자가 iOS의 「◀ 이전 앱」 표시로 원래 앱에 돌아온다. 본 앱은 백그라운드에서 녹음을 계속한다.
6. 키보드가 돌아온 뒤 세션 상태 `recording`을 보고 「듣는 중」을 표시한다.
7. 사용자가 말하고 마이크 버튼을 다시 눌러 끝낸다 → 키보드가 App Group에 정지 요청을 쓴다.
8. 본 앱이 그 발화 구간을 인식(+ 후처리)해 결과를 `ready`로 기록한다.
9. 키보드가 결과를 읽어 대화 말풍선(지시) 또는 미리보기(받아쓰기)에 넣는다. 입력창 반영은 「적용」 때 `insertText()`로 한다(PRD-9 AC5·AC9 — 인식 결과를 곧바로 입력창에 덮어쓰지 않는다).

### 4.2 세션이 살아 있을 때

마이크 탭 → App Group에 발화 시작 요청 → 본 앱이 구간을 표시하고 듣는다 → 4.1의 7~9와 같다. 본 앱을 거치지 않는다.

## 5. App Group 교환 규약 (제안)

교환은 키 하나에 JSON 하나를 두는 단순한 형태로 시작한다(가정 — 구현 시 확정).

| 키 | 쓰는 쪽 | 내용 |
|---|---|---|
| `voice.session` | 본 앱 | `state`(`idle` · `recording` · `processing` · `ready` · `error`), `startedAt`, `expiresAt`, `error` |
| `voice.request` | 키보드 | `id`, `action`(`begin` · `end` · `cancel`), `at` |
| `voice.result` | 본 앱 | `requestId`, `text`, `lang`(인식 언어 정보, 선택), `at` |

- 변경 알림은 Darwin 알림(`CFNotificationCenterGetDarwinNotifyCenter`)으로 보내고, 받는 쪽은 알림을 받으면 App Group을 다시 읽는다. 알림을 놓쳐도 화면이 나타날 때와 짧은 주기로 다시 읽어 상태를 맞춘다(가정).
- 결과는 `requestId`로 짝을 맞춘다 — 늦게 도착한 이전 요청의 결과가 새 지시에 섞이지 않게 한다.
- 키보드는 결과를 읽은 뒤 지우지 않는다. 다음 요청이 덮어쓴다(본 앱만 쓰는 키를 두 쪽이 지우면 경쟁이 생긴다).

## 6. 제약과 위험

### 6.1 키보드에서 본 앱 열기

키보드 확장에는 다른 앱을 여는 공개 API가 없다(`extensionContext.open`은 키보드에서 동작하지 않는다 — 가정). 흔히 쓰는 우회(응답자 체인을 따라 `openURL`을 부르는 방식)는 App Review 정책상 거절될 수 있다. 구현 전에 이 방식의 허용 여부를 확인하고, 막히면 「본 앱을 직접 열어 세션을 켠 뒤 돌아오라」는 수동 안내로 물러선다.

### 6.2 원래 앱으로 돌아오기

본 앱이 이전 앱으로 스스로 돌아갈 공개 API는 없다. 사용자가 상태 막대의 「◀ 이전 앱」을 눌러야 한다 — 그래서 첫 탭마다 앱 왕복이 생기지 않도록 세션을 일정 시간 살려 두는 것(§7)이 이 구조의 사용성을 좌우한다.

### 6.3 백그라운드 녹음

- 본 앱 `Info.plist`에 `UIBackgroundModes` `audio`를 선언하고, `AVAudioSession`을 녹음 카테고리로 연 채 유지해야 백그라운드에서 녹음이 이어진다. 지금은 선언되어 있지 않다.
- 녹음 중에는 iOS가 상태 막대·다이내믹 아일랜드에 마이크 사용 표시를 띄운다. 세션을 오래 살려 두면 이 표시도 계속 켜져 있다.
- 전화·Siri·다른 앱의 오디오가 세션을 끊을 수 있다(오디오 인터럽션). 끊기면 세션 상태를 `error`로 두고 키보드는 다음 탭에서 4.1을 다시 탄다.
- 메모리 압박으로 iOS가 본 앱을 종료할 수 있다. 키보드는 `expiresAt`이 지났거나 상태가 오래 바뀌지 않으면 세션이 없는 것으로 본다.
- 백그라운드 오디오 사용은 App Review에서 실제 녹음 기능일 때만 허용된다 — 세션을 열어 둔 동안 실제로 마이크를 쓰는지(무음 유지가 아닌지) 설명할 수 있어야 한다.

### 6.4 Full Access

키보드가 App Group 공유 컨테이너를 읽고 쓰려면 Full Access가 필요하다(가정 — 공유 컨테이너는 Open Access가 있어야 열린다). Full Access가 없으면 음성도 LLM 기능과 함께 비활성이다(PRD-9 AC12와 같은 안내).

### 6.5 프라이버시

음성은 본 앱이 녹음하고 STT 엔진(서버형이면 서버)으로 보낸다. 오디오 보관 여부·기간은 정하지 않았다 — PRD-6 AC4(숏컷 음성의 원본 음성 메타데이터)와 같은 질문이다.

## 7. 세션 수명 정책 (제안)

- 마지막 발화가 끝난 뒤 N분(예: 5분) 동안 세션을 유지하고, 그 안의 마이크 탭은 본 앱을 거치지 않는다. N이 지나면 본 앱이 녹음을 멈추고 `idle`로 돌린다.
- 키보드 대화 UI를 닫아도 세션은 N분 동안 유지한다 — 같은 메일을 다시 열어 이어 말하는 경우를 위해서다.
- N은 왕복 횟수(사용성)와 배터리·마이크 표시 부담 사이의 절충이다. 실제 사용으로 정한다.

## 8. PRD에 미치는 영향 (미반영)

이 결정은 다음 PRD 문구와 어긋난다. PRD는 이 문서에서 고치지 않는다 — 별도 변경으로 반영한다.

| PRD | 현재 문구 | 이 구조에 맞춘 방향 |
|---|---|---|
| PRD-9 AC5 | 「본 키보드 확장은 자체 음성 인식기를 가진다(메인 앱의 STT 엔진과 분리)」 | 키보드는 녹음·인식을 하지 않고 본 앱의 STT 엔진 결과를 App Group으로 받는다. 「미리보기에서 검토」 조건은 그대로 |
| PRD-7 개요 「키보드 확장 전용 진입점」 · AC6 | 확장 내부에 자체 인식기를 둔다 | 키보드 경유 음성도 본 앱 프로세스의 단일 엔진(AC2)을 쓴다. AC6은 「본 앱 경유 키보드 음성 입력」으로 바꾸거나 AC2에 흡수 |
| PRD-7 AC4 | 메인 앱과 키보드 확장 두 인스턴스가 같은 추상화를 공유 | 인스턴스는 하나다 — 두 인스턴스 전제 삭제 |
| PRD-7 열린 질문 | 키보드 확장 인식기 구현 형태 · 코드 공유 범위 · 단어장 동기화 | 해소 — 본 앱 단일 엔진. 단어장도 본 앱 한 곳 |

## 9. 열린 질문

- **본 앱 열기 방식의 App Review 허용 여부**(§6.1) — 막히면 수동 안내로 물러선다.
- **세션 유지 시간 N**(§7).
- **받아쓰기와 지시의 구분**: 같은 음성 결과를 「지시」(대화로 보냄)와 「받아쓰기」(미리보기로 보냄) 중 어디로 보낼지 — 사용자가 버튼으로 고를지, LLM이 판단할지.
- **본 앱 미로그인**: 서버형 STT·LLM 후처리에 로그인이 필요하면, 본 앱이 열린 그 자리에서 로그인을 요구할지.
- **오디오 보관**(§6.5).
